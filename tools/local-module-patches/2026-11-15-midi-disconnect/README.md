# Midi-QOL 14.6.8 — реакции и спасброски при обрыве связи

При отклонении `chooseReactions` ожидание завершается сразу. Таймер и шёпот с приглашением очищаются также при штатном таймауте. Клик до истечения таймера `reactionDialog` даёт координатору время подтвердить реакцию. Вызов `MidiQOL.extendReactionTimeout(options.reactionRequest)` с клиента получателя один раз доводит оставшееся время внешнего таймера до 130 секунд, если первоначальный запрос ещё открыт. Обычное ожидание без выбора и пауза штатной телепортации сохраняются.

Локальный `options.rebreyaBeforeForcedAc()` вызывается после истинного штатного условия автоматической реакции на КД, перед исходным броском и расходом. При `false` Midi-QOL пропускает эту реакцию. Функция остаётся на клиенте и не входит в параметры обычных активностей. Для ручного окна КД используется оставшееся время выбора и штатный таймер окна.

При отклонении запроса спасброска Midi-QOL сохраняет броски остальных токенов и сообщает, для какой цели требуется ручное разрешение. Для этой цели исход остаётся неопределённым. Ведущий проверяет, успел ли пройти исходный бросок, и определяет урон и эффекты вручную. Хук проверки спасброска и выбор провайдера остаются штатными.

Патч подготовлен для конкретной сборки Midi-QOL 14.6.8. `manifest.json` фиксирует SHA-256 файла до и после. Тесты принимают оба состояния и проверяют применение и побайтовый откат во временной копии. Работающий клиент Foundry получает изменённый JavaScript при новой загрузке.

Проверка из корня Rebreya Main:

```powershell
node --test tools/local-module-patches/2026-11-15-midi-disconnect/midi-disconnect.test.mjs
```

Из каталога `Data/modules` проверить применимость:

```powershell
$midiPatch = 'rebreya-main/tools/local-module-patches/2026-11-15-midi-disconnect/patches/midi-qol.patch'
git -c core.autocrlf=false apply --check $midiPatch
```

Для будущего применения в отдельном окне обслуживания используется та же команда без `--check`. Для отката сначала проверяется `--reverse --check`, затем применяется `--reverse`.
