## Автоматизация проклятий-усовершенствований

Владелец — `scripts/combat/curse-upgrade-automation-service.js`; composition root создаёт один `CurseUpgradeAutomationService`. Он не меняет расчёт ступеней «Пожирателя проклятий». Источник: стабильный gearId → сохранённый профиль (приоритет) или каталог → installed-связи → heroDoll → managed Actor ActiveEffect / боевой адаптер. Оружейные проклятия требуют соответствующее оружие в руке; щит — удерживаемый щит.

- `collectCurseUpgradeSources(actor,catalog=new Map())` разрешает активные источники; `buildCurseUpgradeEffect(source,actor,state={})` строит описание и обратимые изменения initiative/AC/movement. Для «Тяжести жизни» читает явно заданную скорость либо movement.fromSpecies (наследование от расы dnd5e); не использует уже уменьшенную derived speed как базу следующего sync. Регрессия: species walk=30 без Actor._source walk даёт −10, повторный пересчёт стабилен, при утрате temp HP штраф исчезает. `values`, `flag`, `clone`, `change`, `escape`, `getChanged`, `syncOptions` — локальные нормализаторы коллекций, flags, данных, HTML и свежих Document options.
- Service: `constructor(moduleApi={},options={})`, `isAuthority()`, `sources(actor,key)`, `ownedSources(actor,key)`, `state(source)`, `now()`, `debtSources(actor)` задают каталог, authority и состояния. `initialize()` загружает каталог, восстанавливает pending chains и синхронизирует Actors; `registerNativeSaveWrapper()` однократно оборачивает D20Roll.buildPost до публикации результата.
- `requestSync(actor)` маршрутизирует player → active GM; `syncActor(actor)` идемпотентно согласует только собственные эффекты, исключая уже наложенные цепи. `handleChanged(document,options)`, `actorUpdated(actor,changed,options)` обслуживают hooks и provenance временных HP. `enqueue(actor,operation)` сериализует мутации персонажа. `writeState(source,patch)` сохраняет merged Item state только у active GM; Document options всегда новые.
- `resolveSaveRequest(payload)`, `executeSaveRequest(payload,{sender}={})`, `prompt(source,{title,body})` проводят запрос результата/выбора через typed socket и существующую очередь решений. Чужой неизвестный результат требует подтверждения GM. `preUpdateActor(actor,changed,options)` добавляет провал смерти только при positive HP → 0; `preDeathSave(config)` включает преимущество. `blocksReaction(actor,combat)`, `preUse(activity)` запрещают реакции первого раунда; существующий `CombatAttackService.canUseReaction` учитывает этот запрет.
- `initiative(actor,combatants)` выдаёт temp HP, не заменяя большие чужие; receipt dedup по combatant/initiative. `registerLongRestSteps(pipeline)` подключает curse-upgrade.restore к единому pipeline; `longRest(actor,result={})` возвращает использование, сохраняя долг. `preApplyDamage(actor,amount,updates,options={})` сохраняет provenance temp HP и self-damage receipt атомарно с HP.
- `restrain(actor,source)` создаёт/обновляет source-specific restrained; eventId предотвращает продление при recovery. `recoverPendingChains(source)` разрешает сохранённый targetActorUuid, применяет неистёкшее намерение с исходным expiresAt, затем очищает intent. Неизвестная цель оставляет intent с ошибкой. `combatChanged(combat,previous={},current={})` и `_combatChanged(...)` обслуживают только движение времени вперёд, истечение цепей и вопрос о действии Атака для обсидиана. `expireOutsideCombat()` истекает эффекты по world time.
- `attackOccurred(actor,host,eventId)` даёт +1 AC точному источнику обсидиана; `bloodHit(workflow)` передаёт фактический tagged blood bonus; `applyBloodDamage(source,{eventId,turn,amount})` повторно проверяет источник и списывает HP один раз, сверяя атомарный Actor receipt перед Item receipt.
- `CurseUpgradeSaveAdapter`: `constructor(service)`, `_once(actor,eventId,operation)` сериализуют и ограничивают кеш; `resolveSaveAuthority(actor,request={})` сохраняет использование/долг и последние 16 receipts; `resolveMidiChainAuthority(sourceActor,targetActor,request={})` проверяет cooldown и recovery. `_applyChains(source,targetActor,eventId,now,cooldown={})` сначала атомарно резервирует cooldown/receipt/intent, затем эффект, затем очищает intent. `isDamageOnlySaveActivity(activity)` исключает healing, effects и onUse macros. `applyNativeBuildPost(rolls,config={},message={})` требует известный DC, сохраняет dice total; `applyMidiPostCheckSaves(workflow)` / `_applyMidiPostCheckSaves(workflow)` согласуют canonical save/fail sets и отображение до damage. Локальные `values`, `sameSource`, `receiptPatch` нормализуют коллекции, identity и bounded receipts.
- `CurseUpgradeDamageAdapter`: `constructor(service,options)` получает порядок save/DR и источник; `preCalculateDamage`, `midiPreCalculateDamage`, `calculateDamage`, `midiCalculateDamage` принимают `(actor,damages,options={})`. `applyPacket(actor,damages,options={},midi=false)` считает одно плоское изменение на тип после save и до resistance, fire minimum 1. `applyShieldResistance(actor,damages,options={})` не удваивает имеющееся сопротивление. `preTargetDamageApplication(token,{workflow,damageItem}={})` пересчитывает общий MIDI пакет default/bonus/other; `updateDamagePreview(actor,damageItem)` согласует HP preview. `preRollDamage(config={})` добавляет tagged 1d6 только своему оружию; `bloodDamageTotal(workflow,source)` читает выпавший бонус. Локальные finite/ignored/resolveSourceItem нормализуют числа, исключения и источники.
- `CurseUpgradeAttackAdapter`: `constructor(service,{tokens,distance,selectRedirect,warn})`, `preRollAttack(config={})` применяет mourning advantage/-2; смешанная группа окружённых/обычных целей требует отдельных атак. `midiPreAttackRoll(workflow)` перенаправляет ranged weapon attack на ближайшего подходящего носителя щита в 10 ft один раз; UUID разрешает равенство. `releaseWorkflow(workflow)` убирает transient контекст. `isCurseRangedWeaponAttack(activity,item=activity?.item)` отделяет оружие от spell attack.
- `registerCurseUpgradeSocketCommands(moduleApi)` регистрирует save/sync/attack/blood; `isValidCurseSaveRequest(payload)` проверяет exact schema, `authorizeCurseSaveRequest(payload,{sender}={})` проверяет владельца, source activity, автора карточки и фактическую цель. Локальные exact/text/resolve/owns обслуживают валидацию. Player не пишет чужие Actor напрямую.
- `RebreyaMainModule.resolveCurseUpgradeSave(actorOrUuid,{saved,death=false,eventId=crypto.randomUUID()}={})` — публичный путь для вручную определённого результата без DC; возвращает финальный saved/forced. `installItemUpgrade` и `removeItemUpgrade` теперь ожидают requestSync перед UI refresh. `registerCombatHooks(moduleApi)` подключает единственный набор dnd5e/MIDI/document hooks.

Состояние: `flags.rebreya-main.curseUpgradeState` на embedded source Item; managed effect metadata `curseUpgrade`; Actor `curseBloodReceipts` и `curseTempDamageEvent`. Снятие не отменяет уже нанесённый урон/долг; повторный sync не меняет чужие эффекты. Автоматизация hit-dependent self-damage, chain saves и redirect требует MIDI workflow; отдельно брошенный кубик не содержит этих данных. Проверки: `tests/curse-upgrade-{automation-service,lifecycle,saves,damage,attacks,socket,hooks}.test.mjs`, manifest tests. Runtime QA: Foundry 13.351 / dnd5e 5.2.5 / MIDI 13.0.61, временные Actors с cleanup; полноценная многоклиентская игровая сессия отдельно не воспроизводилась.
