# Обезоруживание и физический снимок предмета — R6

Владелец операции: `scripts/combat/disarm-service.js`. Размещение: managed Macro «Обезоруживание» в существующей папке «Ребрея». dnd5e 5.2.5 / Foundry 13; runtime 1.4.276. Автоматического общего счётчика атак нет: UI явно показывает расход одной доступной атаки.

## Правила и броски

- `DisarmError(code,message)`, `evaluateDisarmRules({attackerSize,targetSize,heldHands,saveAbility,...modifierFlags})`, `resolveDisarmOutcome({attackTotal,saveTotal})`, `calculateDisarmDropCell({tokenBounds,gridSize,direction})`, `buildDisarmAttackFormula({abilityModifier,proficiencyContribution})` — `scripts/combat/disarm-rules.js`. Размеры canonical tiny/sm/med/lg/huge/grg; цель максимум +1; actual grip ≥2 даёт помеху; меньший атакующий даёт преимущество только STR save. Равенство Сл спасает, nat1/20 не меняют сравнение. Геометрия возвращает центры внешних клеток N/NE/E/SE/S/SW/W/NW, включая большие footprint. Неверные входные данные отклоняются.
- `buildDisarmRollPlan({actor,weapon,mode,context})` — `scripts/integrations/disarm-roll-adapter.js`. Source ability score из `actor.toObject()`, native `WeaponData.proficiencyMultiplier` и proficiency дают формулу. Melee/thrown STR, ranged DEX, finesse выбирает большую базовую характеристику. Качество, magical bonus, temporary attack additions и class/feat bonus не используются (решение пользователя 2026-09-08). Различие source/current ability и неясный proficiency возвращают null formula/unresolvedModifiers; только отдельное решение GM с причиной задаёт baseline score/contribution.
- `DisarmRollAdapter({RollClass}).attack(plan,mode)`, `.save(actor,ability,mode)`, `.direction(count)` исполняются authority. Attack — обычный Roll без damage/on-hit; save — native `actor.rollSavingThrow` с configure/create false и обычными save modifiers; направление — одна кость по числу допустимых точек. Private `serialize` сохраняет total и Roll JSON до chat. Неизвестный/неподтверждённый roll — ошибка без автоматического повторения.
- Версионное основание: установленный `systems/dnd5e/dnd5e.mjs`, WeaponData.proficiencyMultiplier и Actor.rollSavingThrow. [Foundry Token.checkCollision](https://foundryvtt.com/api/v13/classes/foundry.canvas.placeables.Token.html#checkCollision), [BaseGrid.getAdjacentOffsets](https://foundryvtt.com/api/v13/classes/foundry.grid.BaseGrid.html#getAdjacentOffsets).

## Live Documents и разрешённая проекция

- `DisarmDocuments({resolve,gameProvider,canvasProvider})` — `scripts/infrastructure/foundry/disarm-documents.js`. `tokens(intent,sender)` заново разрешает два Token, одну текущую сцену, source OWNER, скрытость и LOS. `weaponModes(weapon)` перечисляет melee/ranged/thrown из native weapon. `preview(intent,sender)` возвращает только своё удерживаемое оружие и удерживаемые предметы цели, без остального инвентаря.
- `prepare(intent,sender,context)` проверяет weapon mode, хват через held-items owner, обычную range/досягаемость, размеры и назначает одного online OWNER защитника либо GM. Возвращает detached имена/UUID/size/grip signatures/roll plan/responder. `revalidate(record,saveAbility)` сравнивает живые identities/количество/хват/размер; возвращает target Actor и native save conditions. `dropPoints(record)` вызывает `collectDisarmDropPoints(token,canvas)`.
- `collectDisarmDropPoints` исключает стены через public Token.checkCollision(type move) и границы sceneRect **до** случайного выбора. Square/gridless: восемь направлений; hex: public соседние offsets вокруг footprint. При восьми точках к8, иначе равномерная кость по числу вариантов. Нет точек — нет source debit. Точка ещё раз валидируется до ground create.

## Typed authority и durable workflow

- `DISARM_ACTIONS`, `isValidDisarmPayload(action,payload)`, `authorizeDisarmSender(action,{sender,game})` — `scripts/infrastructure/foundry/disarm-command-contract.js`. Exact commands `disarm.preview/start/resolve-save/set-baseline/reassign-responder/resume/cancel`; bounded canonical world/synthetic UUID. Player не передаёт total, formula, ItemData, senderId или capability. Реальный authenticated User обязателен, set-baseline/reassign-responder — GM-only; source/target ownership дополнительно проверяется сервисом на живых Actor.
- `DisarmService({journal,coordinator,documents,rollAdapter,storageCommands,publish,gameProvider})` использует **существующий** InventoryService.mutationJournal, короткую очередь disarm-operations, без ожидания человека внутри queue. `start(intent,context)` ищет receipt до source lookup, сверяет sender fingerprint, не допускает конкурирующее pending intent для того же атакующего/предмета, готовит и сохраняет бросок. `chooseSave(intent,context)` допускает только назначенного responder (включая GM), проверяет свежий хват и живые права OWNER; повтор выбора не делает новый save. Неназначенный GM сначала явно меняет responder с причиной.
- `reassignResponder({operationId,expectedResponderRevision,responderUserId,reason},context)` — authenticated GM, только awaiting-save. В той же очереди повторно проверяет Documents и подключённого OWNER/GM, сравнивает revision (legacy default0); сохраняет responder/revision и audit decisions одним guarded checkpoint. История до64 решений включает GM, прежнего/нового responder и причину1–240 символов. Последний exact intent+GM повторяется без записи даже после terminal; старый конфликтующий revision не отменяет новое назначение. Смена не бросает кости. `projection` добавляет responderRevision и последнюю responderDecision.
- `resume(operationId,context)` продолжает только доказанно подготовленные фазы. Если completed/cancelled/conflict/manual-review уже записана, но terminal marker ещё отсутствует, повторно завершает только журнал через authority guards; не бросает кости и не вызывает storage. Для completed снимает временную ошибку записи, для остальных сохраняет исходное объяснение. Незавершённый attack-rolling/save-rolling/direction-rolling переводится в manual-review без reroll. `cancel` разрешён до roll или при ожидании save/baseline; существующий бросок остаётся видимым. `setBaseline(intent,context)` записывает GM/reason и запускает ранее не выполненный attack. `projection(record)` исключает физические ItemData из socket response.
- Private `#id/#sender/#authorize` проверяют идентичность и роли; `#write/#phase/#finish` оборачивают journal writes authority guards; `#attack` сохраняет roll до публикации; `#completeSave/#continueSave` завершают успешный save либо продолжают recoverable drop, сохраняя видимую ошибку без повторных костей. `#present` публикует карточку; ошибка отображения не повторяет world mutation.

## Storage owner и сохранение физической вещи

- `StorageCommandService` constructor принимает internal `disarmCapability`, `prepareDisarmPlacement`, `validateDisarmDestination`; `dropDisarmedItem({operationId},context)` требует identity capability из composition и assertAuthority. Публичный обычный dropItemToScene сохраняет свою ACL. Внутренний worker — `runDisarmDrop(owner,operationId,context)` в `scripts/application/disarm-drop-workflow.js`, без нового socket/settings owner.
- Worker читает реальную disarm receipt с failed save, serializes через existing inventory queue; сохраняет graph, source-before/remaining, placement и точку до writes. R3 `ItemInstanceDocuments.readSource` и `planItemInstanceMutation` проверяют физический split: допускается одна held единица обычного стака с разэкипированным остатком; содержимое/upgrades/charges/independent state запрещают partial split.
- Фазы drop: prepared → ground-creating → ground-created → source-debit-started → source-debited → committed/terminal. Ground owner получает стабильный mutation ID и уникальную row identity; throw-after-create проверяется существующим ground receipt. Неясное создание без receipt не повторяется. Source debit сверяет сохранённые Documents, для остатка одним Item.update записывает quantity/unequipped/held reset/debit marker, для whole удаляет только сохранённый набор IDs. Повтор после потерянного ack сверяет source state; completed replay не создаёт заново уже подобранную/удалённую ground вещь.
- `HeroDollService.prepareDisarmPlacement(actor,item)` строит только точечные `{path,before,after:null}` для занятых этим Item слотов. Worker сравнивает текущие поля, удаляет только эти membership через Actor.update и не восстанавливает целый Actor snapshot. Отдельный source state не создаётся.
- `captureRuntimeItemGraph(actor,root)`, `buildRuntimeGraphDocuments(graph,operationId,rootData,{actorId=null})`, `materializeRuntimeItemGraph(actor,graph,operationId,rootData,{recoverMissing=false})` — `scripts/data/runtime-item-graph.js`. Это bounded (200 nodes) **транспортный снимок реальных Documents**: native container children и installed upgrade children, исходные system/flags/effects. Нет каталожной реконструкции или второй world repository. Повторные/циклические/missing links отклоняются. Deterministic IDs назначаются до create, host/upgrade/native container links переназначаются; root получает quantity1 и снятие хвата через canonical held-items adapter. Partial observed graph либо изменённая quantity/topology требуют manual-review, не повторной выдачи. R8 добавляет opt-in recoverMissing только для prepared loot и переназначение hostActorId target Actor; disarm не включает этот режим. Детали — [составной лут](lootgen-composite-function-passport.md).
- Graph хранится только в authoritative `storageRow.runtimeGraph` и journal transfer receipt. `InventoryService.buildLootgenItemData` не доверяет одноимённому флагу Item: удаляет его и использует row.runtimeGraph только в persisted-storage path. `StorageCommandService.#inventoryIngressRow` аналогично переносит trusted graph во временный internal itemData flag. На созданных Actor Items этот transport flag отсутствует; остаются короткие origin markers.
- `InventoryService.#findInventoryMergeCandidate` не объединяет runtime graph; `commitInventoryIngressBatch` направляет его в существующий durable legacy ingress и запрещает transport flag вне storage source. `#prepareInventoryIngressTargetReceipts` не разрешает dismantle графа, `#applyInventoryIngressTargetReceipt` и `#executeInventoryGrantOnce` создают весь graph через единый materializer до source claim. Обычные legacy/simple rows сохраняют прежние маршруты.

## Composition, macro, UI

- `RebreyaMainModule` создаёт один service/documents/adapter, capability остаётся только internal closure; `#registerTypedSocketCommands` использует existing PrivilegedMutationGateway. `requestDisarmAction(action,payload)` не принимает кастомный executor; `disarm(options)` блокирует двойной диалог, захватывает explicit tokens и immutable intent; `openDisarmOperation(id)` читает durable state и для GM предлагает unresolved baseline. `publishDisarmOperation(record)` на active GM находит единственную GM-authored chat card по ID, показывает сохранённые Rolls и обновляет только затронутый инвентарь. Hook renderChatMessageHTML регистрируется один раз в initialize.
- Existing `GrappleMacroService.syncManagedDocuments()` создаёт третий managed macro через `buildDisarmMacroData(folderId,options)`, `DISARM_MACRO_SOURCE_ID=disarm-macro`. Exact папка «Ребрея», unmanaged name collisions не изменяются.
- `resolveDisarmSelection`, `promptDisarm`, `promptDisarmBaseline`, `buildDisarmChatContent`, `bindDisarmChat` — `scripts/ui/disarm-dialog.js`. DialogV2, escaped names, расход1 атака до подтверждения; cancel до start не создаёт operation. Chat кнопки STR/DEX только для назначенного responder, «Сменить отвечающего» только GM, cancel только sender/GM; команды всё равно авторизуются серверным модульным маршрутом. AbortController/WeakMap заменяют handlers при повторной отрисовке, кнопки блокируются на время await. UI не меняет Actor/Item/settings.
- `promptDisarmResponder(operationId,expectedResponderRevision,users=game.users.contents)` возвращает intent либо false/null при отмене. Список подключённых пользователей экранирован, право OWNER повторно проверяет authority. Snapshot revision захвачен из карточки; причина обязательна, render listener блокирует «Назначить» при пустом/пробельном вводе (DialogV2 сам не останавливает click по HTML required). Карточка показывает последнюю причину; full audit остаётся в durable journal.
- DialogV2 использует собственную form: content содержит div; поля читаются через `elements.namedItem`, включая имя `item`, совпадающее с методом HTMLFormControlsCollection. Callback отмены возвращает false, поскольку native DialogV2 заменяет null/undefined на action. `requestDisarmAction` освобождает local pending intent только после подтверждённого preflight rejection или operation-not-found; timeout сохраняет прежний ID. Publisher делает scoped refresh только при изменении карточки завершённого переноса.
