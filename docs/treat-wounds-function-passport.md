# Перевязка ран: текущий контракт

## Владельцы и интерфейсы

- `scripts/application/treat-wounds-rules.js`: `getTreatWoundsTiers(level)` возвращает все доступные `{dc,bonus}`; пороги 5/11/17, Сл 10/15/20/25, бонусы 0/10/30/50. `resolveTreatWoundsOutcome({total,dc,bonus})` возвращает `{kind,formula,bonus,canContinue}` для четырёх исходов. `TreatWoundsError(code,message)` сохраняет typed code.
- `scripts/integrations/treat-wounds-dnd5e-adapter.js`: `TreatWoundsDnd5eAdapter({RollClass}={})` владеет `level(actor)`, `isLiving(actor)`, `hasMedicineProficiency(actor)`, `kitState(item)`, `rollMedicine(actor,{dc})`, `rollResult(outcome)`, `planResult(actor,{kind,amount,operationId})`, `applyResult(actor,plan)`. Native Medicine/wis бросается с `configure:false`, `{create:false}`; штатный диалог процедуры уже подтверждён игроком, очередь не ждёт чужого диалога на GM. NPC CR читается без пересчёта. Полные/0 HP допустимы; dead, death.failure>=3, undead/construct исключены. Каталожный gearId `komplekt-tselitelya` либо exact native имя определяет комплект; whole quantity, spent0 и понятный pool либо отсутствие uses (каталожный loot) обязательны. Healing/damage план сохраняет исходные hp/effectiveMax/temp/failures/successes и точные updates, объединяя Actor health receipt с HP write. Pure piercing напрямую меняет health pool, обходит damage traits и preApplyDamage-модификаторы; temp HP поглощают урон. Healing сбрасывает только failures; native сброс successes при выходе с0 HP компенсируется второй guarded записью с отдельным `treatWoundsDeathSuccessReceipt`, recovery не повторяет HP. Повтор с matching receipt безопасен; иной HP snapshot требует manual-review.
- `scripts/infrastructure/foundry/treat-wounds-documents.js`: `TreatWoundsDocuments({adapter,groupContextService,resolve,gameProvider,canvasProvider})`; `tokens(intent,sender)` проверяет dnd5e, authenticated sender, OWNER лекаря, одну сцену, скрытую цель, living и Medicine. `preview(intent,sender)` возвращает имена, уровень/ПО, tiers, personal/group kits и GM-only custom DC. `prepare(intent,sender)` повторно проверяет выбранные tier/kit/group и возвращает `{source,target,tier,dc}`. `resolve(uuid)` — injected document boundary.
- `GroupContextService.canManageGroupForUser(groupActorId,user)` в `scripts/data/group-context-service.js` использует явного пользователя: GM либо OWNER character-member; не наследует права клиента-исполнителя. Existing `resolveForGroup`/`resolveForCurrentUser` сохранены.
- `InventoryService.consumeTreatWoundsKitOnce(payload,context)` в `scripts/data/inventory-service.js` делегирует `consumeTreatWoundsKitOnce(owner,payload,context,{adapter,resolve})` из `scripts/application/treat-wounds-kit-consumption.js`. Выполнение на существующей queue `inventory`, journal key `treat-wounds-kit:<id>`, стадии prepared/debited/terminal. Exact group source, explicit sender, whole-kit eligibility и fingerprint проверяются до расхода. Actor Items с container children не удаляются молча. Quantity>1 уменьшается на1 с Item receipt, последний комплект удаляется. Stored before/after/uses сравниваются при recovery; отсутствующий prepared last Item подтверждает расход без второго delete. Internal `context.operationSenderId` сохраняет исходный fingerprint при GM recovery; ACL проверяет реально действующего sender. Клиент это поле не передаёт.
- `scripts/application/treat-wounds-service.js`: `TreatWoundsService(options)` получает existing journal/coordinator, inventoryService, adapter, documents, publish, gameProvider, isActiveGm. `preview(intent,context)`, `start(intent,context)`, `resume({operationId},context)`, `continue({operationId},context)` — один authoritative procedure owner. Queue `treat-wounds` не содержит human prompt; отдельные inventory debits используют canonical inventory queue. `cleanupExpiredEffects(worldTime=game.time.worldTime)` на active GM удаляет только истёкшие tagged effects world/synthetic Actors, дедуплицируя по Actor UUID.
- `scripts/infrastructure/foundry/treat-wounds-command-contract.js`: `TREAT_WOUNDS_ACTIONS`, `isValidTreatWoundsPayload(action,payload)`, `authorizeTreatWoundsSender(action,payload,context)` задают exact typed contract, bounded UUID/ID, tier/customDC и authenticated sender. Все действия идут через существующий privileged gateway.
- `scripts/ui/treat-wounds-dialog.js`: `resolveTreatWoundsSelection(options,controlled,targets)` выбирает self без target и отклоняет неоднозначный выбор; `promptTreatWounds(preview,{DialogV2}={})`, `promptTreatWoundsContinuation(record,{DialogV2}={})` возвращают exact intent/boolean либо false. `buildTreatWoundsChatContent(record)` экранирует данные, показывает все исходы, выбранную tier/bonus при customDC, точный remaining world-time interval на момент публикации, ошибки и action buttons; `bindTreatWoundsChat(message,html,api)` заменяет handlers через AbortController/WeakMap, скрывает чужие кнопки и вызывает только gateway API.
- `RebreyaMainModule.treatWounds(options={})`, `requestTreatWoundsAction(action,payload)`, `publishTreatWoundsOperation(record)` в `scripts/main.js` собирают единые сервисы, Dialog/API/socket и одну native ChatMessage на operationId. Pending intent сохраняется при timeout; подтверждённый operation-not-found освобождает его. Initialize один раз регистрирует chat binding и worldTime cleanup, также убирает expired effects на startup.
- `buildTreatWoundsMacroData(folderId,options={})` в существующем `scripts/combat/grapple-macro-service.js` добавляет пятый managed world macro «Перевязка ран», sourceId `treat-wounds-macro`; unmanaged collisions не меняются.

## Durable data flow и recovery

Selected tokens → authenticated preview → player Foundry DialogV2 → typed start on active GM → prepared receipt → Medicine roll/serialized result → обязательная публикация → result dice/amount → whole-kit debit → immunity effect → stored HP plan/atomic health receipt → completed/terminal и обновлённая карточка. Journal keys initial `treat-wounds:<id>` и continuation `treat-wounds:<id>:continue` используют existing inventory journal/settings и его bounded terminal retention (64). Продолжение хранит отдельный receipt: дополнительные HP равны initial amount, без reroll/debit. Initial/continuation replay показывает последнюю карточку.

Любая выполненная Medicine проверка остаётся в чате при обычном/критическом провале и последующих ошибках. Известный roll, запись которого дала transient error, сохраняется повторным checkpoint либо публикуется из памяти; неоднозначный rolling record после прерывания не перебрасывается, нужен manual-review. Living eligibility перепроверяется до неприменённого health write в resume/continuation. Недоступность самого ChatMessage persistence не может гарантировать немедленную публикацию: подтверждённый результат хранится для resume. Повторная доставка проверяет стабильный fingerprint независимо от порядка ключей. Concurrent pending source/target блокируются; старое продолжение запрещено после нового старта или pending операции пациента.

Effect `flags.rebreya-main.treatWounds={operationId}`, `duration.seconds=3600`, `duration.startTime=начало` — единственный cooldown. Отдельный Actor flag `treatWoundsLatestOperation` идентифицирует последнюю процедуру, не задаёт таймер; `treatWoundsHealthReceipt`/Item `treatWoundsKitReceipt` подтверждают записи. Обычный провал тоже расходует комплект и создаёт иммунитет. Продолжение не продлевает/снимает эффект. Мировое время вручную продвигает Мастер; после 10 минут осталось50, после полного часа0. До продвижения часов повтор по-прежнему заблокирован.
