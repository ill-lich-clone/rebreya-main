# Downtime UI Redesign Notes

Цель макета: разделить два разных режима работы с простоем, которые сейчас живут рядом и визуально спорят друг с другом.

- Игрок на чарнике должен быстро понять остаток недель, выбрать тип простоя, заполнить заявку и увидеть статус.
- Мастер в партийном инвентаре должен управлять группой: выдавать недели, видеть очередь заявок, назначать проверки и менять статус.
- Мастерская форма "создать заявку за персонажа" должна быть вторичной, а не выглядеть как основной сценарий рядом с выдачей недель.

## Что проверено в Foundry

- Вход через `https://vtt.rebreya.com/join` под профилем CODEX.
- Открытие Rebreya из левой панели Foundry.
- Открытие партийного инвентаря, переход на вкладку "Простой".
- Состояние мастера: балансы участников, выдача недель, список заявок и кнопки модерации.
- Чарник персонажа без свободных недель: форма блокируется, причина видна.
- Чарник персонажа со свободной неделей: форма доступна, заявка создаётся прямо с листа персонажа.

Я не отправлял новые заявки и не менял статусы, чтобы не засорять живой мир тестовыми данными.

## UX-принципы, использованные в макете

- Visibility of system status: остаток недель, резерв, потрачено и следующий шаг всегда рядом с действием.
- Match to real workflow: игрок видит только свою заявку, мастер видит групповую очередь и инспектор выбранной заявки.
- Recognition rather than recall: типы простоя показаны как узнаваемые варианты, а не только длинный выпадающий список.
- Error prevention: недоступная отправка объясняется возле формы, а не только в tooltip.
- Clear form labels: постоянные подписи остаются видимыми; placeholder не заменяет label.
- Grouping and hierarchy: выдача недель, очередь заявок и решение мастера разделены на отдельные зоны.

## Направление внедрения

1. Оставить вкладку простоя на чарнике, но заменить текущую компактную форму на пошаговый блок "Заявить простой".
2. В партийном инвентаре переделать вкладку "Простой" в мастерскую панель: участники слева, очередь по центру, инспектор справа.
3. Перенести "создать заявку за персонажа" в вторичное действие мастера, чтобы оно не конкурировало с выдачей недель.
4. Добавить явные empty/disabled states: "нет свободных недель", "нет заявок", "ожидает броска", "мастер вернул".
5. После утверждения макета уже менять `templates/inventory-app.hbs`, `templates/character-downtime-tab.hbs` и соответствующие CSS-блоки.
