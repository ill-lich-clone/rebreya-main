# UI Mini Guide (общий слой Rebreya)

Этот гайд фиксирует базовые роли компонентов для всех окон модуля: экономика, город, связи, инвентарь, лутген и вспомогательные диалоги.

Важно: в шаблонах используем только префиксованные классы `rm-*`. Роли `.panel`, `.section`, `.row`, `.badge`, `.tab`, `.button`, `.danger`, `.warning`, `.muted` ниже описывают смысл компонента, но не являются голыми CSS-классами для разметки.

## Радиусы и форма

| Роль | Реальные классы | Радиус |
|---|---|---:|
| Главное окно / верхний хедер | `.rm-hero`, `.window-content` | `12px` |
| Крупная секция | `.rm-panel`, `.rm-stat-card`, `.rm-disclosure` | `8px` |
| Строка списка / карточка записи | `.rm-city-card`, `.rm-route-card`, `.rm-trade-card`, `.rm-compact-item`, `.rm-party-row` | `6px` |
| Поле ввода / поиска | `.rm-field input`, `.rm-field select`, `.rm-textarea` | `6px` |
| Малая кнопка действия | `.rm-button`, `.rm-icon-button` | `7px` |
| Короткий статус | `.rm-chip`, `.rm-badge`, `.rm-status-badge` | `999px` |
| Навигационная вкладка | `.rm-tab` | `8px 8px 0 0` |

## Семантические роли

- `panel`: основная рабочая зона с фоном и смысловой границей; не использовать для каждой мелкой строки.
- `section`: вторичный блок внутри панели, например disclosure или toolbar.
- `row`: повторяемая запись списка, обычно без тяжёлой рамки до hover/open/critical.
- `badge`: короткий статус или компактный фильтр, например `СИЛ 5`, `Груз 75`, `Эн. 2/2`.
- `tab`: навигация между разделами; вкладка не должна выглядеть как обычная кнопка.
- `button`: действие пользователя; главное действие получает `rm-button--primary`.

## Состояния

- `danger`: критическая проблема, например перегруз, нулевые запасы, дефицит.
- `warning`: предупреждение, например низкие запасы или риск.
- `muted`: служебный текст, который не должен спорить с основными значениями.
- `disabled`: недоступное действие с видимым объяснением через текст, hint или tooltip.
- `is-active`: активная навигация или выбранный объект; должно считываться быстрее соседних элементов.

## Правила иерархии

1. Критические ресурсы и ошибки должны быть виднее декоративных рамок.
2. Главное действие на экране должно быть визуально сильнее вторичных действий.
3. Обычные строки не получают pill-форму; pill остаётся только для коротких статусов.
4. Вкладки отделяются нижней линией и активным состоянием, а не выглядят как ряд одинаковых таблеток.
5. В экономике списки городов, событий и маршрутов читаются как строки данных: название слева, метрики справа, критика цветом.
6. Рамки остаются только у крупных смысловых зон, активной/критической строки и drag-and-drop зоны.
