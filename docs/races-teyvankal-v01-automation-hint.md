# Подсказка: что автоматизировать по расам Тейванкаля

Этот файл нужен как чеклист для Codex при переносе механик из `Расы Тейванкаля V0.1.txt` в данные/код модуля.

## 1) Ключевые файлы проекта

- `data/races-teyvankal-v01.json`
  - Источник структурированных рас, умений и опций.
  - Сюда добавляется/обновляется блок автоматизации по каждой особенности.
- `scripts/data/races-compendium.js`
  - Генерация compendium-документов рас и расовых умений.
  - Здесь нужно начать использовать `automation`-данные для `effects`, `activities`, `uses` и `flags`.
- `tools/apply-feat-automation.mjs`
  - Референс по созданию `Active Effect` и `Activity` (можно брать паттерны/хелперы).
- `scripts/combat/status-definitions.js`
  - Референс по внутренним статусам модуля (если расовые умения вешают состояния).
- `docs/`
  - Отчёт покрытия автоматизации рас (full/partial/manual).

## 2) Что автоматизировать обязательно

- Пассивные числовые модификаторы:
  - КД, хиты (включая max HP), скорость и типы перемещения, чувства.
  - Сопротивления, иммунитеты, уязвимости, иммунитеты к состояниям.
  - Владения (навыки/инструменты/оружие/доспехи), если это выражается полями dnd5e.
- Флаги MIDI-QoL / DAE / DFreds:
  - advantage/disadvantage на атаки, проверки, спасброски.
  - Состояния и статус-эффекты (стандартные dnd5e или кастомные из модуля).
- Активные особенности:
  - Тип действия: action / bonus action / reaction / special / utility.
  - Check/Save (с DC), Damage/Healing (формулы), применение эффектов.
  - Расходы и восстановление использований.

## 3) Что фиксировать как partial/manual

- Выбор цели/контекста, который не читается однозначно из текста.
- Эффекты, требующие решения мастера или внешних таблиц/подсистем.
- Сложные триггеры, которые пока не покрываются текущим пайплайном.

Для таких случаев:
- автоматизируй максимально возможную часть;
- добавляй явный `manualNote` с кратким объяснением, что именно осталось вручную.

## 4) Рекомендуемая схема данных (минимум)

Добавлять в каждую `ability` и `option` структурный блок наподобие:

```json
{
  "automation": {
    "coverage": "full|partial|manual",
    "effects": [],
    "activities": [],
    "uses": null,
    "manualNotes": [],
    "sourceRef": {
      "lineStart": 0,
      "lineEnd": 0
    }
  }
}
```

Минимальные поля:
- `coverage`: текущий статус автоматизации.
- `effects`: список эффектов, которые реально вносят механическое изменение.
- `activities`: активные кнопки действия с уронами/проверками/спасбросками.
- `manualNotes`: что осталось ручным.
- `sourceRef`: привязка к месту в исходном тексте.

## 5) Где в коде подключать автоматизацию

- В `scripts/data/races-compendium.js`:
  - при создании race feature документа заполнять:
    - `effects` (не оставлять пустым, если есть механика),
    - `system.activities`,
    - `system.uses` и recovery,
    - `flags` для служебной метаинформации автоматизации.
  - при создании race документа применять расовые пассивы, если они относятся к самой расе, а не к отдельной особенности.

## 6) Критерии готовности

- Обработаны все расы из `Расы Тейванкаля V0.1.txt`.
- У каждой особенности есть `coverage` и понятный результат.
- Все механические эффекты (КД/ХП/скорости/урон/использования/действия/состояния) перенесены в данные там, где это возможно.
- Сформирован итоговый отчёт по покрытиям в `docs/`.
