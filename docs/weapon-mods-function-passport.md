# Оружейные обвесы и модернизированные части

## Панель МОДЫ

Владелец `scripts/integrations/weapon-mod-panel.js`; прежний `bindItemUpgradeSheet` вызывает async binding. `item-mods-tab.hbs` размещает local subnav внутри Mods part под штатным D&D разделителем: «Обвесы» и «Усовершенствования». Кнопки навигации имеют native `always-interactive`, чтобы dnd5e PLAY mode не отключал просмотр. `bindWeaponModSubtabs(root,app,{enabled,signal})` хранит выбор в WeakMap app, обновляет hidden/aria-selected/tabindex и поддерживает стрелки/Home/End; rerender сохраняет выбор. Unsupported host скрывает subnav, показывает обычные upgrades. `renderItemUpgradePanel` вставляет старую секцию в её wrapper, сохраняя прежние listeners/API.

`buildWeaponModCatalogView({catalog,host,installed,inventory,sourceItems,kind,mountId,isOwner})` оставляет совместимые с текущей effective form/креплением строки (`fitsCatalogSlot(row,host,catalog,mountId,installed)` делегирует pure rules), включая отсутствующие. Проверка наличия/текущих links/quantity/held/profile отделена от intrinsic compatibility; ранги0 available,1 owned blocked,2 missing. Для модернизаций сначала сохраняются допустимые канонические установки/замены, включая снятие обрезки при лимите и восстановление long baseForm; иначе intrinsic preview использует текущую форму и только синтетические зависимости. Предпросмотр ничего не устанавливает. `loadWeaponModSourceItems(catalog)` читает доступные world Items и canonical `world.rebreya-gear` index с gearId (один запрос на binding, native cache); не создаёт документы, отсутствие доступа не блокирует owned UI. Строка получает существующий documentUuid/img; обычные fields mechanics/requirements сохраняются для consumers. `createWeaponModCatalogHtml(rows,kind,mountId)` выводит две группы с разделителем, картинку/имя/native `a[data-link][data-uuid]` и отдельную кнопку установки; prose не выводится. Missing установка disabled, ссылки остаются читаемыми и доступными клавиатурой.

`getWeaponModMountPositions(host)` сохраняет topology3/6/2 и центры; карточка18.7% ширины, aspect1 в диаграмме5:3. `getWeaponModConnectorPoints(host,mountIds)` возвращает четыре orthogonal точки между границами bottom/barrel tile, half-size93.5; золотой маршрут/середина и один декоративный padlock на physical child сохраняются. `createWeaponModPanelHtml` выводит frame legend, полные square images, один primary marker и plain-text data-rm-tooltip с mount/name/«Пусто». Inline caption и inline каталог отсутствуют. `bindWeaponModPanel(...,{loadSourceItems,openContextMenu,...})` использует общий с куклой героя `bindAnchoredTooltips`: body portal/role=tooltip, предпочтение top и scoped прозрачный фон; клавиатурный focus поддерживается. Каталог через AnchoredOverlay всплывает у слота, не меняет высоту листа; наружный click/Escape/close/rebind освобождает portal и listeners. Внешний content получает прежний action dispatch, отдельный AbortController закрывается при замене. UUID reference не имеет href, клики сохраняют propagation в native TextEditor и закрывают каталог; Enter/Space активируют ссылку. `buildWeaponModContextActions(item,child,projection,api,{run,open})` возвращает строки Open/remove/native activities для существующего openHeldItemContextMenu. Подтверждённая reciprocal weapon связь вызывает прежнюю typed removeWeaponAttachment с operationId; matching ordinary installedUpgrade — прежний removeItemUpgrade. Чужая связь не получает remove. Через bindItemUpgradeSheet(root,app,moduleApi,{openContextMenu}) dnd5e owner инжектирует своё контекстное меню, без циклического импорта. `renderWeaponModPanel` сохраняет mount; root sequence/AbortController/fresh/busy guard и drag preview/drop остаются прежними.

`installWeaponModWithChoices(item,component,api,{mountId,catalog,projection,chooseMount})` требует реальный owned Item; владелец черты выбирает все свободные места многоопорного обвеса, отмена не пишет state. Modern replacement/500gp подтверждаются до typed install. `choose(title,entries)` спрашивает конкретный экземпляр/действие; `request(item,method,payload,api)` сохраняет operationId для неопределённого повторного запроса. Все world mutations идут через прежний API. В occupied context доступны строки open/remove/native activity без select dialog; отдельного снятия modern parts нет.

В `item-upgrade-sheet.js` `installItemUpgradeWithChoices` направляет mod drops в тот же install helper; ordinary upgrades не зависят от загрузки weapon catalogue. `isInstalledModInventoryItem` сохраняет legacy exports. Focused: `weapon-mod-panel.test.mjs` (совместимость/группы/native links/геометрия/subtabs/paid install), item-upgrade-service, item-sheet-branding, module-manifest; текущие live evidence и границы — в follow-up verification report.

## Чертежи

Владелец `scripts/data/weapon-blueprints.js`, manifest `data/weapon-blueprints.json`, raster originals `assets/weapon-blueprints/`. `buildWeaponBlueprintIndex(manifest,hosts)` проверяет coverage каждого текущего host, уникальность IDs/paths, размеры и нормализованные anchors всех поддержанных mounts; число host не зашито. `getWeaponBlueprint(index,item,catalog)` возвращает individual для known host, family fallback только для неизвестного поддержанного оружия; unrelated item получает null. `loadWeaponBlueprints(hosts)` кеширует один Promise manifest fetch, при ошибке допускает повтор; filesystem scan отсутствует, Item.img не меняется. Focused `weapon-blueprints.test.mjs`: coverage/anchors, все41 файла и разные hashes, fallback policy, concurrent fetch once. Individual38 +fallback3 визуально проверены в контактной таблице.

## Цели, глушители и разброс

Владельцы: pure `weapon-mod-roll-modifiers.js`, прежний `CombatAttackService` и `CurseUpgradeDamageAdapter`. Focused: `weapon-mod-target-effects.test.mjs`, commands, combat, curse, absorption, automation tests.

- `isValidWeaponModTargetDecision(value)`, `resolveWeaponModTargetConditions(known,decision,context)`, `buildWeaponModTargetDecision(input)`: exact target-effects DTO; только неизвестные факты дополняются решением. MaterialTarget подтверждает authenticated GM. Глушитель: musket/pistol/rifle, радиус30/10 фт., native Восприятие против10+floor(actual attack total/2), раскрытие конкретному наблюдателю без изменения global hidden.
- `tagWeaponModAttack(config)` сохраняет nonce, Actor/host/activity/token/targets, ammo, modifier/scatter formula и component/profile identities в options native roll. `getWeaponModAttackContext(message,activityUuid)` требует один evaluated roll; `getWeaponModDamageContext(messageOrId,targetUuid,activityUuid)` восстанавливает originating/associated attack, отказывает при неоднозначности.
- Публичные `rollWeaponAttack(actor,weapon,options)` и `rollFirearmAttack` используют ту же проверенную native attack activity (при необходимости `options.activityId`) и tag на фактическом Roll, включая реальный ability modifier/critical/fumble. Созданная карточка содержит matching dnd5e activity/attack flags и поступает в прежний GM listener. `createMessage:false` сохраняет отсутствие карточки и не создаёт target/scatter receipts. Без реальной native activity публичный старый бросок не получает вымышленной activity identity. `resolveWeaponModScatter` читает native critical/fumble или сохранённые факты этого legacy Roll, не бросая атаку повторно.
- `resolveWeaponModTargetEffects(payload,{sender,assertAuthority})` и `resolveWeaponModScatter(payload,context)`: active GM + OWNER, прежний inventory coordinator. Детерминированные закрытые GM-authored ChatMessage receipts: pending → rolling → resolved; durable rolling до RNG. Неопределённый rolling требует ручной сверки без переброса. `#writeWeaponModTargetReceipt(receipt,before,next,patch,guard,key)` делает CAS/readback и authority checks. Attack roll/патроны не меняются.
- `getWeaponModTargetConditions(actor,context,target)` читает geometry/deafened, `promptWeaponModTargetConditions(input)` спрашивает неизвестное у GM. Геометрия проверяется после диалога. Observer receipt виден GM/владельцам наблюдателя; стрелку только для исходной явной цели.
- `isValidWeaponModScatterDecision(value)`, `buildWeaponModScatterPlan({host,attack,scatterDamage,abilityModifier,contributions,targets})`: exact decision, радиус5/strong10, weak добавляет только фактический ability modifier. Тот же attack total против AC других существ, large Token выбирает одну занимаемую клетку. Один native DamageRoll, без обычных bonuses/critical dice; штатная card применяет HP. Неизвестная КД/геометрия требует ручного решения. `getWeaponModScatterHits(attack)` принимает дополнительные projectile targets только из GM resolved receipt.
- `initializeWeaponModTargetIndex()` исключает исторические атаки; `handleWeaponModAttackMessage(message)` обрабатывает новые nonce через существующие chat hooks, сначала scatter. `prepareWeaponModDamageUse(activity,config,message)` ждёт решения до native rollDamage и сохраняет config/dialog/flags/authored parts.
- `getWeaponModDamageRule(actor,options)` возвращает два scoped trait-флага только для точных target/attack/component identities из GM receipts. `warnWeaponModDamageLimit(actor,options)` сообщает о ручном расчёте custom MIDI trait expressions.

## Вычисляемые свойства и вес

- `weapon-mod-projections.js:buildWeaponModContributions({host,mods,context})` получает detached source и проверенные links, возвращает typed contributions с identity Actor/host/child/effect/version и diagnostics. Исходные веса переводятся по native weight units; отрицательная каталожная масса модернизации используется как delta, если native nonnegative schema сохранила0. Никакие projectedEffects flags не записываются.
- `projectWeaponModItem(system,contributions,{itemId})` применяет delta массы к native derived полям после чужих AE: clamp(body + modernized weights) → body multiplier → attachment weights; существующий simple-upgrade reducer вызывается после этого ровно один раз. Проверенный child получает derived weight0, source-вес сохраняется. Дальность меняется отдельно по нормальной/максимальной tracks; добавляется ProneFire. Saw-off снимает two и уменьшает только base denomination, сохраняет number/bonus/types/extra terms; custom formula диагностируется для решения мастера.
- `ItemUpgradeAutomationService.project` объединяет прежние вклады с weapon-mod contributions; catalogue читается один раз в `initialize`. `applyItemProjection/restoreItemProjection` используют прежний Item.applyActiveEffects wrapper и WeakMap, сравнивают каждый исходный/вычисленный owned field отдельно: source edit одного поля не оставляет старый вклад в других и не перезаписывает чужие изменения. `getWeaponModItemState(item)` возвращает detached read-only state для native consumers.
- `getWeaponModEffectiveHost(host,parts)` выводит текущую short/long форму только из проверенных частей. `readWeaponMods` сначала валидирует модернизации, затем совместимость обвесов с итоговой формой. Paid quote проверяет оставшиеся обвесы до списания: длинноствольный обвес нужно снять перед обрезкой.
- `held-items.js:getItemHandRequirement` учитывает verified derived saw-off state в существующем reader для object и legacy numeric flags; authored flags не переписывает. Удаление части возвращает исходные ограничения.
- Focused: `tests/weapon-mod-projections.test.mjs`, `tests/held-items.test.mjs`, прежние simple-upgrade projections/automation/roll/absorption; суммарный вес проверяется реальным `buildActorInventoryWeightSnapshot`.

## Магазин и боеприпасы при пересборке

- `weapon-mod-rules.js:getWeaponModAmmoConfiguration({capacity,ammunition},parts=[])` вычисляет base/effective capacity и тип патронов по проверенным итоговым частям; исходный Reload не переписывается, увеличение округляется вниз.
- `CombatAttackService.planWeaponAmmoReconfiguration(actor,host,{capacity,ammunition,modernizedParts=[]}) -> Promise<{updates,creates,before,after,returned}>` строит read-only CAS-план. Уменьшение возвращает излишек, смена типа выгружает весь прежний магазин; неизвестный тип/источник блокирует изменение до записи. Возврат идёт в точный canonical source/subtype, без fuzzy name matching; при отсутствии такого stack native factory создаёт detached данные с количеством патронов, а не упаковок. Identity/quantity/name/effects snapshots проверяются вместе.
- `#resolveFirearmReloadCapacity/#resolveFirearmAmmoState/#setFirearmAmmoStateSync` сохраняют baseCapacity для модернизированного магазина, не обрезают его до исходного Reload при чтении/выстреле/перезарядке. `resolveFirearmAreaFire` расходует min(current,baseCapacity); дополнительные патроны остаются. Прежняя обычная автоматическая очередь по шесть патронов и partial area fire сохранены.
- `ItemUpgradeService.#mutateWeaponMod` включает ammo create/placement, снятие и новую часть в один существующий batch. Create-only refund step использует тот же journal/origin/recovery; `ItemInstanceDocuments.verifyCommitted` для kind=create сверяет весь созданный snapshot. Compensation удаляет только неизменённый собственный refund, потерявший власть GM не компенсирует.
- Focused: ammo/magazine/rifling/overflow cases в `tests/combat-attack-service.test.mjs`, `tests/weapon-mod-mutations.test.mjs`; instance batch и environment automation regressions.

## Установка и typed commands

- `ItemUpgradeService(moduleApi,{getManifest,getWeaponModCatalog=loadWeaponModCatalog})` сохраняет прежние upgrade API. `getWeaponModsProjection(host)` возвращает проверенные live links, diagnostics и полный каталог с реальными свободными itemIds/quantity того же Actor.
- Projection включает diagnostics текущего host из канонического automation owner, поэтому авторская damage formula при обрезке получает видимое предупреждение мастеру. World Item без Actor остаётся доступен для чтения. Install/modernize повторно проверяют equipped+heldHands под Actor lock до денежных/Item writes; `component-held` требует освободить руки. UI проверка не заменяет backend.
- `installWeaponAttachment(host,component,{mountId,operationId,sender,assertAuthority})`, `removeWeaponAttachment(host,componentOrId,{operationId,sender,assertAuthority})` используют существующие InventoryService journal/coordinator, `ItemInstanceWorkflow.runBatch` и `ItemInstanceDocuments`. Под Actor lock повторно читаются host/component; split отделяет ровно одну единицу. Mode/host/mount входят в fingerprint. Patches изменяют только weaponMods, installedWeaponMod и native container; обычные upgrades не меняются. Authority проверяется вокруг каждой записи, потерявший власть GM не компенсирует. Terminal replay не восстанавливает удалённый child.
- `installWeaponModernization(host,component,{removeItemId,operationId,approvalReceiptId,...context})` и paid alias `applyWeaponModernization` проверяют итоговую сборку через `buildWeaponRebuildQuote`, списывают ровно 50000 cp из native `system.currency` Actor-владельца оружия и включают снятие/часть/патроны в один batch. Нехватка денег отклоняется до записи; exact currency before/after обеспечивает восстановление исходных номиналов. Стоимость приобретения детали независима от платы. Календарь/craft/project state не используются; неделя по 8 часов — только текст правила.
- `approveWeaponModernization(payload,{sender,assertAuthority})` записывает authenticated GM audit в тот же journal, привязанный к Actor/host/source/profile/operationId. Host approvals содержат только ссылки; при новой установке каждый receipt проверяется по реальной terminal записи. Approval receipt не входит в business fingerprint, поэтому server-side согласование не ломает сетевой retry исходного запроса. Новая операция требует нового согласования.
- `weapon-rebuild-rules.js:buildWeaponRebuildQuote({host,component,parts,removeItemId,gmApproval,currency})` валидирует singleton/compatibility/cap/dependencies и смешанные native монеты, возвращает `{costCp,beforeCp,afterCp,currencyBefore,currencyAfter,removeItemId}`. Нет времени, расписаний, новых кошельков или скидок.
- Private `#publishWeaponModAction` после durable результата обеспечивает один ChatMessage с детерминированным ID, operationId и native activation `{type:bonus|action,value:1}` в module flag; write-then-throw сверяется по collection, failed publication повторяется без второго install. Отдельный счётчик действий не вводится.
- `weapon-mod-mutation-commands.js:registerWeaponModCommands(moduleApi,bus)` регистрирует `item-mod.attachment.install/remove`, `item-mod.modernization.install/approve`, `item-mod.activity.use` с exact validators, authenticated sender, OWNER/GM и Actor scheduling. Activity decision допускает null либо exact attack-conditions DTO; неподдерживаемое действие не пишет state. Особое оружие при отсутствии audit показывает активному GM native подтверждение; отказ не списывает деньги и не создаёт установку. `isValidWeaponAttachmentInstallPayload`, `isValidWeaponAttachmentRemovePayload`, `isValidWeaponModernizationInstallPayload`, `isValidWeaponModernizationApprovalPayload`, `isValidWeaponModActivityPayload` исключают произвольные цены/profiles/sender flags.
- Composition wrappers `installWeaponAttachment(payload)`, `removeWeaponAttachment(payload)`, `installWeaponModernization(payload)`, `approveWeaponModernization(payload)` используют privileged gateway одинаково для active/inactive GM и игроков. `registerItemUpgradeFilterHook` скрывает физические installed children через существующий inventory filter.
- Focused: `tests/weapon-rebuild-rules.test.mjs`, `tests/weapon-rebuild-mutations.test.mjs`, `tests/weapon-mod-mutations.test.mjs`, `tests/weapon-mod-commands.test.mjs`; существующие instance workflow/batch, item upgrades и recovery.

## Условия атаки и прицеливание

- `weapon-mod-roll-modifiers.js:evaluateWeaponModAttack({host,attack,target,contributions,conditions})` читает только проверенные host contributions. Возвращает allowed, attackBonus, rangeMultiplier, ignoreHalfCover, stopMovement, damageRules, diagnostics, needsDecision. AND-условия с известным false не требуют уточнять остальные. Клапан меняет обе дистанции только под водой; без клапана известный underwater запрещает огнестрельную атаку.
- `WEAPON_MOD_CONDITION_FIELDS`, `isValidWeaponModAttackDecision(value)`, `resolveWeaponModConditions(known,decision,{targetUuid,attackMessageId})` задают bounded exact DTO. Решение заполняет только unknown; текущий aimMode нельзя назначить решением условий атаки. Цель/карточка и изменившиеся известные факты проверяются повторно.
- `getWeaponModAimState(host,combat,contributions)` возвращает state только для того же Actor/host, проверенного child/mode и собственного текущего combat/round/turn. Завершённый бой, перенос оружия, снятый прицел или новый ход обнуляют вычисленный результат, включая после reload клиента.
- `CombatAttackService.getWeaponModAttackConditions(activity,target,config)` читает native statuses/prof.hasProficiency, движение своего хода, явный underwater Actor/Scene flag и видимость из конкретного workflow. Неизвестные факты остаются null. `deferWeaponModAttack(activity,config,dialog,message,method)` синхронно отменяет native hook, затем `promptWeaponModConditions` уточняет только нужные поля и возобновляет use/rollAttack с исходными authored parts. Cancel не возобновляет бросок; native hookNames/rolls shift учтены. `hydrateWeaponModAttackConditions(config,message)` читает решения только из совпадающей originating card/activity/Actor/host, а не shared activity state.
- `SimpleUpgradeRollAdapter.evaluate(host,attack,target,activity,config)` объединяет прежние модификаторы и новые условные бонусы. Общий `weaponActivity(activity)` принимает только weapon Item и native mwak/rwak/fwak либо weapon classification с melee/ranged/firearm; `preRollAttack/preRollDamage` используют этот guard. Native огнестрельный бонус добавляется в roll config ровно один раз, без записи source formulas; attack bonus не становится damage bonus. Focused: `tests/weapon-mod-roll-modifiers.test.mjs` с реальной installed projection и native fwak shape. `context/preRollAttack` требуют отдельные броски при разных бонусах/дистанциях; половинное native coverHalf компенсируется +2 только если нет coverThreeQuarters. `CombatAttackService.getWeaponModRangeResolution(activity,target,multiplier)` вычисляет эффективные normal/long и actual token footprint distance через canonical grid helper; adapter назначает помеху после normal и запрещает после long. Если Token/сцена недоступны, computed range сохраняется, автоматическая проверка расстояния недоступна. Source range/AC не меняются. Custom `rollWeaponAttack` использует тот же adapter, prompt и диапазоны.
- `SimpleUpgradeRollAdapter.halfCoverBonus(host,activity,target,config)` берёт max native AC cover/status и публичного `MidiQOL.computeCoverBonus` для точной пары Token/activity. Компенсирует только итоговые2, сохраняя ¾/full; недоступная геометрия/API явно требуют ручной сверки. Не меняет AC/traits. `deferWeaponModAttack` отклоняет известную недопустимую effective range до native consumption; публичный legacy roll также проверяет условия/отмену до расхода патронов и misfire RNG.
- `ItemUpgradeAutomationService.projectWeaponModActivityRange(activity)` изменяет только подготовленные numeric activity.range после native `prepareFinalData`, чтобы MIDI preflight видел scope/underwater multiplier. `restoreWeaponModActivityRange(activity)` восстанавливает только собственные неизменённые поля; отдельные WeakMaps сохраняют base/effective и wrapper identity. `getWeaponModActivityRangeState(activity)` возвращает base только для совпадающего собственного результата; Combat range consumer не умножает дальность повторно. Повторная подготовка, окончание aim и авторский activity override сохраняют source formulas и Item.range; managed spear/launcher и melee исключены. Focused projection test дополнительно исполняет настоящий installed MIDI checkRangeFunction, если источник установлен.
- `buildWeaponModActivities({hostId,mods})`, `resolveWeaponModActivity(host,mods,{childItemId,activityId})` в `weapon-mod-activities.js` выводят детерминированные identities из проверенных физических links/effect keys. Backend требует реальную совпадающую native activity. `ItemUpgradeService.useWeaponModActivity(payload,context)` использует прежний inventory batch/journal и ownership; `CombatAttackService.planWeaponModActivity({actor,host,definition,decision})` возвращает read-only aim placements. Начало прицеливания проверяет собственный ход и предел перемещения; stop-aim очищает только свой state. Повтор operationId не выполняет действие снова. Composition `useWeaponModActivity(payload)` направляет через typed active-GM gateway.
- `CombatAttackService.handleWeaponModTurnChange(combat,{ended})` и `handleWeaponModTokenMove(token,changed)` вызываются существующими combatTurn/updateToken/deleteCombat listeners. Активный GM сериализует Actor/host writes прежним inventory coordinator, считает native v13 passed path distance один раз на movementId, unknown/teleport не выдаёт нулевое перемещение. Движение и конец хода снимают aim. ItemUpgradeAutomationService.project выводит для активного коллиматора пять movement override0 contributions; прежний syncActor создаёт/удаляет только собственные эффекты, учитывая mode/priority и сохраняя чужие.
- `DisarmDocuments.revalidate` возвращает текущий targetItem вместе с targetActor; `DisarmService.chooseSave` передаёт его native adapter. `DisarmRollAdapter({RollClass,getContributions}).save(actor,ability,mode,{item})` добавляет проверенный disarm-bonus только к этому спасброску против обезоруживания данного оружия. Обычные saves и baseline формула атакующего не меняются.
- Focused: `tests/weapon-mod-roll-modifiers.test.mjs`, `tests/weapon-mod-projections.test.mjs`, `tests/disarm-roll-adapter.test.mjs`; прежние combat-attack, item-upgrade-roll/automation, environment и disarm owner tests.

## Действия штыка, фонаря и гранатомёта

Владелец native lifecycle — `ItemUpgradeAutomationService`; мутации и receipts — прежние `ItemUpgradeService` / `ItemInstanceWorkflow` / inventory journal. Нового хранилища, календаря или набора hooks нет.

- `buildWeaponModActivities({hostId,mods,sources,heldHands,grenadeActivities})` выводит stable native action identities. `buildWeaponModBayonetProfile(source)` берёт canonical spear, исключает thrown, сохраняет versatile. `buildWeaponModLightProfile(effect)` задаёт cone60° / bright30 / dim60. `getWeaponModGrenadeCandidate(item,{sources,allowedSourceIds})` сверяет stable ID, canonical hand/one-use explosive и сохранённый профиль.
- `buildWeaponModGrenadeActivity(marker,source,rule)` сохраняет отдельные исходные damage packets, DC и radius; native save/damage card имеет range90. Неизвестные ability/onSave и ручное разрешение задержки/особых свойств подтверждает активный GM через `CombatAttackService.promptWeaponModGrenadeRule`. Они не угадываются. `reconcileWeaponModActivities(existing,desired)` сохраняет чужие activities/flags, полные uses, косметические имена и авторские mechanical overrides; изменённый baseline получает diagnostic, automatic use отключён. `resolveWeaponModActivity(host,mods,payload,{sources})` проверяет реальную activity и физические links, поддерживает native Item clones по canonical host ID.
- `syncWeaponModActivities(actor)` использует native `system.==activities` replacement. `applyWeaponModActivityRuntime(item)` идемпотентно оборачивает только managed instances, включая native cloned Items. Для штыка private `#createWeaponModBayonetItem` готовит отдельную неперсистентную native spear model с тем же host/activity UUID: base damage и STR, native spear proficiency/Actor bonuses/exhaustion, без thrown/огнестрельных патронов. `getWeaponModActivityProficiency` предоставляет native proficiency. Attack остаётся действием реального host; его native roll builder принудительно исключает ammunition/thrown modes, а getAttackData/getDamageConfig делегируют копью. Исходные Items и формулы не переписываются.
- `syncWeaponModLights(actor)` создаёт отдельный deterministic AmbientLight на активный flashlight/Token: точный конус следует центру/rotation/elevation Token. Token.light и произвольные lights не меняются; у своего light меняются только position/bright/dim/angle/hidden, чужие color/config extras и flags сохраняются. Выключение, снятие, удаление/смена Actor Token удаляют только собственный light; authority проверяется вокруг writes. State на physical child: `weaponModLight={enabled,tokenUuid}`. Existing Token hooks вызывают прежний sync owner.
- `CombatAttackService.deferWeaponModUtility(activity)` возвращает synchronous false, затем `promptWeaponModChoice` выбирает конкретный Token/owned grenade и направляет exact DTO в existing active-GM gateway. Один in-flight request на действие; после ошибки operationId сохраняется. `planWeaponModActivity` возвращает placements для aim/light. Install/remove и utility cards используют private `#publishWeaponModAction`: deterministic ID, write-then-throw readback, terminal replay не повторяет мутацию.
- `ItemUpgradeService.#prepareWeaponModLauncherLoad` переносит ровно одну физическую гранату через прежний split/placement batch в container=launcher child; допускает разные проверенные типы, всего6. Main magazine не меняется. Из другого установленного launcher напрямую не перезаряжается; снятие самого launcher сохраняет содержимое.
- `#prepareWeaponModLauncherShot` обрабатывает exact `launcher-prepare`, `launcher-consume`, `launcher-ack`. Prepare без расхода записывает native Activity, проверенный GM rule и journal proof. Awaited native consume после configuration списывает конкретную qty1 гранату, отсоединяет qty0 и записывает consumed receipt в том же CAS batch. Receipt связан с Actor/host/child/source/profile/Activity/стрелком/prepareOperationId. До native card publication следующий выстрел и перенос оружия запрещены. Private `#applyWeaponModLauncherRuntime` публикует native card с deterministic ID/keepId и per-attempt publisher marker; ambiguous success подтверждается readback, проигравший concurrent publisher не запускает повторную native finalization. Existing/published card останавливает повтор до ресурсов и subsequent actions; create:false сохраняется. Ack сверяет actual card и receipt. Private `#cleanupWeaponModGrenade` после terminal ack удаляет только неизменённый own spent qty0 Item, повтор безопасен; чужие правки требуют сверки.
- Typed payloads и ownership проверяет `isValidWeaponModActivityPayload` / `registerWeaponModCommands`. Решение GM не принимается из player DTO. Rebuild остаётся immediate500gp за одну часть, без проектов.
- Private `#weaponModGrenadeSignature(data)` сравнивает полный исходный экземпляр, исключая только native `_stats` и равнозначные пустые folder/container. Prepare journal сохраняет grenadeSource; consume выполняет CAS полных authored system/effects/flags и меняет только quantity/container/own spent marker. Cleanup сверяет полный ожидаемый остаток с этим snapshot: чужая правка имени/формул/зарядов/flags блокирует удаление. Смена GM после debit продолжает тот же batch без компенсации прежним GM и без второго расхода.
- Focused: `tests/weapon-mod-activities.test.mjs`, `tests/weapon-mod-commands.test.mjs`, `tests/weapon-mod-mutations.test.mjs`; compatibility: combat-attack-service, item-upgrade-automation-service, runtime-item-graph, weapon-mod-transport, gear-compendium, magic-item-runtime. Native baseline: Foundry13.351 / dnd5e5.2.5. Особые эффекты и задержки гранат разрешаются вручную по source description через native card; автоматических таймеров нет. Native template placement идёт после расхода по контракту dnd5e; отмена native configuration до consume бесплатна.

## Физическое дерево, Storage и цена

`getRuntimeWeaponModChildren` также запрещает изменение/перенос дерева с `weaponModShot.phase=consumed` до подтверждения карточки. Завершённый выстрел не блокирует перенос. Focused: weapon-mod-activities/transport/runtime-item-graph.

- `runtime-item-graph.js:getRuntimeWeaponModChildren(host,items)` проверяет обе физические связи, singleton, source identity, непересекающиеся крепления и orphan reverse links без повторной сборки по каталогу. Capture включает children один раз; build remap-ит оба направления и Actor; materialize отвергает изменённые связи при replay. Envelope остаётся RuntimeGraph v1, charges/ammo/effects сохраняются.
- `lootgen-composition.js:normalizeWeaponModComposition(raw,{instanceKeys})` проверяет exact DTO v1 с отдельными attachments/modernizedParts, global identities и mounts. `weaponModComponents(descriptor)` возвращает плоский список без размножения multi-mount child. Нормализаторы композиции/дерева и aggregation key принимают descriptor v3, сохраняют прежние контракты v1/v2, лимиты 200 документов/8 уровней.
- `composite-item-graph.js:buildCompositeItemGraph(raw,{buildBase,buildUpgrade,buildWeaponMod=buildUpgrade,weaponModCatalog,createDocumentId,manifest,actorId})` валидирует v3 по проверенному каталогу до вызова builders компонентов и создаёт detached native links. Для переноса существующих custom Items используется физический snapshot, а не этот builder.
- `storage-container-item-service.js:captureHostData` включает новые компоненты и их реальные descendants через канонический `captureRuntimeItemGraph`, исключая их из обычных contents. Заряженный launcher сохраняет каждую гранату, source UUID/custom fields и remapped container; пересечение/цикл/лимит200 отклоняются. `prepareItemGraph` учитывает их identities; `storage-container-snapshot.js:normalizeItemRow` запрещает quantity>1 для составного v3.
- `lootgen-prepared-item.js:readLootgenPreparedComposition/buildLootgenPreparedItem` сохраняют marker v2 и runtime v1 с descriptor v3, проверяют количество children и точное совпадение связей корня и графа. Контейнерная валидация охватывает каждый host дерева.
- `item-value.js:evaluateItemValue(descriptor,reader)` для v3 добавляет `weaponModValue`, суммируя каждый реальный компонент один раз. Неизвестная цена/неверный kind отклоняется; global identity/depth/document budgets общие с contents. Точная форма результата v2 сохранена. `lootgen-catalog-reader.js:resolveValueComponent` передаёт source attachment profile для проверки kind.
- `ItemInstanceDocuments.readSource` выставляет `hasWeaponMods`; `planItemInstanceMutation`, `getInventoryDismantleBlockReason` и `isInventoryGraphItem` защищают составное оружие и установленный child от plain/split/dismantle путей. Inventory graph transfer запрещает отдельный перенос child и проверяет связи при recovery.
- Focused: `tests/weapon-mod-transport.test.mjs`, `tests/composite-item-graph.test.mjs`, существующие runtime graph, prepared item, Storage, value, instance/recovery и disarm tests.

## Каталог и носители

Владелец: `scripts/data/weapon-mod-catalog.js`; источники: `data/gear.json`, `data/weapon-mod-rules.json`, `data/weapon-mod-hosts.json`.

- `buildWeaponModCatalog(gear,definitions,hosts) -> {rows,hosts}` проверяет уникальные stable IDs, source joins, типы правил и известные compatibility tags; future source без правила сохраняется видимым unavailable. Возвращает detached профили с исходным attachment signature; source данные не меняет.
- `loadWeaponModCatalog() -> Promise<Catalog>` объединяет три versioned read-only fetch в cached Promise; ошибки сбрасывают Promise для повтора. Не сканирует assets и не пишет settings/Items.
- `getWeaponModCandidate(item,catalog)` возвращает `{itemId,sourceId,quantity,profile,profileSignature,available,legacyOverride,reason}`. Source — только `gearId`; отсутствие старого stored attachment допускает каталог, отличающийся custom профиль сохраняется без новой установки. Нет name fallback.
- `getWeaponModHostDescriptor(item,catalog)` возвращает `{id,gearId,family,form,baseForm,modelTags,mountIds,quantity,requiresGmApproval}` либо null. Канонические source rows различают primitive/advanced/crossbow и short/long; колесцовый пистолет long. Удаление текущего Reload исключает magazine-fed tag. Native неизвестный firearm получает family fallback и необходимость решения GM; обычный неизвестный weapon не становится огнестрелом по имени.
- Focused: `tests/weapon-mod-catalog.test.mjs`, `tests/weapon-mod-rules.test.mjs`.

## Pure правила и проверка сохранённых связей

Владелец: `scripts/data/weapon-mod-rules.js`; Foundry globals отсутствуют.

- `WeaponModRuleError(code,details={})` сообщает объяснимый отказ incompatible/invalid-quantity/slot-conflict/duplicate-mod/capacity/missing-dependency/unavailable/gm-approval-required.
- `weaponModFlag(item,key)` читает flag без записи; `weaponModProfileSignature(profile)` канонизирует object keys. `isInstalledWeaponMod(item)` распознаёт синтаксическую обратную связь/container; это не подтверждение авторизации/валидности.
- `hasFirearmMastery(actor)` проверяет stable identifier/featId черты; `getWeaponModHostDescriptor` публикует `freeMounts` только по данным Actor. `validateWeaponAttachmentInstallation(host,installed,candidate,{mountId=null,mountIds=null,freeMounts=false}={}) -> {mountIds}` требует singleton host, доступную целую единицу, verified profile, совместимость и уникальность вида. Без черты oneOf занимает одно свободное место из перечисленных, all — по одному каждой категории; с чертой разрешены любые свободные места в прежнем количестве. Сервер повторно определяет наличие черты под Actor lock, проверяет переданные места и записывает `freeMounts:true` в обе ссылки. Intent без mountIds сохраняет прежний fingerprint. Повреждённые/перекрывающиеся installed mounts отклоняются до выбора. Focused: `weapon-mod-rules`, `weapon-mod-mutations`, `weapon-mod-commands`, `weapon-mod-panel`, `weapon-rebuild-rules`.
- `validateModernizedPartInstallation(host,parts,candidate,{removeItemId=null,gmApproval=null}={}) -> {countedParts,removeItemId}` проверяет итоговую сборку, зависимости, исключающие пары, максимум3 counted parts, improved-grip exception и GM requirement. Бесплатное включённое снятие допускается при достигнутом лимите; оно не оставляет orphan dependency. Crossbows не являются носителями modernizedPart.
- `readWeaponMods(host,resolveItem,catalog) -> {attachments,modernizedParts,diagnostics}` читает weaponMods v1 и возвращает только реальные children с quantity1, exact Actor/host/container/reverse links, source signatures и допустимыми полными mount sets/частями. У нестандартной установки `freeMounts` обязан совпадать в обеих ссылках; она сохраняет действие после передачи и при paid rebuild. Все исторические flags сохраняются, invalid entries получают diagnostics без эффекта. Проверка прежней установленной части не требует повторного GM approval после переноса.
- Новый state не переиспользует `itemUpgrades`/`installedUpgrade` и не меняет 1–3 слота обычных усовершенствований. Runtime mutation/effect APIs не публикуются на этом этапе.
- Focused: `tests/weapon-mod-rules.test.mjs`, `tests/weapon-mod-catalog.test.mjs`; compatibility regressions: item-upgrade-rules/service, gear-compendium.
