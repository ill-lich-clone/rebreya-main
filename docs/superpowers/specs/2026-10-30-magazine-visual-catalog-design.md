# Физический магазин и полные профили боеприпасов

Дата: 2026-10-30. Продолжение пользовательской задачи о боеприпасах. Механика утверждена в 2026-10-30-ammunition-magazine-design.md. Пользователь отклонил лоток и задал фотографией изогнутый коробчатый магазин; прямо попросил попробовать взаимодействие с ним. Фото — источник формы; прежний эскиз лотка не является утверждённым образцом.

## Наблюдаемый результат

Редактор показывает изогнутый металлический магазин с разрезом: видны отдельные патроны и их порядок, верхний идёт следующим. Патроны одной атаки образуют однородную группу 1/3/6. Нажатие на группу выбирает её; выбор боеприпаса справа или перетаскивание карточки на группу заменяет состав локального черновика. Перемещение групп, заполнение остатка, пресеты, предыдущая зарядка, отмена и разрядка сохраняются. У клавиатуры есть доступный эквивалент drag-and-drop. Цвет дополняет имя и подпись типа. Legacy rounds показаны как неизвестные, но не как отдельный доступный запас с нулём; решение мастера остаётся явным.

Изменение внешнего вида не меняет количество, вместимость, авторские формулы, расход 3/6, однократный бонус, имплант, осечки и права. Пока не подтверждено — никаких Document writes. Сложные эффекты остаются ручными. Нет отдельного Item-магазина, новых сокетов, журналов или очередей.

## Подтверждённая причина отсутствующих боеприпасов

В мире testovyj3 у Actor и в world.rebreya-gear огненная/ледяная мазь имеют subtype firearmBullet и ammunition:null; винтовка требует rebreyaRifle. В data/gear.json у обеих compatibility:[all]. normalizeGear в scripts/data/normalizer.js отбрасывает ammunition/explosive/attachment, поэтому фактическая модель и компендиум не получают профили. Runtime stable IDs нормализованы в boepripasy-s-ognennoy-maz-yu-20 и boepripasy-s-ledyanoy-maz-yu-20; текущий прямой damage lookup знает только исходные Cyrillic IDs.

Нормализатор должен сохранять полные detached профили ammunition/explosive/attachment. Известный catalog-backed Item с отсутствующим профилем получает его в read projection только по точному gearId; authored non-null профиль имеет приоритет. Это не требует изменений инвентаря при открытии окна или участия GM. Та же проекция используется для совместимости, source identity, возврата, snapshot и урона; уже сохранённые известные source keys без профиля согласуются в read projection с сохранением ссылок rounds/presets/lastPattern. Неизвестные legacy charges не типизируются автоматически. Оба варианта stable ID мазей дают однократный 1d6 своего типа.

## Подход и границы

Лоток со списками отвергнут пользователем; плоская декоративная фотография не позволяет видеть состав. Выбран заданный пользователем физический силуэт с интерактивным разрезом. Отдельный процедурный 3D-движок не нужен. Native ApplicationV2/Handlebars остаётся; корпус использует предоставленное фото с UI-клипом по силуэту, патрон — отдельное сгенерированное изображение, а подписи, горячие области, состояние и подтверждение остаются кодом. Размер окна около 960x760; узкий режим сохраняет доступность кнопок и не обрезает имена. Допускается художественный разрез корпуса, чтобы показать содержимое; это намеренное отличие от непрозрачного фото.

Канонические владельцы: normalizer, ammunition-compatibility, ammunition-magazine, CombatAttackService и существующий AmmunitionMagazineApp. Никаких новых независимых хранилищ. Сохраняются все контракты предыдущей спецификации.

## Проверка

Regression: raw catalog → normalized model → native Item projection → совместимость и урон; старые Actor Items без профиля без writes; authored overrides; известные старые source keys и точный unload; legacy count; draft selection/drop/reorder/presets/cancel; разный состав внутри одной атаки запрещён. Live: реальные source snapshots клонируются в disposable fixture, основные пути проверяются в Foundry13.351/dnd5e5.2.5, визуальная форма сравнивается с фото; производственные Actor quantities/composition не меняются. Выполняются focused/full tests, JS/JSON checks, passport/README, release/cache, независимый review, commit/push только своих файлов в lich_branch.

Art decision: генерация технического разреза была отклонена image tool; безопасная exterior-art версия имела непригодную прозрачность. Корпус берётся непосредственно из пользовательского фото без raster edits: native SVG clips показывают только его силуэт и интерактивное окно. Generated cartridge art сохранён отдельным asset; все реальные controls и подписи native. Отдельный непрозрачный 3D-art не нужен.
