# Lootgen: множественное появление предметов

## Цель

Сделать количество предметов в выдаче правдоподобным, не превращая настройку количества в жёсткий потолок. Лутген должен учитывать бюджет, естественные размеры пачек конкретных предметов и разнообразие выдачи. Магические предметы остаются исключением: один конкретный магический предмет может выпасть только в одном экземпляре за генерацию.

## Источник данных

Основной источник — лист `Общий компендиум снаряжения V0.1` таблицы `Ребрея: Оружие, огнестрел и снаряжение`:

`https://docs.google.com/spreadsheets/d/1G-UCW00vsjON05fr0CgyK03YaF82oYJemlqNKdv1JBk/edit`

Колонка `M` называется `Множественное появление`. На момент проектирования на листе 773 заполненные строки предметов, а значения в колонке пусты.

Значение колонки описывает количество упаковок предмета, а не число единиц внутри уже описанной упаковки. Поэтому `Стрелы (20)` со значением `1` означают одну пачку из двадцати стрел.

## Формат значения

Поддерживаются:

- положительное целое число: `1`, `4`, `20`;
- формула костей в русской или латинской записи: `1к4`, `2к12`, `1d6`, `2d12`;
- пустое или некорректное значение нормализуется в `1`.

Формула бросается один раз при каждом успешном выборе позиции. Результат броска становится количеством добавляемых упаковок. При повторном выборе обычной позиции новый бросок прибавляется к уже набранному количеству.

## Правила заполнения таблицы

Значение `1` получают предметы, которые естественно встречаются по одному или уже являются готовой пачкой:

- оружие, огнестрельное оружие и доспехи;
- инструменты, контейнеры и готовые комплекты;
- транспорт и скакуны;
- импланты, усовершенствования и обвесы;
- сокровища;
- уже упакованные боеприпасы и расходники: `Стрелы (20)`, `Иглы для трубки (50)`, `Металлические шарики (1 000 шт. в сумке)` и аналогичные позиции.

Формулы получают только предметы, которые естественно находить россыпью или небольшим запасом. Начальные ориентиры:

- бумага по одному листу — `2к12`;
- мел по одному кусочку — `1к6`;
- небольшие расходники, свечи, фляги масла и аналогичные запасы — обычно `1к4`;
- дешёвые массовые расходники — до `2к12`.

Каждая из 773 строк должна быть просмотрена по названию, типу, описанию и упаковке. Название с числом в скобках само по себе не создаёт формулу: если число уже является содержимым одной упаковки, значение остаётся `1`.

## Настройка Lootgen

В форму и сохранённые шаблоны добавляется поле `Оптимальное количество предметов`. Значение по умолчанию и значение миграции старых шаблонов — `4`.

Это мягкий ориентир для количества одинаковых обычных позиций, а не максимум результата. Формула `Множественного появления` имеет приоритет и может сразу дать количество выше ориентира.

## Алгоритм генерации

1. Лутген выбирает доступные позиции в текущих фильтрах ранга и типа.
2. Один проход содержит не более `itemCount` успешных выборов. Если доступных вариантов меньше, проход заканчивается раньше.
3. Для выбранной обычной позиции бросается её формула множественного появления. Количество уменьшается до максимально доступного по остатку бюджета; платная позиция никогда не выводит результат за пределы бюджета.
4. При выборе кандидата новые позиции и позиции ниже оптимального количества получают повышенный вес. Позиции на уровне или выше ориентира остаются в пуле с пониженным весом, а не исключаются. Случайный выбор внутри этих весов сохраняет разнообразие результатов без жёсткого потолка.
5. Если бюджет существенно не заполнен, начинается следующий проход по доступному пулу.
6. В следующем проходе обычная позиция может выпасть снова. Для неё заново бросается формула множественного появления, а результат прибавляется к существующей строке.
7. Когда недостающую стоимость разумно закрывает ещё одна упаковка сверх ориентира, она добавляется. Дешёвые массовые предметы могут накопить большие количества, если это соответствует их формуле и бюджету.
8. Конкретный магический предмет после первого выбора исключается из последующих проходов и всегда имеет итоговое количество `1`, включая магические расходники.
9. Предмет без настоящего положительного `value` может появиться как отдельная находка, но не расходует бюджет и не используется для добивания бюджета. Это предотвращает стеки `x500`, созданные из искусственной стоимости `1`.
10. Генерация завершается, когда бюджет заполнен, нет доступных вариантов, очередной полный проход не добавил стоимость или остаток меньше стоимости всех доступных платных позиций.
11. Неиспользованный остаток переводится в монеты по существующему правилу.

Алгоритм обязан иметь конечное число операций: нулевые значения выбираются не более одного раза за генерацию, магические позиции исключаются после выбора, а каждый платный повтор уменьшает остаток бюджета.

## Шаблоны

Каталог шаблонов получает новую версию данных. При чтении старого каталога отсутствующее поле `optimalItemQuantity` нормализуется в `4`, после чего миграция сохраняет обновлённый каталог в world setting.

В интерфейс Lootgen добавляется удаление выбранного шаблона с подтверждением. После появления этого управления из живого мира удаляются только явно тестовые записи Codex; пользовательские шаблоны не удаляются.

## Импорт данных

Импортёр `data/gear.json` должен сохранить колонку `Множественное появление` в стабильном поле модели предмета. Название поля в коде — `multipleAppearance`.

Лутген передаёт это значение из модели снаряжения в пул генератора. Парсинг и бросок формулы выполняются в чистом модуле генератора, чтобы поведение можно было тестировать без Foundry.

## Проверки

Автоматические тесты должны доказать:

- нормализацию целых чисел и формул `к`/`d`;
- откат пустых и некорректных значений к `1`;
- бросок формулы при каждом повторном выборе обычной позиции;
- возможность превысить оптимальное количество ради бюджета;
- приоритет разнообразия до чрезмерного повторения одной позиции;
- строгое количество `1` для каждого магического предмета;
- отсутствие бюджетного размножения предметов с нулевым `value`;
- перевод остатка в монеты;
- значение `4` в старых и новых шаблонах;
- сохранение `multipleAppearance` импортёром;
- работу удаления шаблона из интерфейса.

После автоматических тестов выполняется живая проверка в Foundry: применение сохранённого шаблона, генерация дешёвых массовых предметов, генерация магических предметов, остаток в монетах и удаление тестового шаблона.
