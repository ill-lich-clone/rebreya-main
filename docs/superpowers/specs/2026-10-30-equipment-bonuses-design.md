# КД магических доспехов, NPC-шаблоны и бонусы снаряжения

Статус: пользователь подтвердил объём, включая похожие фокусировки; implementation plan подготовлен к review. Дата: 2026-10-30. Builder check: существенных пробелов нет.

## Наблюдаемый результат

1. Магические доспехи с определённой базой и щиты в managed-компендиуме имеют корректный базовый КД, предел Ловкости и прочие параметры базы. Магический бонус хранится отдельно и учитывается один раз. Кираса, кольчуга, латы и проклёпанная кожа берут профиль существующего немагического снаряжения. Баклер использует собственный каталожный профиль, а не обычный щит.
2. На NPC, включая чудовищ, работает существующий выбор базового оружия для «Оружие +1/+2/+3» и именных магических шаблонов. Создание Item и повторное открытие NPC-листа используют тот же адаптер, проверки владельца, текущего пользователя и отмены, что персонажи. Пользовательские формулы и уже выбранные шаблоны сохраняются. Расширение NPC для доспехов/боеприпасов/инструментов допустимо только в пределах общего существующего адаптера без изменения их правил.
3. Универсальный инструмент, Магический гримуар и Флакон с кровью всех трёх вариантов дают соответственно +1/+2/+3 к атаке и Сл своих классовых заклинаний. Предположение автора: названный пользователем «сосуд с кровью драконов» означает каталожный «Флакон с кровью»; другого предмета с таким названием и бонусами в каталоге нет.
4. Тем же механизмом покрываются сходные уже найденные фокусировки: Амулет благочестия, Барабан задающего ритм, Лунный серп и Жезл хранителя договора +1/+2/+3. Классы: жрец; бард; друид/следопыт; колдун соответственно. Инструмент — изобретатель, гримуар — волшебник, флакон — чародей. Это предложенный дополнительный объём по фразе пользователя «Если ещё найдёшь предметы».
5. Механизированную одежду можно разместить в существующем слоте `clothing` куклы героя. Только реально размещённая owned-копия даёт +1 ко всем проверкам Силы, включая Атлетику, без бонуса к атакам, урону, значению Силы или спасброскам. Обычное хранение в инвентаре и силуэт отсутствующего предмета бонусов не дают. Снятие, удаление и замена немедленно убирают вклад; две копии не удваивают его.
6. Одежда повышает действующий множитель грузоподъёмности на 1: стандартное ×15 становится ×16. Выбор автора для ручного нестандартного множителя: прибавлять 1 к вычислению, сохраняя исходную настройку (например, ×20 → ×21); `strOverride`, `capModOverride`, `defaultCapMod`, `capBonusLb`, транспортные лимиты и имплантные бонусы не перезаписываются. Отображаемая физическая вместимость и штатный предел dnd5e должны быть согласованы с учётом существующих единиц/модификаторов. Формула складского профиля W+U / B+C не меняется.

## Условия и сохранение контрактов

- Настройка на магический предмет и требование держать/носить его следуют каталожному описанию и существующим canonical данным held-items/equipped. Для инструмента, гримуара, барабана, серпа и жезла требуется держать предмет; для амулета — носить. Флакон требует действующую настройку; удержание для его бонуса не требуется его каталожным текстом.
- Принадлежность заклинания берётся из dnd5e `system.sourceClass` и его разрешённой классовой идентичности. Мультиклассовый персонаж не получает бонус чужому классу. Неизвестный/неоднозначный источник не угадывается по характеристике или имени; пользователь может указать класс штатным полем dnd5e.
- Глобальные `system.bonuses.msak/rsak/spell.dc` для ограниченных классом бонусов не используются. Существующие авторские attack/save formulas, фиксированные Сл/атаки предметов и прочие эффекты сохраняются. Повторная preparation/reload не накапливает бонусы. Применение нескольких разных разрешённых предметов следует существующим правилам dnd5e; дубли одной семьи не суммируются.
- Для доспехов «Любой», «Лёгкий», «Тяжёлый» и других неоднозначных подтипов сохраняется выбор базы адаптером: нельзя выдумывать конкретный КД до выбора. Уже выданные копии с нулевой базой исправляются только при доказанной каталожной/выбранной базе; ненулевой ручной КД, описание, количество, заряды и эффекты не заменяются.
- Явное намеренное изменение относительно противоречивого текста одежды «увеличивается на 2, например с 15 до 16»: автоматизация следует запросу пользователя ×16 и даёт +1 к множителю. Противоречие описания отражается/исправляется явно, а не превращается в скрытый +2.
- Новых world settings, привилегированных команд, очередей, инвентарных транзакций и владельцев куклы не появляется. Изменения Documents остаются в существующих service/repository маршрутах.

## Подход

Рекомендуется расширить существующих владельцев: `scripts/data/magic-items-compendium.js` и его embedded projection для КД/магической metadata; `scripts/integrations/magic-weapon-template.js` для NPC; каноническую dnd5e integration для вычисляемых классовых бонусов; `gear-compendium.js`, существующие данные куклы и расчёт `InventoryService.getPartySnapshot()` для одежды. Общий чистый resolver допустим при необходимости разделить вычисление между native dnd5e и инвентарём.

Альтернативы: глобальные ActiveEffects проще, но ошибочно усиливают чужие классы; ручная правка world-компендиума пропадает при следующем sync. Отдельные приложения/hooks для каждого фокуса дублируют владельцев. Эти альтернативы отклонены как несовместимые с существующими контрактами.
