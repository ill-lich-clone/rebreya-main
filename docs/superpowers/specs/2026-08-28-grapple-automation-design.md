# Автоматизация захвата и перемещения схваченного

## Цель

Добавить в боевой слой Rebreya механику фиксации уже успешно выполненного захвата. Модуль не совершает проверку Захвата, не сравнивает размеры и не решает, был ли захват успешен: игрок запускает макрос после ручного разрешения проверки.

Active GM создаёт в world-каталоге Macro папку `Ребрея` и два управляемых script-макроса:

- `Захват` вызывает только `await game.rebreyaMain?.toggleGrapple?.();`;
- `Переместить схваченного` вызывает только `await game.rebreyaMain?.moveGrappled?.();`.

Вся проверка контекста, авторизация, работа с состоянием, руками, ActiveEffect, визуальным размещением и TokenDocument находится в модуле.

## Пользовательские сценарии

### Зафиксировать или отменить захват

1. Игрок контролирует ровно один токен-захватчик и выбирает ровно одну цель.
2. Первый запуск `Захват` занимает первую свободную руку в порядке `left`, `right`, затем дополнительные слоты, создаёт управляемую связь и добавляет цели нативное состояние dnd5e `grappled` (`Схваченный`).
3. Если свободных рук нет, документы не изменяются и пользователь видит сообщение `Захват невозможен: нет свободной руки.`
4. Повторный запуск на той же связи снимает состояние, удаляет оба флага связи и освобождает именно занятую этой связью руку.
5. Ручное удаление управляемого эффекта `Схваченный` выполняет ту же очистку.

Один захватчик может держать несколько разных целей, пока хватает рук. Текущая версия Rebreya управляет только одним захватчиком для одной цели. Если цель уже связана с другим захватчиком, новая связь не создаётся и пользователь видит сообщение `Цель уже схвачена. Сейчас поддерживается только один захватчик.` Неуправляемые эффекты `grappled` не удаляются и не принимаются за связь Rebreya.

### Переставить схваченное существо вокруг захватчика

1. `Переместить схваченного` автоматически выбирает единственную удерживаемую цель. Если захватчик держит несколько целей, пользователь должен отметить нужную цель; неоднозначный запуск ничего не изменяет.
2. Клиент вычисляет естественную досягаемость захватчика без оружия и открывает круглый маркер размещения через публичный `chrisPremades.Crosshairs`.
3. Диаметр маркера соответствует footprint перемещаемого токена; маркер использует его текстуру и корректный grid snap для чётных и нечётных размеров.
4. Отдельный визуальный overlay показывает допустимую область вокруг захватчика. Радиус центра маркера расширяется на половину наибольшего измерения footprint цели, чтобы большой токен можно было поставить краем в пределах естественной досягаемости, даже если его центр находится за исходной границей.
5. После grid snap позиция проверяется по ближайшему краю footprint цели, а не только по её центру. Положение допустимо, когда этот край находится в естественной досягаемости захватчика. Невалидный маркер и граница отображаются красным.
6. Отмена preview не изменяет документы. Подтверждённая позиция отправляется active GM и применяется только после повторной авторитетной проверки.

Другие токены не запрещают размещение: Foundry допускает перекрытие токенов. Позиция за границей сцены или с wall-collision запрещена. Если `chris-premades` неактивен или `chrisPremades.Crosshairs` недоступен, захват продолжает работать, а макрос перемещения сообщает, что визуальный маркер CPR недоступен.

### Перенести схваченное вместе с захватчиком

Обычное перемещение токена-захватчика автоматически переносит все удерживаемые им токены на тот же `x/y` delta:

- взаимная сторона и ось сохраняются;
- права игрока на вражеские TokenDocument не требуются;
- источник и все цели обновляются active GM одной batch-операцией с внутренним bypass-флагом;
- служебные updates не запускают защитный диалог и не рекурсируют;
- для изменения взаимного расположения игрок использует `Переместить схваченного`.

Исходный update захватчика перехватывается до записи и маршрутизируется как typed-команда. Active GM повторно разрешает все live-связи, вычисляет одинаковый delta и проверяет путь и конечный footprint каждого токена. Если хотя бы один участник выходит за сцену или не проходит из-за стены, вся batch-операция отменяется, позиции и связи сохраняются, а пользователь получает сообщение с именем заблокированного токена.

### Попытаться переместить схваченное отдельно

Любой внешний update `x/y` связанного токена цели, кроме управляемого размещения или группового переноса, перехватывается до записи. Координаты удаляются из исходного patch, поэтому токен не совершает промежуточный скачок, а другие поля update не теряются. Инициатор видит диалог `Существо было схвачено` с кнопками:

- `Отменить захват` — active GM атомарно очищает связь и повторяет исходное перемещение;
- `Отменить перемещение` — позиция и связь сохраняются.

Параллельные попытки для одной связи сериализуются; повторный диалог не открывается, пока первый не разрешён.

## Естественная досягаемость

Текущий расчёт досягаемости извлекается из private-логики `CombatAttackService` в общий чистый combat-helper. Естественная досягаемость равна:

1. `baseReachFeet` из `getCharacterSizeRule(actor.system.traits.size)`;
2. плюс неотрицательный Actor flag `flags.rebreya-main.racialReachBonusFeet`;
3. плюс максимальный активный `flags.rebreya-main.runeKnight.reachBonus` только у действующей Huge-формы `giant-might-form`.

Она не включает `system.range.reach`, свойства оружия `lchReach`, значения `reachBonus` оружия и временную досягаемость отдельной атаки. `CombatAttackService` использует тот же общий helper и отдельно прибавляет оружейную часть, сохраняя существующие результаты атак.

## Владение руками и состояние

`scripts/integrations/held-items.js` остаётся единственным владельцем доступных и занятых рук. Он получает общий контракт резервирования руки на Actor. Управляемая запись захвата содержит как минимум:

```js
{
  linkId,
  kind: "grapple",
  handSlot,
  sourceTokenUuid,
  targetTokenUuid
}
```

`getFreeHandSlots()` исключает как руки экипированных предметов, так и валидные резервы. Отсутствующий Actor/race flag рук сохраняет текущий default `2`, но явно заданное значение `hands: 0` означает отсутствие рук и не заменяется default.

Связь имеет один стабильный `linkId` в трёх местах:

1. канонический резерв руки на Actor захватчика;
2. зеркальный flag на конкретном TokenDocument цели с UUID захватчика и слотом;
3. управляемый ActiveEffect `grappled` на Actor или synthetic Actor цели.

Token-scoped flag нужен, чтобы различать несколько scene-токенов одного Actor и защищать перемещение точной цели. ActiveEffect содержит module metadata, позволяющую отличить управляемый статус от чужого.

## Архитектура и data flow

`GrappleAutomationService` в `scripts/combat/` является единственным владельцем use cases захвата, освобождения, ручного размещения, группового переноса, rollback и reconciliation. Чистые расчёты естественной досягаемости и token-footprint geometry находятся в небольших профильных helpers, а не в UI или macro code.

`scripts/combat/grapple-hooks.js` регистрирует один набор lifecycle hooks для:

- перехвата source/target `preUpdateToken`;
- очистки после удаления управляемого ActiveEffect;
- cleanup удалённого TokenDocument;
- reconciliation на `ready`/смене canvas только через сервис.

Composition root создаёт сервис, публикует `toggleGrapple()` и `moveGrappled()`, регистрирует exact typed-команды и синхронизирует управляемые world-документы только на active GM.

Минимальные privileged routes:

- `combat.grapple.toggle` — создать или снять связь после проверки ownership захватчика;
- `combat.grapple.place` — переместить точную удерживаемую цель в выбранную позицию;
- `combat.grapple.drag` — атомарно перенести захватчика и все его live-цели на общий delta;
- `combat.grapple.release-and-move` — разрешить внешний move цели после очистки связи.

Каждый payload имеет exact schema, стабильный operation ID и UUID конкретных scene-токенов. Active GM заново разрешает документы и не доверяет клиентским Actor IDs, руке, досягаемости, списку целей или вычисленным координатам. Player-команды разрешены владельцу source Actor; `release-and-move` разрешён GM либо пользователю, который имел право перемещать exact target TokenDocument. Неизвестный sender, неактивная сцена, stale link, сменившийся владелец, несовпадающий operation fingerprint и повторная операция с другими данными отвергаются без локальной записи игроком.

## Атомарность, rollback и восстановление

Операции одной связи и одного захватчика сериализуются через существующий mutation coordinator/operation-id pattern. Создание связи фиксируется только после успешного создания всех управляемых частей. При ошибке последующего шага сервис best-effort восстанавливает предыдущие flags, hand reservations, ActiveEffect и позиции; неполный rollback возвращает `AggregateError` и оставляет данные для reconciliation.

Active GM reconciliation удаляет только управляемые осиротевшие части:

- резерв без target flag/effect;
- target flag без source reservation;
- управляемый effect без совпадающей token-связи;
- связь с удалённым source или target token.

Reconciliation не создаёт захват из одного остаточного документа, не трогает неуправляемый `grappled` и не выбирает нового захватчика. Удаление токена или управляемого эффекта освобождает связанную руку идемпотентно.

## Синхронизация папки и макросов

Active GM на `ready` ищет папку Macro и оба макроса по стабильным `flags.rebreya-main.sourceId`. Отсутствующие документы создаются, управляемые name/type/scope/command/folder/ownership обновляются только при отличии. Одноимённые пользовательские макросы не перезаписываются и не удаляются. Если управляемой папки нет, сервис переиспользует самую старую по `_stats.createdTime` world-папку exact типа `Macro` и exact имени `Ребрея`; при одинаковом или отсутствующем времени выбирается наименьший строковый ID. Если совпадений нет, создаётся управляемая папка. Другие document types с тем же именем не считаются совпадением.

## Ошибки и уведомления

До любого mutation пользователь получает короткое русское сообщение при неправильном числе контролируемых токенов/целей, отсутствии связи, отсутствии свободной руки, неподдерживаемом втором захватчике, stale token, смене сцены, недоступном CPR marker и невалидной позиции. Отмена crosshair или диалога не показывает success и не меняет state.

## Проверка

Focused-тесты должны покрыть:

- естественную досягаемость всех размеров, racial flag и активную/неактивную Rune Knight form без оружейных бонусов;
- сохранение прежней итоговой weapon reach в `CombatAttackService`;
- default рук, явный `hands: 0`, предметы, резервы и несколько дополнительных рук;
- создание связи, автоматический слот, toggle-release, ручное удаление эффекта и cleanup токена;
- несколько целей одного захватчика и отказ перезаписать цель второго захватчика;
- точную geometry для 1×1, 2×2, больших и rectangular/fractional footprint после grid snap;
- CPR Crosshairs config, отображение области, cancel и отсутствие прямого вызова `Teleport.target`;
- одинаковый delta группового переноса, несколько целей, batch bypass, сохранение оси и атомарный отказ при стене/границе;
- обе кнопки внешнего перемещения, сохранение non-position patch и подавление повторного диалога;
- exact socket schemas, sender authorization, stale/fingerprint отказ, direct active-GM и inactive-client routes;
- rollback каждого промежуточного шага и идемпотентный reconciliation;
- создание, повторную синхронизацию и collision policy папки/макросов;
- composition root, публичный API и единственную регистрацию hooks.

Перед commit реализации обязательны focused-тесты владельцев, полный `node --test tests/*.test.mjs`, `git diff --check`, `node --check` всех tracked JS/MJS и UTF-8 JSON parse всех tracked JSON. Все новые и изменённые методы, сигнатуры, data flow, ограничения и профильные тесты записываются в раздел 16 `docs/function-passport.md`; пользовательский macro API добавляется в профильный раздел `README.md`.

## Вне границ задачи

- автоматизация проверки Захвата, спасбросков, размера допустимой цели или преимущества;
- автоматическое ограничение скорости/стоимости движения при перетаскивании;
- несколько одновременных захватчиков одной цели;
- использование weapon reach для захвата или размещения;
- анимации телепортации и прямой вызов CPR `Teleport.target`;
- принудительное устранение перекрытия с другими токенами.
