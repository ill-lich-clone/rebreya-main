# Дополнение автоматизации механических имплантов — проект

## Цель

Дополнить уже существующие `implant-automation-registry`, `ImplantService`,
`ImplantAutomationService`, общий Active Effect `Импланты` и действующие сервисы
Foundry/D&D5e. Новая архитектура, отдельные Active Effects, служебные предметы и
миграция мира не создаются.

## Объём

### Конденсатор магии

- `spentPoints` установленного импланта задаёт уровень дополнительной ячейки от
  1 до 5.
- Если этот уровень выше максимального доступного актёру уровня обычных ячеек,
  используется максимальный доступный уровень.
- Максимум выбранного уровня увеличивается на один.
- При установке после продолжительного отдыха дополнительная ячейка доступна
  сразу.
- При снятии импланта или снижении уровня текущее количество ячеек
  ограничивается новым максимумом.
- Если у актёра нет обычных ячеек заклинаний, бонус не применяется.

### Телепатический модуль

- В вычисляемое поле пользовательских языков добавляется
  `Телепатия (60 фт.)`.
- Существующие стандартные и пользовательские языки не изменяются.
- Сообщения, выбор цели и проверка дистанции не автоматизируются.

### Механизм перезарядки оружия

- Настоящий Foundry Item импланта типа `loot` получает в своём нативном листе
  действие `Загрузить механизм`. Тип Item не меняется: модель D&D5e `LootData`
  не поддерживает `system.activities`.
- Действие доступно только владельцу установленного и эффективного импланта.
- Диалог выбирает один стек боеприпасов и количество; во внутреннем боезапасе
  одновременно хранится один тип и не более 20 единиц.
- Загрузка списывает выбранное количество из Item боеприпасов актёра.
- Если в механизме уже лежит другой тип, загрузка блокируется до опустошения
  механизма; разные типы не смешиваются.
- Обычная activity `Перезарядить` совместимого оружия сначала расходует
  внутренний боезапас. Недостающее количество затем может добираться текущим
  штатным путём из инвентаря.
- Расход из механизма не требует свободной руки. Существующее поведение
  перезарядки для персонажей без импланта не ужесточается в этой задаче.
- Состояние хранится одним актёрским флагом с идентификатором/названием
  боеприпаса и количеством. Отдельный Item для боезапаса не создаётся.

### Ракетная тяга

- Вычисляемая скорость полёта равна максимуму из текущей скорости полёта и
  скорости ходьбы.
- Расход минут полёта, снижение и восстановление ресурса пока не
  автоматизируются.

### Модуль восстановления

- В начале собственного хода в активном бою актёр восстанавливает 1 хит, если
  его текущие хиты не меньше 2 и ниже максимума.
- Один ключ `combat/round/turn/actor` не может вылечить актёра повторно.
- Изменение выполняет единственный ответственный клиент.
- Вне боя лечение не выполняется.

### Рука бога

- Существующая база обычного крафта 5 зм/день увеличивается на 5 зм/день.
- Предпросмотр проекта и фактическая обработка рабочего дня используют один
  и тот же resolver и получают базу 10 зм/день.
- Бонус 10 зм/день для конструктов остаётся в capability, но не подключается к
  ручной downtime-активности до появления отдельного сервиса крафта
  конструктов.

## Явно не автоматизируется

- `Модуль чувства жизни`;
- `Великое хранилище энергии`;
- `Хранилище невероятной проницательности`;
- `Контейнер для фамильяра`.

Их существующие capability можно хранить как данные, но обработчики в рамках
этой задачи не добавляются.

## Архитектурные ограничения

- Источником истины об установленном импланте остаётся скомпилированная
  capability общего эффекта `Импланты`.
- Пассивные производные значения дополняются существующим патчем
  `prepareDerivedData`.
- Начало хода дополняется в существующем `handleCombatTurnChange`.
- Перезарядка дополняется в существующем `CombatAttackService`.
- Крафт дополняется через уже предусмотренный `resolveCraftProgressBase`.
- Все операции с ресурсами ограничивают значения диапазонами и остаются
  идемпотентными при повторном Foundry hook.
- Автоматическая проверка требований установки остаётся за пределами задачи.

## Проверка

- Каждый новый сценарий сначала фиксируется падающим `node:test`.
- Отдельно проверяются установка/снятие, повторный хук хода, несовместимые
  боеприпасы и одинаковая скорость крафта в preview/process.
- Итоговая проверка: `git diff --check` и полный `node --test tests/*.test.mjs`.
