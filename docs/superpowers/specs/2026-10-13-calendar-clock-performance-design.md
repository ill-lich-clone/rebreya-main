# Быстрое чтение часов и календаря

Дата: 2026-10-13. Статус: подтверждено пользователем; подготовка плана реализации.

## Наблюдаемый результат

Изменение минут через SmallTime и даты через календарь требует существенно меньше работы в клиенте. Чтение часов не копирует журналы переходов, downtime и состояние других групп. Переход дня выполняет прежние игровые стадии, проверки полномочий и durable checkpoints, но не материализует полное состояние для проверки существования группы.

Пользователь поручил облегчить чтение часов и убрать повторную обработку состояния, сохранив журналы восстановления и игровые правила. Настоящая задача ограничена существующими сервисами; новую схему хранения и миграцию данных не вводит.

## Подтверждённая причина и исходные замеры

На диагностической копии мира `groupState` содержит четыре группы и занимает 1 553 667 байт. Около 1 033 319 байт приходится на calendar, главным образом `transitionJournal`; 495 500 байт — на downtime.

Изолированный Node-замер с установленной функцией `deepClone` Foundry 13.351 дал:

| Сценарий | Медиана | Работа |
| --- | ---: | --- |
| `CalendarService.getSnapshot()` | 18,59 мс | 2 чтения реестра, 150 вызовов `deepClone` |
| Rebreya-обработчик изменения минут с имитацией чтений солнца/даты | 73,01 мс | 7 чтений, сохранение всего `groupState` |
| Один день без downtime, daily cycles, UI и сети | 576,8 мс | 61 чтение, 11 сохранений, 17 107 970 сериализованных байт |

Эти значения описывают копию данных и mock persistence, а не полный профиль работающего браузера. Существующие world settings сериализуют целый объект при записи; этот транспортный расход остаётся ограничением данной задачи.

## Выбранное решение

1. **Repository:** добавить узкое чтение индекса групп и трёх полей часов (`version`, `isoDate`, `timeOfDaySeconds`) одной группы. Возвращать detached projection, не обходить доменные данные или `calendar.transitionJournal`. Существующий полный `read()` сохраняет свой контракт.
2. **Group context:** добавить явное разрешение ссылки на текущую/указанную группу без `groupState`, используя канонические правила выбора и membership. Полные `resolveForCurrentUser()` и `resolveForGroup()` сохраняют форму результата, свежесть и detached normalized state. Календарный контекст использует ссылку и узкую repository projection.
3. **Calendar:** `#getStateScope()` использует узкий контекст. `#assertExecutionContext()` координатора проверяет прежние identity/active-GM/group условия через ссылку, сохраняя все места вызова guard. Calendar patch обновляет поля уже detached черновика без дополнительного полного клонирования журнала.
4. **Mutation:** `mutateGroupState()` переиспользует уже нормализованный черновик `mutateRegistry()`. Убрать повторные нормализации выбранной группы непосредственно до/после mutator; final registry normalization, fresh queued read, detach boundaries и guard-before/after-write сохраняются. Создаваемая группа получает прежние defaults.
5. **SmallTime:** не отправлять повторное сохранение неизменившейся строки `current-date`; при `syncSmallTimeToCalendarTime()` один раз рассчитывать солнце, сохраняя порядок обновления часов/даты. Отдельные события времени и их доменные последствия не объединять и не пропускать.

Долгоживущий кэш требует дополнительных правил инвалидирования. Отдельное хранилище времени требует миграции persisted contracts. Для текущей задачи выбран узкий свежий read без этих дополнительных механизмов.

## Сохраняемые контракты

- Весь `groupState`, неизвестные сохранённые поля календаря, `transitionJournal` и downtime history остаются сохранены; миграция и сокращение истории не выполняются.
- `getCalendarSnapshot()` возвращает прежнюю форму: дату, время, названия, cells и moon. World fallback и нормализация некорректных дат/секунд сохраняются.
- Текущая группа GM выбирается из registry; player — только из зарегистрированных managed-групп по прежнему owned-character membership. Явный group ID и захваченная группа перехода не подменяются текущим выбором GM.
- Отсутствующий Actor и Actor неверного типа дают прежние ошибки. Ссылка на явно указанную существующую Group Actor сохраняет прежний fallback для отсутствующего календарного состояния; новые требования регистрации не добавляются.
- Все active-GM/user identity guards, typed commands, sender authorization, очереди и проверки до/после записи сохраняются.
- Порядок стадий перехода, durable claims/checkpoints/precommit, retry, resume, failover, идемпотентность и reconciliation сохраняются; количество durable checkpoint writes не сокращается.
- Каждый сдвиг времени, переход через полночь и каждое пересечённое число обрабатываются. Forward сохраняет исходные опции downtime/припасов и подтверждение их списания. Backward не запускает downtime, припасы или monthly reset. Suppression собственного clock sync сохраняется.
- Нормы количества, authored formulas, energy, budgets, crafting, trader resets и global events не изменяются. Автоматизации лечения, проклятий, гаджетов, сцен и освещения остаются вне правки.
- Public API и существующие settings/flags/socket schemas сохраняются. Новые внутренние методы документируются в паспорте функций.

## Преднамеренные изменения поведения

- Clock/reference reads больше не нормализуют и не копируют архивы и другие домены групп.
- Неизменившаяся дата SmallTime не вызывает повторный `settings.set`; отображение обновляется как прежде.
- Clock sync выполняет один расчёт солнца вместо двух.
- Нормализация мутации выполняется на canonical входной и выходной границах без промежуточных повторов.

## Регрессионные проверки до реализации

- Использовать throws-on-access архивы/данные посторонней группы: clock и reference guards должны работать, не обращаясь к ним. Проверять structural counts вместо нестабильных временных порогов.
- Узкие результаты detached; повторное чтение видит изменение setting и смену активной группы без reload. Полные context/read результаты сохраняют прежний контракт.
- Проверить GM/player selection, explicit group, trimmed legacy IDs, world fallback и прежние ошибки отсутствующей/неверной группы.
- Проверить unchanged journal/custom calendar fields, failed-mutation isolation, queued fresh reads, latest concurrent date/time patches, create defaults и оба authority guards.
- Сохранить и расширить forward/backward/midnight, prompts/options, self-sync suppression и отсутствие потери последовательных time events.
- Существующие переходы должны проходить проверки captured group, failover, terminal lost acknowledgement, retry/resume и запрета повторных callback.

## Проверка и выпуск

Сравнить прежние и новые изолированные замеры на одной копии данных, явно отделив mock persistence от браузера. Критерий механизма: clock/reference reads не обходят архивы; число нормализаций мутации и расчётов солнца уменьшается при неизменных результатах и recovery stages.

Перед runtime commit выполнить `node --test tests/*.test.mjs`, `node --check` tracked JS/MJS, JSON parse и `git diff --check`. Повысить `module.json` до следующей свободной patch-версии, синхронизировать versioned forwarder и runtime imports затронутых файлов. Изменения делать и пушить только в `lich_branch` без force push.

Live-проверка зависит от доступного авторизованного сеанса Foundry. Если он недоступен, явно сообщить это ограничение, не заявлять подтверждённую браузерную задержку или совместимость за пределами проверенной среды.
