# Публичное окно города — спецификация дизайна

## Наблюдаемый результат

Игрок может открыть любой город из общего окна экономики и из вкладки путешествия. Город открывается в существующем `CityEconomyApp`, но для игрока отображается как атмосферная публичная витрина: панорама, описание, конечные городские цены материалов и доступ к торговцам. GM сохраняет нынешнее аналитическое окно и может переключиться на тот же публичный вид.

Общее окно экономики доступно игрокам в сокращённом режиме. Оно показывает города, базовые цены материалов и мировой дефицит, но не раскрывает городские коэффициенты, причины изменения цен и служебные экономические показатели.

## Подтверждённые продуктовые решения

- Любой игрок может просматривать любой город; местоположение группы не ограничивает просмотр.
- В путешествии открываются как исходный, так и целевой город маршрута.
- Торговцы доступны из любого просматриваемого города; удалённая покупка разрешена и не проверяет местоположение группы.
- Публичное окно города показывает конечную фактическую цену материала в этом городе.
- Публичное окно не показывает проценты, стрелки, сравнение с базой, коэффициенты и причины изменения цены.
- Общее окно экономики показывает базовую цену материала и мировой дефицит по материалам.
- Базовые описание и изображение принадлежат source JSON; GM может переопределить их в world-state без изменения source-файлов.
- Выбран визуальный вариант A: крупная кинематографическая панорама и вкладки `Город`, `Рынок`, `Торговцы`.

## Архитектурный подход

Существующие `EconomyApp`, `CityEconomyApp` и `openCityApp(cityId)` остаются каноническими. Второй City app, новый Trader app или параллельный маршрут открытия не создаются.

Оба окна получают role-aware context:

- GM-контекст сохраняет существующую аналитику и административные действия;
- player-контекст формируется отдельными чистыми projection-функциями и содержит только публичные поля;
- публичный шаблон не получает механические поля, которые ему запрещено показывать.

UI не рассчитывает цены и не пишет world settings напрямую. Расчёт публичной цены переиспользует канонические правила материалов из `scripts/engine/trader-engine.js`; чтение и запись overrides проходит через repository и composition root.

## Владельцы поведения

- Source и runtime-модель городов: `data/cities.json`, `scripts/data/repository.js` (`EconomyRepository`).
- Экономические snapshots и мировой дефицит: `scripts/engine/economy-engine.js`.
- Расчёт цены материала: `getMaterialPriceModifier()` и `applyMarketPrice()` в `scripts/engine/trader-engine.js`.
- Public projections: новый небольшой модуль рядом с `scripts/ui/city-app.js` либо в `scripts/engine/selectors.js`; точное место закрепляет implementation plan после проверки текущих импортов.
- Окна и DOM binding: `scripts/ui/economy-app.js`, `scripts/ui/city-app.js`.
- Markup: `templates/economy-app.hbs`, `templates/city-app.hbs`.
- Путешествие: `scripts/ui/inventory-app.js`, `templates/inventory-app.hbs`. Обработчик `travel-open-city` и ссылки на обе стороны legs уже существуют; изменение должно сохранить и покрыть их роль в новом player flow.
- Открытие окон, публичные API-методы и scoped refresh: `scripts/main.js`.
- Стили: существующий канонический stylesheet модуля.
- Trader UI: только `scripts/ui/trader-app-v2.js`; город делегирует существующему `openTrader()`.

## Данные города и overrides

### Базовые данные

Каждая запись `data/cities.json` сохраняет существующее поле:

```json
{
  "description": "Базовое описание города"
}
```

и получает поле:

```json
{
  "image": "assets/Карты/Карты городов/Пейзажи 2x1/Название города.webp"
}
```

В каталоге присутствуют 300 панорам для 300 городов; имена всех файлов точно совпадают с `city.name`. Все пути записываются явно в JSON, чтобы source data оставались самодостаточными и проверяемыми.

### World override

Новая setting `cityPresentationOverrides` хранит только отличия от source JSON:

```js
{
  [cityId]: {
    description: "Переопределённое описание",
    image: "worlds/.../custom-city.webp"
  }
}
```

Правила нормализации:

- неизвестные `cityId` не применяются;
- `description` приводится к строке и ограничивается разумной длиной формы;
- `image` принимается только как непустой Foundry asset path;
- отсутствующее поле означает использование source value;
- сброс удаляет override соответствующего поля, а пустая строка не уничтожает базовое значение;
- detached snapshots не возвращают ссылку на объект setting.

`EconomyRepository` владеет чтением, нормализацией и записью setting. Публичный composition-метод изменения presentation проверяет `game.user.isGM`; player-вызов завершается без мутации. После успешной записи перерисовывается только открытое окно изменённого города без кражи focus.

## Публичная projection города

Projection принимает каноническую модель, snapshot города, presentation override и summaries торговцев. Она возвращает только данные, необходимые публичному шаблону:

```js
{
  id,
  name,
  state,
  regionName,
  cityType,
  description,
  image,
  materialRows: [{
    materialId,
    name,
    finalPriceGold,
    finalWeight
  }],
  traders: [{
    traderKey,
    name,
    image,
    description,
    availabilityLabel
  }]
}
```

`materialRows` строятся из `model.materials`. Для каждого материала используются его `linkedGoodId`, соответствующий `city.goodsRows` и канонические `getMaterialPriceModifier()`/`applyMarketPrice()`. Публичная цена обязана совпадать с ценой материала, применяемой Trader Engine для этого города. Если минимальная цена приводит к изменению продаваемого веса, UI показывает фактическую пару `finalPriceGold` за `finalWeight`; само служебное состояние корректировки в public projection не входит.

В публичный context не входят `production`, `demand`, `balance`, `surplus`, `deficit`, `priceModifierPercent`, event modifiers, import routes, self-sufficiency и промежуточные множители. Это ограничение проверяется тестом по ключам projection, а не только отсутствием текста в шаблоне.

## Публичная projection экономики

Player-режим `EconomyApp` содержит:

- доступный поиску список всех городов с названием, государством, регионом, типом и публичной панорамой;
- переход каждого города через существующий `openCityApp(cityId)`;
- строки материалов с `material.id`, `material.name`, базовыми `priceGold` и `weight` из `data/materials.json`;
- мировой дефицит связанного товара из канонического world overview: `max(0, totalDemand - totalProduction)` по `linkedGoodId`.

Игроку не передаются городские цены, производство и спрос отдельных городов, balances, route analytics, state policies, global-event mechanics, audit и административные действия. GM-режим общего окна остаётся функционально совместимым с текущим.

## Интерфейс публичного города

### Шапка

- Крупная панорама занимает верхнюю часть окна и визуально продолжает стиль партийного инвентаря.
- На затемнённой части панорамы располагаются тип/регион, название и описание города.
- Если изображение отсутствует или не загружается, используется нейтральная тематическая заглушка; остальные вкладки продолжают работать.
- GM видит компактные действия изменения описания и изображения, а также сброса к базовым значениям.

### Вкладка `Город`

Показывает публичное описание и немеханическую географическую информацию. Население, производство, спрос, самообеспеченность и экономический баланс в player-режиме не показываются.

### Вкладка `Рынок`

Показывает список/сетку материалов с поиском или группировкой по существующим категориям при необходимости. Каждая строка содержит название и одну фактическую цену (либо фактическую цену за скорректированный продаваемый вес). Не отображаются базовая цена, разница, цветовая оценка, процент, стрелка или tooltip с формулой.

### Вкладка `Торговцы`

Показывает summaries торговцев города. Действие `Открыть лавку` вызывает существующий `openTrader(cityId, traderKey)` и не реализует торговлю внутри City app. Доступность покупки не зависит от travel state.

### GM-переключение

GM по умолчанию сохраняет текущий аналитический режим `CityEconomyApp`. Явное действие `Публичный вид` переключает ту же app instance на публичный context/template branch; обратное действие возвращает аналитику. Player всегда фиксирован в публичном режиме и не получает GM controls.

## Точки входа

- `openCityApp(cityId)` остаётся единственной публичной точкой открытия города.
- Карточки городов в player-режиме `EconomyApp` используют `openCityApp(cityId)`.
- Существующие `data-action="travel-open-city"` для source и target в travel legs сохраняются и используют `openCityApp(cityId)`.
- Если travel summary показывает исходный и целевой города вне списка legs, они также должны быть кликабельными через тот же action; implementation plan должен сверить фактический context и не дублировать обработчик.
- `openTrader()`, `openTraderV2()` и `openTraderSheet()` продолжают делегировать единственному Trader V2.

## Ошибки и отказоустойчивость

- Неизвестный `cityId` показывает существующее безопасное состояние «город не найден» без исключения из render loop.
- Ошибка получения traders не блокирует вкладки `Город` и `Рынок`; вкладка торговцев показывает локальное сообщение об ошибке.
- Ошибка сохранения override оставляет форму открытой, сообщает GM о причине и не заменяет локально authoritative значение.
- Повреждённая setting нормализуется без мутации source model.
- Background refresh не поднимает свёрнутое окно и не крадёт focus.
- Игрок не может вызвать mutation presentation через UI или публичный composition method.

## Проверки

Focused-покрытие должно включать:

1. Public city projection содержит итоговые цены из канонических функций Trader Engine и не содержит запрещённых механических полей.
2. Цена и продаваемый вес совпадают с material pricing Trader Engine, включая minimum-price weight adjustment.
3. Public economy projection содержит базовую цену и мировой дефицит, но не содержит city mechanics и GM actions.
4. Player `CityEconomyApp` всегда выбирает публичный режим; GM может переключаться между аналитическим и публичным режимами.
5. GM update/reset description и image проходят через repository, player mutation отклоняется, source JSON не меняется.
6. Missing image, missing city и failure загрузки traders дают предусмотренные состояния.
7. Экономика открывает любой город через `openCityApp(cityId)`.
8. Путешествие открывает исходный и целевой города через уже существующий `travel-open-city` handler.
9. Торговец открывается через существующий `openTrader(cityId, traderKey)` без нового Trader app и без travel authorization.
10. Composition root экспортирует изменённые публичные методы, учитывает City app в scoped refresh и не создаёт второй app cache.
11. Все 300 записей `cities.json` имеют валидный image path, совпадающий с существующей панорамой.
12. GM-аналитика города и экономики сохраняет текущие вкладки и действия.

Перед завершением реализации обязательны focused-тесты владельцев, `node --test tests/*.test.mjs`, `git diff --check`, `node --check` всех tracked `*.js`/`*.mjs` и UTF-8 JSON parsing всех tracked `*.json`.

## Документация и публичный контракт

При реализации обновляются:

- соответствующие разделы `README.md`: player/GM режимы Economy/City, public API и правила фактической цены;
- разделы 3, 5 и 19 `docs/function-passport.md` для новых или изменённых методов, signatures, data flow, ограничений и focused-тестов;
- описание новой setting и её владельца.

## Вне scope

- Изменение экономических формул, route pricing, events или state policies.
- Ограничение просмотра или покупки текущим местоположением группы.
- Новый Trader UI, второй City app или новый composition root.
- Изменение typed commands и транзакционных гарантий покупки/продажи.
- Редактор производства, спроса, связей или механических параметров в публичном режиме.
- Автоматическая генерация новых художественных изображений.

## Критерии готовности

- Игрок открывает любой город из экономики и обе стороны маршрута из путешествия.
- Публичный город соответствует выбранному кинематографическому макету и работает при отсутствии необязательных данных.
- Рынок показывает фактические городские цены без механической расшифровки.
- Экономика показывает базовые цены и мировой дефицит без закрытых механических данных.
- Любая городская лавка открывается и использует существующий транзакционный workflow.
- GM сохраняет текущую аналитику и может редактировать/сбрасывать presentation overrides.
- Все 300 панорам сопоставлены городам.
- Focused и полные проверки проходят без ошибок.
