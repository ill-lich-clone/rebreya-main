# Набор бытовых фэнтезийных хранилищ

## Наблюдаемый результат

В модуле появляется согласованный набор из 22 токенов бытовых хранилищ для карт Foundry VTT. Низкие ёмкости получают три визуально естественных состояния, высокая мебель — по одному узнаваемому состоянию. Набор продолжает стиль существующих токенов сундука, но не заменяет их.

## Границы задачи

- Добавить только растровые ассеты в `assets/storage/furniture/`.
- Не менять встроенные пресеты, JavaScript, шаблоны, стили, `README.md` или публичный API.
- Не заменять и не редактировать файлы из `assets/storage/chests/`.
- Промежуточные chroma-key изображения не коммитить.

## Состав набора

### Хранилища с тремя состояниями

Каждая группа использует одинаковые силуэт, масштаб, материал и положение объекта во всех состояниях. Суффиксы совместимы с семантикой `unopened`, `opened`, `empty`, даже если предмет закрывается крышкой, тканью или завязкой.

|---|---|---|---|---|
| Бочка | `barrel-closed.webp` | `barrel-open.webp` | `barrel-empty.webp` | зерно |
| Дощатый ящик | `wooden-crate-closed.webp` | `wooden-crate-open.webp` | `wooden-crate-empty.webp` | смешанные бытовые припасы |
| Плетёная корзина | `wicker-basket-closed.webp` | `wicker-basket-open.webp` | `wicker-basket-empty.webp` | сложенное полотно |

| Керамический сосуд | `ceramic-storage-jar-closed.webp` | `ceramic-storage-jar-open.webp` | `ceramic-storage-jar-empty.webp` | сушёные бобы |

### Одиночные токены мебели

- `wardrobe.webp` — платяной шкаф.
- `kitchen-hutch.webp` — кухонный буфет.
- `dresser.webp` — комод с ящиками.
- `bedside-cabinet.webp` — прикроватная тумба.

## Визуальная система

- Тёмное бытовое фэнтези без магических эффектов, гербов и дорогого дворцового декора.
- Состаренные дерево, кованое железо, грубая ткань, лоза и матовая керамика.
- Тёплые коричневые и охристые тона, умеренный контраст, тонкая тёмная обводка деталей.
- Низкие ёмкости показаны строго сверху. Высокая мебель использует небольшой верхний наклон, достаточный для чтения дверец и ящиков, но не полноценную изометрию.
- Один объект по центру кадра, без пола, стен, подписей, рамок, персонажей, теней за пределами объекта и водяных знаков.
- Между состояниями не меняются перспектива, габариты, фурнитура и положение предмета.
- Существующие `wood-dark-closed.webp`, `wood-dark-gold-open.webp` и `wood-dark-empty.webp` используются только как стилистические референсы.

## Формат и технические требования

- Финальный формат: WebP, 512×512 пикселей, sRGB, с альфа-каналом.
- Объект занимает примерно 70–82% полезной площади и имеет равномерный безопасный отступ.
- Прозрачные углы обязательны; заметная цветная кайма после удаления chroma key недопустима.
- Все варианты одной группы должны совпадать по видимому масштабу с отклонением не более нескольких пикселей.
- Имена файлов — строго как в разделе «Состав набора».

## Производственный процесс

1. Использовать встроенный ImageGen; существующие сундуки передавать как стилевые референсы, а не как цели редактирования.
2. Генерировать каждый из 22 ассетов отдельным запросом. Для состояний одного предмета повторять неизменяемые признаки и использовать предыдущий удачный вариант как дополнительный референс, если это требуется для согласованности.
3. Просить однородный chroma-key фон `#00ff00`, не используемый в самом объекте.
4. Удалять фон штатным helper-скриптом навыка imagegen с soft matte и despill; при необходимости один раз применять edge contraction.
5. Приводить результат к 512×512 WebP без растяжения и сохранять в `assets/storage/furniture/`.
6. Проверять каждый файл визуально и технически; неудачный ассет перегенерировать, не исправляя его рисованием вручную.

## Проверка и критерии готовности

- В каталоге присутствуют ровно 22 ожидаемых файла, каждый ненулевого размера.
- ImageMagick определяет каждый файл как 512×512 WebP с альфа-каналом.
- У каждого файла прозрачны четыре угла, объект не обрезан и не содержит chroma-key каймы.
- Пять трёхсоставных групп визуально сохраняют один предмет между состояниями.
- На контактном листе все объекты читаются как единый набор и различимы в размере игрового токена.
- `git diff --check` проходит; полный набор проектных тестов не требуется, поскольку код и данные поведения не меняются.
