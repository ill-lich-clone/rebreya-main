# Выбор шаблона после закупки

Когда игрок подтверждает закупку в Rebreya Gen, обработчик результата запускает выбор базового шаблона у покупателя после успешной транзакции. Создание Item в рамках такой закупки не открывает окно у активного ГМа. Обычное создание предметов, собственные закупки ГМа и независимая проверка при открытии листа сохраняют существующее поведение.

Rebreya Gen вызывает существующий `purchaseItemBasket`. Активный ГМ проверяет права покупателя, создаёт Item и списывает валюту как прежде. Для закупки, инициированной другим пользователем, создание передаёт существующий флаг пропуска выбора шаблона. После подтверждения закупки клиент покупателя направляет Item из `createdItemUuids` в существующий обработчик выбора шаблонов, проверив, что Item всё ещё принадлежит целевому персонажу и доступен покупателю для изменения. Диалог и его ошибки не задерживают ответ о закупке. Для нескольких предметов диалоги идут по одному. При компенсации или неподтверждённой покупке этот путь не открывает диалог.

Рассмотрели передачу ID покупателя в `createItem`, но она открывала бы диалог до подтверждения списания валюты. Обработка результата на клиенте покупателя использует имеющуюся квитанцию и не требует новой socket-команды или правок Rebreya Gen.

Сохраняются валидация, цены, количество, списание валюты, резерв Rebreya Gen, компенсация, журнал, повтор по `transactionId`, правила подбора и применения шаблонов, а также отмена диалога без записи в Item. При повторе успешно подтверждённой закупки уже обработанный Item отсекается существующими template flags, а открытый диалог защищён текущей блокировкой на Item. Восстановление шаблонов при открытии листа остаётся доступно игроку.

Регрессия должна проверить оба клиента при подключённом владельце: GM выполняет создание без диалога, а покупатель получает выбор после подтверждения и применяет шаблон к купленному Item. Отдельно проверить отсутствие выбора при компенсации и прежнее поведение собственной закупки ГМа.
