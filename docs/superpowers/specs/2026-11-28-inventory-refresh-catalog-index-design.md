# Ускорение обновления партийного склада

После удаления предмета и полной или частичной продажи окно склада и вынесенные папки показывают актуальные остатки и монеты. Стоимость подготовки каждого окна больше не включает полный перебор каталогов для каждой позиции в списке и в сводке.

В `InventoryService` индексировать нормализованные имена по экземпляру массива каталога. Основной список, сводка группы и вынесенные папки используют один индекс каждого каталога. Индекс строится при первом поиске по имени. Репозиторий переиспользует массивы одного загруженного набора данных и подставляет новые при загрузке нового набора. Индексы прежних массивов освобождаются вместе с ними.

Поиск сохраняет приоритет ID и связанного товара. Сопоставление по имени допускает только одно точное совпадение после существующей нормализации, независимо для материалов и снаряжения. Ручные позиции обходят поиск по имени. Сохраняются цены, количество, разрешения, списание, выдача монет и журнал старого склада. Вызовы обновления и их объединение остаются прежними.

Рассматривали переиспользование готовых снимков между окнами. Для него пришлось бы определить срок жизни снимков для разных групп и обеспечить актуальность множества вкладок. Индекс устраняет выявленный перебор в одном месте и сохраняет независимое чтение документов каждым окном.

Сравнение выполняется одним и тем же сценарием Foundry QA на складе из 500 позиций. Сверяются проведённые записи, остатки, монеты, число чтений каталога и медиана времени подготовки контекстов. Время отрисовки Foundry находится за пределами этого прогона.
