# Производительность и диагностика переключения куклы

Пользователь сообщает медленный Apply и компенсированный откат; проверял один комплект с несколькими отличающимися предметами. Конкретная runtime причина отката пока неизвестна: прежний workflow теряет исходную ошибку после успешной компенсации. Не утверждать, что она устранена без повторного пользовательского воспроизведения.

Наблюдаемый результат: неизменённые поля по-прежнему не записываются; изменённые Item не вызывают промежуточных native sheet renders, а состояние doll slots и presets записывается одним Actor.update. Actor lookup выполняется один раз на write/verify проход, а не на каждый touched field. Финальная штатная Actor перерисовка и UI render сохраняются; hooks и broadcast не отключаются. При откате сохраняются первоначальные code/message в durable record и причина добавляется к уведомлению. При verify mismatch причина указывает document UUID и имена расходящихся полей.

Контракты сохраняются: GM/OWNER/active-GM guards, locks, journal/idempotence, world Actor UUID, explicit preset save, ghosts, совместимость, количество, нормализация legacy stacks, authored formulas/quantity rules/budgets, heldHands, post-write verification и compensation/CAS. Unchanged placements всё ещё проверяются: нельзя ускорять Apply удалением проверок. Batch обновления нескольких Items не вводятся, чтобы не расширять транзакционный контракт. Rollback сохраняет прежние render options и безопасные проверки.

Владельцы: HeroDollService prepare final actor placement; ItemInstanceDocuments read/write/verify; ItemInstanceWorkflow batch compensation diagnostics. Tests до runtime edits: lookup count, one Actor write for doll+presets, render:false только для preset Item writes, durable/public original failure and field-specific verify cause. Runtime release1.4.368; изменённые workflow/driver импортируются по единому ESM query всеми прежними consumers, service cache обновляется отдельно. Live world проверку выполняет пользователь.
