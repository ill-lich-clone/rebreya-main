# Перевязка конструктов, целей с 0 HP и отсутствие комплекта — проект

## Наблюдаемый результат
Макрос «Перевязка ран» может лечить конструктов и существ с 0 HP. Автоматический маркер `dead`, который Rebreya ставит при нуле HP, не должен сам по себе мешать такой перевязке; при трёх проваленных спасбросках от смерти персонаж остаётся недопустимой целью, поскольку перевязка не воскрешает. Существо с положительными HP и вручную поставленным `dead` по-прежнему недопустимо. Существующий запрет для нежити сохраняется.

В диалоге появляется галочка «Игнорировать отсутствие комплекта целителя», по умолчанию выключенная. Если она включена и подходящего доступного комплекта нет, процедуру можно провести без него и без списания. Если подходящий комплект есть, используется выбранный комплект и он расходуется как раньше. Если галочка выключена, при отсутствии комплекта продолжить нельзя.

## Границы и контракты
Сохраняются владение Медициной, выбор ступени/Сл, броски и их исходы, иммунитет на час, публикация всех исходов, продолжение лечения и порядок записи HP. При успешном лечении с 0 HP сохраняется существующее правило сброса только проваленных спасбросков от смерти; native сброс успехов компенсируется как прежде. Игроки продолжают направлять запрос через авторизованную typed GM-команду; GM повторно проверяет выбор и доступность комплектов. Запись флага игнорирования включается в исходный intent и fingerprint журнала, чтобы восстановление не изменило режим расхода и не списало комплект дважды. Старые операции без флага работают как раньше. Если комплект исчез между просмотром и подтверждением, GM заново проверяет условия и не подменяет выбор молча.

## Подходы
1. Рекомендуемый: скорректировать критерий допустимости в dnd5e-адаптере и добавить точный флаг через существующие диалог, контракт, документы и журнал. Это сохраняет владельцев поведения и recovery.
2. Пропустить проверки только в диалоге: меньше изменений, но GM и восстановление отклонят такой запрос либо расходуют комплект неправильно; этот вариант не подходит.

## Проверки
До изменения кода добавить регрессии для конструкта, 0 HP с автоматическим `dead`, трёх провалов, нежити и ручного `dead`; для галочки — пустой список, обычный расход существующего комплекта, отклонение без галочки, подмену payload, восстановление и старые записи. Обновить паспорта, README, версию модуля и forwarder; выполнить focused и полные проверки. Живую проверку проводить только в выделенном тестовом мире.
