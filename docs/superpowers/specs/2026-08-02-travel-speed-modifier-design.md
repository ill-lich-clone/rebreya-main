# Модификатор скорости путешествия

## Цель

Добавить во вкладку «Путешествие» общий для группы множитель скорости `1/4`, `1/2`, `1`, `2` или `4`. Выбранное значение должны видеть все пользователи, а расчёт пути должен использовать его как часть сохранённого состояния путешествия.

## Интерфейс

Под существующим рядом управления путешествием размещается отдельный компактный ряд «Скорость» с пятью кнопками: `¼×`, `½×`, `1×`, `2×`, `4×`. Активная кнопка визуально выделяется. Доступ к изменению множителя совпадает с доступом к управлению маршрутом; для остальных пользователей ряд остаётся видимым, но недоступным.

Выбор кнопки сразу сохраняет значение и обновляет представление. Отдельная кнопка сохранения не нужна.

## Состояние и синхронизация

Поле `speedMultiplier` хранится внутри `travelState` активной группы и проходит через существующий механизм нормализации и команду полной замены состояния путешествия. Допустимы только значения `0.25`, `0.5`, `1`, `2`, `4`; отсутствующее или некорректное значение нормализуется в `1`.

Смена маршрута сохраняет выбранный множитель. Полный сброс маршрута возвращает множитель к `1`. После записи сервис возвращает новый snapshot, а открытые приложения обновляются существующим механизмом синхронизации.

## Расчёт

Базовая скорость продолжает поступать от активного транспорта либо дорожной сети. Эффективная скорость равна `baseSpeedMph * speedMultiplier` и используется единообразно для:

- общей и оставшейся длительности маршрута;
- продвижения в милях за выбранное число часов;
- вычисления фактически применённых часов;
- показателя скорости во вкладке путешествия.

Расход топлива остаётся привязан к реально пройденным милям, поэтому отдельное изменение топливной механики не требуется.

## Ошибки и права

Недопустимое значение отклоняется на публичной границе API и нормализуется при чтении старых данных. Пользователь без прав управления не может изменить множитель. При ошибке сохранения UI показывает стандартное уведомление и перерисовывает состояние с сервера.

## Проверки

- нормализация старого, допустимого и некорректного состояния;
- расчёт длительности и продвижения для множителей;
- сохранение множителя сервисом и возврат синхронизированного snapshot;
- наличие пяти кнопок, активного состояния и проверки прав в шаблоне;
- обработчик UI вызывает API один раз и применяет полученный snapshot;
- существующие тесты маршрута, календаря и расхода топлива остаются зелёными.
