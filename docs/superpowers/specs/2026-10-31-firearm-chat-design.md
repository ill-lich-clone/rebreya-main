# Карточки состояния огнестрела

Конкретный запрос пользователя: оформить сообщения огнестрела и объединить проверку осечки и опустевший магазин, когда они относятся к одному выстрелу. Используется существующий chat-note owner CombatAttackService, без нового UI приложения, hooks или очереди сообщений.

Наблюдаемый результат: одна оформленная карточка/секция с заголовком, результатом проверки (порог, d20, исход) и напоминанием о перезарядке после последнего патрона. При наличии настоящей originating attack card секция попадает в неё одним update; без неё создаётся одно сообщение состояния. Осечка до создания attack card остаётся видимым самостоятельным сообщением. Без свойства осечки выводится только реальное предупреждение о пустом магазине. Остальные сервисные сообщения огнестрела используют тот же безопасный визуальный блок. Стиль локальный, тёмный фон, латунный акцент, читаемые строки; пользовательские имена экранируются.

Контракты: прежние ammo quantities, стоимости 1/3/6, порядок проверок, формулы/бонусы, jam state и уведомления не меняются. Public result objects и createMessage:false сохраняются. Самостоятельное сообщение сохраняет реальный Roll через native toMessage; куб не перебрасывается ради оформления. В существующей карточке остаётся её attack Roll, а проверка осечки передаётся текстом/flags как в прежнем successful-check path; новый misfire Roll в parent.rolls не добавляется. Секретные карточки и rejected-update fallback сохраняют whisper/blind. Существующий flags.firearmChatNotes (массив строк) и data marker сохраняются, повторная синхронизация заменяет свой блок, а не дублирует. Area-fire API не получает новой проверки осечки; его уведомление о пустом магазине объединяется с текущим результатом.

Подход: consume возвращает состояние, вывод выполняется после существующей проверки осечки; её options получают результат расхода текущего выстрела. Никакого накопления между выстрелами, таймеров, custom sockets, receipts или distributed protection. При обычной перезарядке/резервуаре меняется оформление, прежнее содержание сохраняется.

Уточнение пользователя: взять за основу недавнее оформление сообщений реакции и добавить «Перезарядить» прямо в сообщение для автора атаки. Используются существующие rm-reaction-chat classes/tokens, без правок механики реакций. Пустой магазин сохраняет маленький адресный flag firearmReload={actorUuid,weaponId} в своём сообщении/parent/fallback. Уже зарегистрированный chat render hook показывает локальную кнопку только автору сообщения с текущими OWNER-правами на оружие; остальные её не видят. Нажатие открывает существующий openMagazineEditor и не списывает патроны до подтверждения. Повторный render не дублирует кнопку, удалённое/недоступное оружие её не получает. Открытие обрабатывает ошибку/disabled на время await.

Второе уточнение: подсказка о пустом магазине тоже нужна только атакующему. В общей карточке эта строка по умолчанию hidden и render hook раскрывает её только автору; прочим остаётся результат осечки. Блок без публичных строк целиком скрывается для остальных. Самостоятельный empty-only статус и подтверждения программной перезарядки/загрузки резервуара отправляются whisper автору. Это настройка отображения общих карточек, не механизм сокрытия части ChatMessage source от пользователей с доступом к самому сообщению.

Проверка: regression для последнего патрона с успехом/осечкой/без свойства, native parent и standalone, createMessage:false, приватность fallback, экранирование, area-fire без нового броска. Live disposable Foundry fixture, сохранённые сообщения и визуальная проверка карточек; production inventory не меняется.
