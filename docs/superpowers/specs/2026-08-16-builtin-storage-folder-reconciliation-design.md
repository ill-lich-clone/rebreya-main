# Согласование папки встроенных хранилищ

## Наблюдаемый результат

После active-GM sync все встроенные storage-Actor находятся в одной существующей папке `Хранилища`, даже если она вложена в другую Actor-папку. Повторный запуск не создаёт второй каталог с тем же именем.

Если в мире уже несколько Actor-папок `Хранилища`, канонической становится самая старая. Остальные папки не удаляются автоматически.

## Владелец и границы

- Единственный владелец поведения — `BuiltinStorageActorService` в `scripts/data/builtin-storage-actor-service.js`.
- Composition root, hooks, sockets, world settings, UI и публичный API не меняются.
- Синхронизация по-прежнему выполняется только на active GM.
- Исправление затрагивает только Actor с валидным `flags.rebreya-main.builtinStoragePreset.id`; пользовательские Actor не перемещаются.

## Выбор канонической папки

1. Получить все папки из `game.folders`.
2. Оставить документы типа `Actor`, чьё имя после `trim()` точно равно `Хранилища`; уровень вложенности не учитывать.
3. Папки с числовым `_stats.createdTime` поставить раньше папок без времени и выбрать минимальное время.
4. При одинаковом времени, а также между папками без времени, стабильно сравнить строковые `id`.
5. Если совпадений нет, создать корневую Actor-папку `Хранилища`, как это происходит сейчас.

Выбор не зависит от порядка элементов в Foundry Collection.

## Синхронизация Actor

`sync()` передаёт идентификатор канонической папки как при создании отсутствующего пресета, так и при обновлении существующего. Для существующего встроенного Actor поле `folder` обновляется только тогда, когда текущая папка отличается.

Остальная существующая синхронизация не меняется: сохраняются имя Actor, содержимое хранилища и пользовательские правки; продолжают обновляться только управляемые prototype-token поля и безопасные миграции токенов сцены.

Обновление `folder` входит в существующий единый `actor.update()`. Его ошибка сохраняет текущее поведение сервиса: прерывает sync и передаётся в error boundary composition root; папки и Actor при этом не удаляются.

## Дубликаты

После успешной синхронизации встроенные Actor собраны в канонической папке. Неиспользуемые одноимённые папки остаются на месте, потому что сервис не может доказать, что внутри нет пользовательских документов, и не владеет их удалением.

## Проверка

Focused-тесты `tests/builtin-storage-actor-service.test.mjs` должны доказать:

- существующая вложенная папка `Хранилища` переиспользуется без `Folder.create()`;
- из нескольких совпадений выбирается самая старая независимо от порядка коллекции;
- папки без `createdTime` следуют после папок с известным временем, а равенства разрешаются стабильно по `id`;
- все существующие встроенные Actor из других папок перемещаются в каноническую;
- пользовательские поля Actor и содержимое storage state сохраняются;
- лишние папки не удаляются;
- при отсутствии совпадений по-прежнему создаётся одна корневая папка и все 12 встроенных Actor создаются в ней;
- inactive GM остаётся полным no-op.

При реализации обновляется раздел 8 `docs/function-passport.md`, затем выполняются focused-тест и полная проектная проверка из `AGENTS.md`.
