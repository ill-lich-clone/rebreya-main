# Новый комплект иконок для компендиумов Rebreya

## Цель и границы

Подготовить новый, согласованный комплект предметных иконок для управляемых компендиумов Rebreya. Единица учёта — документ компендиума со стабильным `packId` и `documentId`, а не существующий файл и не строка имени. Полный каталог содержит более 3500 позиций; текущая волна сознательно исключает базовое снаряжение, поэтому количество генерируемых иконок определяется манифестом и может быть меньше 3500. Не добавлять фиктивные позиции ради численного порога.

Текущая волна **включает** импланты и усовершенствования: в `data/gear.json` это 108 и 124 записи соответственно, входящие в 808 строк gear. `data/implants.json` и `data/upgrades.json` служат профильными источниками, а не отдельными дополнительными документами для повторного счёта. По подтверждённому правилу пользователя исключены обычные оружие, доспехи, вещи и боеприпасы из листов `Оружие V0.36` (57), `Доспехи V0.1` (31), `Общий компендиум снаряжения V0.1` (360), `Боеприпасы V0.1` (52) и `Боеприпасы` (4): всего 504 gear ID. `Длинный меч` входит в этот список. В текущей волне остаются 304 gear ID: импланты 108, усовершенствования 124, огнестрел 34, обвесы 25, взрывчатка 13. Каждое исключение записывается по gear ID; тип `Имплант` или `Усовершенствование` не может попасть под общее исключение.

Эта спецификация новая. Документы от 2026-08-26 описывают другой объём и не определяют ни состав целей, ни визуальный стиль, ни геометрию этой работы.

## Неизменяемый порядок исполнения

1. Зафиксировать чистый `lich_branch`, сделать проверяемую резервную копию модуля и **всего затрагиваемого мира** до синхронизации. Git не заменяет копию world packs. Сохранить путь, дату, хеши и способ восстановления. На время файловой копии остановить Foundry или использовать его согласованную процедуру консистентного backup.
2. Только после проверки копии выполнить **нынешнюю** синхронизацию из текущего HEAD через active GM: `game.rebreyaMain.reloadData({ notify: true })`. Снять до/после counts и стабильные UUID всех managed packs; неожиданные удаления, изменения чужих документов или ошибки блокируют следующий этап.
3. Из синхронизированных pack indexes и канонических source ID построить неизменяемый target manifest. Снять `sourceCommit`, версию модуля, fingerprint каталога, правила исключений и количество по каждому pack. Список файлов в `templates/icons/` не является источником целей.
4. До первой генерации зафиксировать prompt contract, style registry и критерии пилотной сетки выбранного pack. Затем проходить **строго по одному компендиуму за раз**, без смешивания pack в одной сетке.
5. После полной проверки pack установить только его принятые иконки, поднять версию модуля, выполнить синхронизацию и аудит этого pack. Следующий pack начинается отдельным batch/чатом с сохранённым receipt.

## Источники и владельцы

- Pack IDs определяются `scripts/constants.js`; порядок live sync и единственная точка очистки icon cache — `scripts/main.js`, `#syncManagedCompendia(model)`.
- Стандартный managed update — `scripts/data/managed-compendium-sync.js`; нормализация имени, lookup и общий кэш — `scripts/data/compendium-utils.js`.
- Gear, включая импланты и усовершенствования, принадлежит `scripts/data/gear-compendium.js` и `gear-icon-resolver.js`. Отдельных world packs для имплантов и усовершенствований нет.
- Остальные владельцы: `materials-`, `magic-items-`, `feats-`, `glossary-`, `states-`, `backgrounds-`, `races-`, `spells-`, `classes-`, `actions-`, `downtime-`, `transport-` и `craftsman-construct-compendium.js`.
- Существующий `tools/icon-pipeline.py` покрывает только feats/races и выдаёт отдельные 1024×1024 PNG jobs. Его текущий контракт **не** подходит для сеток этой задачи; расширить существующего владельца, не создавать параллельную систему имён и нарезки.

Контрольные числа исходников на 2026-09-23: materials 612, gear 808, magic items 666, feats source 422, backgrounds 160, races 34, transport 62, downtime 26, states 32, glossary terms 63, spells source 2. Числа class/race features, actions и создаваемых сервисами записей берутся из фактического synced pack snapshot; считать количество файлов в `templates/icons/` количеством документов запрещено. Проверять дубликаты по `packId + documentId`, нормализованные имена, коллизии output path и случаи, где один icon обслуживает несколько документов.

## Визуальный контракт

- Язык изображения: предметные фэнтези-иконки, сопоставимые по читаемости и материалу с базовыми иконками Foundry. Один главный объект или ясное действие, узнаваемое при показе 64–200 px; допускается деталь на предмете, но фон чёрный либо простой тёмный, без сценического пейзажа.
- Общие запреты: текст, цифры, псевдобуквы, логотипы, интерфейс, коллаж внутри ячейки, водяные знаки, сильное свечение, закрывающее силуэт, декоративная рамка по умолчанию. Один объект не должен заходить в соседнюю ячейку.
- У каждого pack есть постоянный опознавательный материал, свет или палитра. У каждого класса внутри class pack — отдельный мотив. Эти различия не меняют общий уровень реализма, освещение и контраст.

| Набор | Отличительный признак |
|---|---|
| Materials | один физический образец, узнаваемая фактура вещества |
| Magic Items | форма предмета первична, сдержанное свечение его свойства |
| Feats | жест или символ действия, бронзовый акцент |
| Backgrounds | рабочий инструмент или атрибут роли, тёплая патина |
| Races / race features | силуэт происхождения, кость или камень как общий акцент |
| States | гербовый предмет или ландшафтный знак, холодная эмаль, без надписей |
| Actions | динамический жест, чёткий диагональный силуэт |
| Downtime | инструмент и результат занятия, спокойный тёплый свет |
| Transport | транспорт целиком в три четверти, тёмный нейтральный фон |
| Glossary | один простой предметный символ термина |
| Spells | ясно различимый эффект стихии/школы, без фигуры заклинателя по умолчанию |
| Gear: implants | анатомический механический узел, холодная сталь и бирюза |
| Gear: upgrades | отдельная деталь или модуль крепления, медь и сталь |
| Gear: firearms/attachments/explosives | точная форма механизма, сталь и контролируемый огненный акцент |
| Craftsman construct | механический силуэт, медь и бирюза; token/portrait не менять без отдельного аудита |

Классы: Barbarian — грубое железо и угольный красный; Fighter — синёная сталь; Paladin — светлая сталь и золото; Rogue — тёмная сталь и фиолетовый; Sorcerer — глубокий синий магический свет; Craftsman — медь и бирюзовая инженерия. Для подклассов сохраняется мотив родительского класса, а собственный предмет/действие отличает запись.

## Контракт сетки и приёмки

- Один batch = один pack, не более 25 документов, порядок ячеек слева направо, сверху вниз. Сетка **ровно 1000×1000 px**, 5×5 одинаковых квадратных ячеек по **200×200 px**. Последний неполный batch оставляет пустые чёрные ячейки; не добавляет цели другого pack.
- Генератор получает точный список `01–25` из manifest с коротким визуальным описанием каждого предмета и pack style. Номер — только в промпте/receipt, на изображении текста нет.
- На входе до нарезки машинно проверить фактическую декодируемость, размер **1000×1000**, 25 ровных ячеек, отсутствие смещённой сетки и пустоту незанятых ячеек. Визуально проверить соответствие каждой ячейки имени, уникальность, читаемость и отсутствие текста/слияния ячеек. Некачественную сетку отклонить целиком и перегенерировать; не масштабировать 1024→1000, не растягивать прямоугольник и не чинить раскладку смещённым crop. После трёх неудачных попыток остановить batch с записанной причиной.
- Принятые ячейки обрезать по точным координатам в 200×200 и кодировать в WebP без апскейла. Временная сетка, preview и receipt остаются в ignored `tmp/imagegen/`; итоговые WebP попадают в module-owned path только после приёмки всех ячеек. Существующие файлы заменять атомарно после отдельной копии оригинала и проверки разрешённого target path.
- Receipt содержит pack ID, batch ID, список `documentId/name/outputPath` по ячейкам, SHA-256 исходной сетки, размеры, SHA-256 итоговых файлов, prompt/style revision, результат QA и статус `rejected|accepted|installed|synced`. Частичный batch никогда не отмечается завершённым.

## Runtime и критерии готовности

Использовать существующие поисковые каталоги и `resolveNamedIcon()` там, где они корректно различают документы. Если нормализованные имена сталкиваются внутри общего search root, решить collision **до генерации** и добавить pack/source-ID-aware разрешение у канонического владельца; молчаливое присвоение одной иконки разным целям недопустимо. Для pack без named lookup менять только его владеющий сервис и профильный тест. Не трогать flags, mechanics, UUID, пользовательские документы, actor token или исходные каталоги ради изображений.

После каждого pack: 0 недостающих принятых targets, 0 ошибочных путей и 0 повреждённых WebP; каждое итоговое изображение декодируется как 200×200; excluded base gear не меняется. Live active-GM sync сохраняет UUID, источник и механические поля; изменяется только ожидаемый `img`. Изменение раздаваемых файлов требует новой `module.json` version, соответствующего `scripts/main-<version>.js` forwarder и проверки отсутствия устаревшей runtime-ссылки. Один рекурсивный scan icon root на один startup/reload batch, один canonical ESM URL/cache key.
