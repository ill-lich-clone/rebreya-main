# Исправления панели и бонусов оружейных обвесов

Основание: десять прямых замечаний пользователя к реализации1.4.389 и четыре предоставленных скриншота. Это уточнение ранее утверждённых spec/плана `2026-10-16-weapon-attachments`; способ исполнения Native сохраняется. Нового подсистемного API, миграции или нового проекта нет.

## Наблюдаемый результат

1. В существующей вкладке МОДЫ ниже штатного D&D разделителя с `&` появляются две под-вкладки: **Обвесы** и **Усовершенствования**. Первая содержит чертёж, модернизированные части и их выбор, вторая — прежнюю панель обычных усовершенствований. Выбор сохраняется при rerender листа; на оружии без поддержки обвесов доступна прежняя панель.
2. Надпись «Оружейные обвесы» расположена на верхней рамке чертежа. Инструкция о действии/бонусном действии не обрезается. Квадратные карточки не пересекаются и не выходят за диаграмму при узком/широком листе. Длинные названия ограничены читаемой подписью и полным tooltip/aria-label.
3. Установленный Item заполняет квадрат карточки изображением на всю ширину. Метка крепления и краткое имя накладываются читаемыми плашками; изображение не растягивается по одной оси. Второе крепление одного физического обвеса показывает тот же Item со связью, без создания второго экземпляра. Связь креплений одного child рисуется отдельно от указателей к оружию, ровной линией между границами карточек; стрелки не проходят через карточки.
4. Выбор слота фильтрует каталог по фактической совместимости оружия и выбранного крепления. ВЕРХ показывает подходящие прицелы, не показывает нижние/боковые/ствольные позиции. Сохраняются совместимые отсутствующие варианты. Заблокированный уже установленный вид/занятые необходимые крепления не превращаются в доступный вариант.
5. Окно выбора компактное: изображение, имя-ссылка на существующий доступный Item (owned экземпляр, world или canonical compendium source), количество и отдельное действие установки. Полный текст механики/требований не печатается. Недостающий источник не создаётся из каталога; при отсутствии доступного документа имя остаётся обычным текстом. Ссылки и иконки работают и у отсутствующих вариантов при наличии доступного source Item.
6. Список явно разделён на **Есть в инвентаре** и **Нет в инвентаре**. Во второй группе установка недоступна, серая стилизация дополнена текстом. Совместимые owned заблокированные экземпляры остаются в первой группе с краткой причиной/tooltip. Просмотр ссылок ничего не устанавливает.
7. Модернизация выбирает реальную имеющуюся часть и вызывает прежний paid command. Пустая owned группа объясняет отсутствие деталей. Фраза «Одна часть за пересборку…» удаляется из панели. Механическое правило **одна часть и500 зм немедленно** сохраняется, включая500/499, замену при лимите, возвращение старой части, approval и recovery.
8. Числовые бонусы реально добавляются к native броску огнестрела. Подтверждённая причина: на live Foundry13.351/dnd5e5.2.5 аркебуза имеет `activity.actionType="fwak"`, `attack.type={value:"firearm",classification:"weapon"}`. Проекция тактической рукоятки содержит attack-bonus1, а прежний roll adapter отвергает этот native тип. Исправление общего predicate включает этот подтверждённый тип, не применяет обвесы к заклинаниям/посторонним предметам и не складывает один бонус повторно. Условные прицел/лазер/сошки/приклад сохраняют свои условия; авторские parts, advantage, источники и прочие бонусы сохраняются. Native damage путь также распознаёт огнестрел, не добавляя attack bonus к урону.

## Владельцы и сохранённые контракты

UI: `weapon-mod-panel.js`, прежние `item-upgrade-sheet.js`, `item-mods-tab.hbs`, scoped CSS и точечный part context. Rules/проверенные links и mutations остаются у `weapon-mod-rules.js`/`ItemUpgradeService`; броски — `SimpleUpgradeRollAdapter` и прежние combat hooks. UI не пишет деньги/settings/links напрямую. Старые1–3 enhancement slots, формулы, profile signatures, количество, charges, патроны,500gp, календарное отсутствие, typed ownership/activeGM/journal и публичные API сохраняются.

Изменение относительно старой spec: каталог выбранного крепления показывает весь **совместимый** каталог вместо всех13 обвесов; prose из строк убирается. Под-вкладки и квадратные карточки заменяют прежнее последовательное расположение. Не меняются38 изображений, topology3/6/2, лимит3 частей, запрет дубликатов и один нижний+ствол для многоместного обвеса.

## Проверка

Regression RED до product правок: реальный native `fwak/firearm` без добавленного+1, совместимый верхний каталог с отсутствующим прицелом, компактные ссылки и две группы, две под-вкладки с сохранением выбора, квадратные карточки/многоместная геометрия, успешное UI→paid service подтверждение и бесплатная отмена. Проверить обычные upgrades, managed штык/launcher и несовместимые Item.

Live CODEX вошёл в существующий world; чтение реальной аркебузы подтвердило дефект без броска/расхода/записи. Для дальнейших проверок использовать неперсистентные native fixtures; реальные персонажи, их деньги и патроны не меняются. Browser UI/screenshots и native source подтверждаются отдельно от Node тестов. При ограничениях записать точную непроверенную границу. Версия/forwarder/cache и stylesheet epoch повышаются совместно; full tests, syntax/JSON/diff, scoped commit/push только lich_branch. Паспорт обновляется в том же commit.
