# Геометрия патронов, семейства оружия и понятная зарядка

Продолжение утверждённой механики боеприпасов и пользовательского запроса от2026-10-30. Пользователь просит выровнять патроны по магазину, дать собственные изображения примитивному оружию/дробовикам и объяснить непонятное предупреждение. Нативный редактор, профильные правила, пресеты и подтверждение остаются.

## Результат

У винтовки реальные патроны выровнены по двум границам cutaway-фото: положения, ширина и угол берутся из тех же cubic Bezier edges, не из приблизительной квадратичной кривой. Прозрачные поля sprite учитываются без raster edits. Группы выделяются вдоль того же контура; все патроны видимы внутри рамки без пересечений.

Примитивное оружие показывает отдельные заряды в виде сферической свинцовой пули; AK-магазина у него нет. Дробовики показывают собственные дробовые патроны: короткая раскладка патронников для1–2 и прямой трубчатый магазин для большего количества. Остальное современное оружие с малой вместимостью/иной ammo family использует нейтральные зарядные ячейки, а не AK. Семейство выбирается по native type/firearmClass и canonical ammunition subtype, не по display name. Геометрия меняет только представление; однородные группы1/3/6, последовательность, стоимости, эффекты и реальные capacities сохраняются.

Предупреждение объясняет конкретное сохранённое количество и необходимость указать уже заряженные патроны для правильного возврата. Фраза «разновидность старых боеприпасов» убирается. Отсутствующая запись не доказывает наличие патронов.

## Подтверждённая ошибка и намеренное изменение поведения

В live testovyj3 старая аркебуза NX1k5gP5JAC3v6EK имеет scalar current1 с timestamp2026-10-29; тип не сохранён. Новая аркебуза3MydiVi1QpPn0cHj и автоматqC5zGhXCJUb3C4Xh не имеют firearmAmmoState, но #resolveFirearmAmmoState подставлял capacity как current. Это создавало фиктивные заряды и предупреждение. Новый default при отсутствии сохранённого/явного current —0. Любой реально сохранённый count, в том числе старый scalar1, и явный options.firearmAmmoCurrent сохраняются. Модернизация оружия без состояния также не должна возвращать несуществующие патроны. Ни количество инвентаря, ни реальные старые заряды автоматически не переписываются; чтение/редактирование — без Document writes, до подтверждения.

Сохранённый неизвестный count требует прежнего явного решения GM только для правильного возврата/замены. @legacy резервуар импланта с положительным количеством остаётся доступен, без выдуманного типа или бонуса. Старые typed snapshots/presets не переосмысляются. Новых socket commands, journals, receipts, queues или Item-магазинов нет.

## Подход

Для curved rifle сохраняется пользовательское фото, а UI следует его контурам. Один универсальный рисунок отвергнут наблюдаемыми скриншотами; новый3D движок не нужен. Генерируются два самостоятельных арт-asset (свинцовая пуля и дробовой патрон), controls/ячейки остаются native ApplicationV2/Handlebars/SVG. Владелец визуального выбора/геометрии — отдельный pure UI helper, механики — прежний CombatAttackService.
