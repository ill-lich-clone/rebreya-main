# Топливо транспорта через Item в партийном инвентаре

## Цель

Полностью заменить текущую настройку топлива через лист Actor транспорта. Вся пользовательская механика выбора и отображения топлива должна находиться во вкладке «Транспорт» приложения партийного инвентаря.

Топливо остаётся обычным Item партийного инвентаря. Его количество хранится только в стандартном `item.system.quantity`; отдельного запаса, embedded Item транспорта или дублирующего числового поля не существует.

## Основная модель

Для каждого конкретного транспорта Rebreya хранится только селектор активного топлива. Селектор описывает идентичность выбранного Item, но не содержит его количество.

Селектор включает достаточные данные для устойчивого поиска и отображения:

- UUID исходного Item, если он доступен;
- управляемые модулем `sourceType` и `sourceId`, если они доступны;
- тип документа Item;
- нормализованное название;
- отображаемые название и изображение.

Выбор относится к конкретному Actor транспорта. При переключении активного транспорта вкладка показывает топливо выбранной машины.

## Drag-and-drop

Во вкладке «Транспорт» находится drop-зона активного топлива. Она принимает только стандартный Foundry drag payload типа `Item`.

Item можно перетащить из:

- компендиума;
- каталога Items;
- открытого листа Actor;
- партийного инвентаря;
- другого интерфейса, создающего корректный Foundry Item payload.

Drop только выбирает тип активного топлива. Он не перемещает, не копирует, не создаёт и не удаляет Item, а также не меняет количество исходного документа.

Новый корректный drop сразу заменяет прежний селектор. Подтверждение не требуется, поскольку складские предметы и их количества не изменяются.

Если активный транспорт не выбран, транспорт не является конкретным экземпляром Rebreya или пользователь не может управлять группой, drop отклоняется с понятным уведомлением.

## Поиск запаса в партийном инвентаре

После выбора топлива сервис ищет соответствующий Item среди Items партийного инвентаря в следующем порядке:

1. точный текущий Item партийного инвентаря, если селектор был создан из него и документ ещё существует;
2. совпадение управляемых `sourceType` и `sourceId`;
3. совпадение исходного UUID;
4. для пользовательских Items — совпадение типа и нормализованного названия.

Если совпадает несколько стеков одного топлива, их количество суммируется для отображения запаса хода. При списании стеки расходуются в стабильном порядке до покрытия требуемого количества.

Если соответствующего Item нет, выбор топлива сохраняется. В интерфейсе отображаются нулевой запас и `0 миль`; оба значения имеют красный текст. Когда соответствующий Item позднее появляется в партийном инвентаре, он подхватывается автоматически без повторного drop.

## Карточка топлива

Топливный блок использует полноценное представление Item по образцу строки во вкладке «Инвентарь», а не упрощённую текстовую плашку.

Карточка показывает:

- изображение;
- название;
- тип;
- суммарное количество в партийном инвентаре;
- вес и стоимость, когда они доступны;
- расход транспорта на милю;
- доступный запас хода в целых милях.

Игрок может открыть Item как обычную карточку:

- если найден складской Item, открывается реальный Item партийного инвентаря;
- если запаса нет, но исходный UUID доступен, открывается исходный Item, например документ компендиума;
- если документ больше нельзя разрешить, карточка остаётся видимой, но действие открытия отключается с пояснением.

Существующие правила прав на открытие Item сохраняются. Изменение количества выполняется существующими средствами партийного инвентаря; отдельного редактора количества во вкладке «Транспорт» не добавляется.

## Расход и запас хода

Расход на милю берётся из характеристик конкретного транспорта. Существующее ручное поле `fuelPerMile` удаляется из пользовательского интерфейса.

Нормализатор транспортного каталога должен преобразовывать исходную строку расхода в машинно-читаемые поля: вид расходника, числовой расход на милю и единицу. Дроби вида `1/8`, `1/16` и `1/32` поддерживаются явно.

Запас хода вычисляется так:

`floor(суммарное количество подходящих Items / расход на милю)`

При продвижении маршрута сервис списывает требуемое количество непосредственно из `system.quantity` складских Items. Количество не дублируется во флагах транспорта или состоянии приложения.

Нулевой стек не удаляется специально топливной механикой, если сохранение нулевого Item допускает текущая модель партийного инвентаря. Если сторонняя логика удаляет нулевой стек, селектор топлива всё равно сохраняется и продолжает показывать ноль до пополнения.

Недостаток топлива не блокирует существующий мягкий сценарий путешествия: доступный запас списывается, недостача показывается предупреждением, путешествие продолжается.

## Удаляемая механика

Из листа Actor транспорта полностью удаляются:

- секция «Топливо в пути»;
- выбор товара со склада;
- ручное поле расхода на милю;
- кнопка сохранения топлива;
- связанные обработчики и стили.

Старые `fuelItemId`, `fuelItemName` и `fuelPerMile`, указывающие на конкретный складской Item, больше не участвуют в расчётах. Они могут быть очищены при первой записи нового селектора, но очистка не должна изменять или удалять Items партийного инвентаря.

## Ошибки и права

- Не-Item payload не принимается.
- Неразрешимый Item сообщает об ошибке и не меняет текущий выбор.
- Ошибка записи селектора сохраняет прежнее топливо.
- Ошибка складского списания превращается в предупреждение и не повреждает остальные стеки.
- Менять выбор топлива могут только пользователи с правом управления группой.
- Просматривать карточку, запас и пробег могут все пользователи, которым доступен партийный инвентарь.

## Тестирование

Автоматические тесты должны покрывать:

- drop Item из компендиума, каталога, Actor и партийного инвентаря;
- отклонение payload другого типа;
- сохранение одного селектора на каждый транспорт;
- замену селектора без мутации Items;
- поиск по точному ID, управляемому источнику, UUID и пользовательскому fallback;
- суммирование нескольких стеков;
- нулевой и отсутствующий запас;
- полноценный контекст карточки и открытие складского либо исходного Item;
- автоматический разбор дробного расхода транспорта;
- расчёт целого запаса хода;
- списание из нескольких складских стеков;
- переключение активного транспорта;
- права доступа и обработку ошибок;
- отсутствие старой формы топлива на Actor Sheet.

Полный набор тестов модуля запускается перед публикацией ветки.
