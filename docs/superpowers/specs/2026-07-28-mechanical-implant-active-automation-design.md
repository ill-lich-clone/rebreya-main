# Активная автоматизация механических имплантов — проект

**Дата:** 2026-07-28

**Статус:** согласован на уровне решений, ожидает проверки спецификации

## Цель

Дополнить существующую механику Модифицирования активной автоматизацией трёх
механических имплантов:

- `Синтезатор яда`;
- `Модуль с препаратами`;
- `Разрисованный корпус`.

Решение продолжает существующие `implant-automation-registry`, `ImplantService`,
`ImplantAutomationService`, общий Active Effect `Импланты`, интеграцию универсального
пояса и штатные D&D5e/Midi-QOL activities. Короткие карточки, дублирующие служебные
предметы и миграция существующих миров не создаются.

## Границы задачи

В рамках задачи:

- настоящий Foundry Item `Синтезатор яда` получает штатные действия D&D5e;
- запас яда восстанавливается от продвижения мирового времени;
- `Модуль с препаратами` добавляет один предметный слот к интерфейсу универсального
  пояса;
- `Разрисованный корпус` создаёт ауру через обязательный модуль Aura Effects;
- состояние `Провокация` начинает реально изменять броски атаки.

В рамках задачи не автоматизируются:

- `Система термоконтроля` — остаётся внутренним capability/флагом;
- `Многофункциональный захват`;
- заклинания `Симбиотического мозга` — уже существующий бонус `+2` к проверкам
  Интеллекта и инициативе сохраняется без изменений.

Магические, древние и титанические импланты по-прежнему находятся вне текущего
объёма.

## Общие архитектурные ограничения

- Источником истины об установленном импланте остаётся скомпилированная capability
  общего эффекта `Импланты`.
- Пассивные числовые бонусы продолжают жить в одном общем эффекте `Импланты`.
- Отдельный постоянный эффект владельца допустим только для ауры
  `Разрисованного корпуса`, потому что Aura Effects требует Active Effect типа
  `auraeffects.aura` в качестве источника.
- Все изменения документов, зависящие от глобального времени или ауры, выполняет
  единственный ответственный GM-клиент.
- Повторный Foundry hook не должен дважды расходовать ресурс, восстанавливать заряд
  или добавлять один и тот же модификатор броска.
- Отдельная миграция мира не создаётся. Управляемый общий компендиум обновляется
  штатной синхронизацией; старую встроенную копию изменившего тип предмета при
  необходимости нужно удалить и снова взять из компендиума.

## Синтезатор яда

### Представление предмета

Существующая запись `sintezator-yada` остаётся единственным игровым предметом.
Служебная feature или вторая копия предмета не создаётся.

В управляемом общем компендиуме только эта запись меняет D&D5e-тип с `loot` на
`equipment` (`wondrous`), поскольку `LootData` текущей версии D&D5e не поддерживает
`system.activities`. Стабильный идентификатор и gear-id предмета сохраняются.
Синхронизатор управляемого компендиума заменяет корень `system` при изменении типа,
чтобы в документе не оставались поля старой модели данных.

### Штатные действия

Предмет содержит две save-activity:

1. `Синтезировать яд — бонусное действие`;
2. `Синтезировать яд — вместо атаки`.

Обе activity используют одну механику:

- активация первой — бонусное действие;
- активация второй — специальная, с явным текстом «вместо одной атаки»;
- область — конус 10 футов;
- спасбросок — Телосложение против существующего КС класса владельца;
- тип урона — яд;
- при успешном спасброске наносится половина урона;
- Midi-QOL получает обычную D&D5e save/damage activity и не требует отдельной
  карточки Rebreya.

До запуска activity открывается диалог с выбором количества костей. Допустимый
диапазон:

```text
1 .. min(6, текущий запас)
```

Выбранное значение задаёт формулу `Nd8` только текущему использованию и расходует
`N` единиц общего ресурса предмета. Постоянная формула activity не переписывается,
чтобы два почти одновременных использования разных актёров не влияли друг на друга.

Если запас равен нулю, использование блокируется до построения workflow. Закрытие
или отмена диалога отменяет activity и ничего не расходует. Расход происходит
ровно один раз только после подтверждения использования.

### Запас и восстановление

Предмет использует штатный ресурс uses текущей версии D&D5e:

- максимум — `12`;
- одна единица ресурса соответствует одной кости `d8`;
- новый предмет создаётся с полным запасом.

Восстановление подписывается на стандартный Foundry hook `updateWorldTime`.
SmallTime изменяет то же мировое время, поэтому отдельное вмешательство в его
внутренний API не требуется.

Правила восстановления:

- за каждые полные 3600 положительных секунд восстанавливается одна единица;
- неполный остаток времени хранится на самом Item и складывается со следующим
  положительным продвижением времени;
- ресурс не может превысить 12;
- при заполненном ресурсе накопленный полный час считается прошедшим, а не
  сохраняется для мгновенного восстановления после следующего расхода;
- перемотка мирового времени назад не отнимает заряд и не создаёт остаток;
- один ответственный GM обрабатывает все подходящие актёрские копии предмета.

Продолжительный отдых не получает отдельного обработчика восстановления.
Если отдых продвигает мировое время через SmallTime/Foundry, заряд восстанавливается
тем же часовым путём. Это исключает двойное восстановление.

## Модуль с препаратами

### Слот

Существующий интерфейс и сервис универсального пояса расширяются без создания
отдельной панели:

- обычные слоты `1–3` не меняются;
- при эффективной capability `medicineModule` появляется слот `4`;
- слот `4` не участвует в покупке и не влияет на число купленных слотов;
- слот доступен даже при одном стандартно открытом слоте пояса;
- подпись визуально связывает слот с Модулем с препаратами.

Для предмета в слоте используется тот же флаг назначения и тот же drag-and-drop
путь, что для слотов пояса.

### Допустимый предмет и использование

Проверяется только наличие `system.quantity`. Тип, подтип и назначение предмета не
проверяются: по согласованному правилу в модуль можно положить любой предмет «на
доверии».

Если в слот перетаскивается стек, существующая логика пояса отделяет одну единицу.
Клик использует настоящий Foundry Item его штатным способом. Предмет можно открыть,
прочитать, перетащить как ссылку и проверить его эффекты.

После снятия импланта слот скрывается, назначение предмета слоту `4` очищается, а
сам предмет остаётся в инвентаре актёра. Предмет не удаляется и не расходуется.
Повторная сверка состояния идемпотентна.

## Разрисованный корпус

### Обязательная зависимость

В `module.json` добавляется обязательная зависимость:

```json
{
  "id": "auraeffects",
  "type": "module",
  "compatibility": {
    "minimum": "1.5.2"
  }
}
```

Fallback без Aura Effects не реализуется. Foundry должен сообщить о недостающей
обязательной зависимости до активации Rebreya.

### Эффект-источник ауры

При эффективной capability `paintedBodyProvocation` сервис сверки поддерживает на
актёре ровно один управляемый Active Effect:

- имя: `Разрисованный корпус — аура`;
- тип: `auraeffects.aura`;
- радиус: 10 футов;
- disposition: hostile;
- эффект не применяется к владельцу;
- отдельный module-флаг однозначно отличает этот управляемый эффект от пользовательских.

Повторная сверка обновляет существующий эффект, а не создаёт новый. При снятии
импланта удаляется только этот управляемый эффект. Общий эффект `Импланты` не
превращается в aura-effect и продолжает обслуживать остальные импланты.

### Выбор целей

Aura Effects выполняет геометрическую проверку и поддерживает дочерние эффекты на
целях. Скрипт ауры дополнительно допускает цель, только если у её актёра указан хотя
бы один язык:

- хотя бы одно значение в `system.traits.languages.value`; либо
- непустой пользовательский язык в `system.traits.languages.custom`.

Проверка способности читать конкретный язык пока не выполняется. Враг без языков
ауру не получает. Союзники и нейтральные токены не получают её независимо от
языков.

Подходящая цель получает состояние `rebreya-provoked` со значением `1` и
module-флагом UUID провокатора. При выходе из ауры Aura Effects удаляет дочерний
эффект. Новый источник провокации заменяет предыдущий источник, чтобы у состояния
оставался один актуальный провокатор.

## Механика Провокации

Автоматизация относится к общему состоянию `rebreya-provoked`, а не только к
Разрисованному корпусу.

Перед броском атаки сервис определяет:

1. есть ли у атакующего эффективное состояние `rebreya-provoked`;
2. его текущее числовое значение;
3. UUID актёра-провокатора;
4. фактические цели текущей D&D5e/Midi-QOL атаки.

Правила:

- при атаке только провокатора штраф отсутствует;
- если среди целей атаки есть хотя бы одна цель, не являющаяся провокатором, к
  броску атаки добавляется штраф, равный отрицательному числовому значению
  состояния;
- `Провокация 1` даёт `−1`, `Провокация 2` даёт `−2` и так далее;
- отсутствующее, нулевое или некорректное числовое значение не создаёт штраф;
- спасброски, проверки характеристик и урон без броска атаки не изменяются;
- один workflow получает модификатор не более одного раза, даже если одновременно
  работают системный и Midi-QOL hook.

Источник и значение читаются в момент атаки. Поэтому изменение счётчика состояния
сразу меняет штраф без пересоздания activity или предмета.

## Ошибки и деградация

- Ошибка одной временной сверки ауры или времени журналируется с контекстом актёра
  и не прерывает остальные Foundry hooks.
- Отсутствующий актёр-провокатор означает отсутствие штрафа: система не угадывает
  источник по имени токена.
- Отсутствующая цель не позволяет определить «другую цель», поэтому штраф не
  добавляется до выбора цели.
- Предмет без доступного ресурса яда показывает понятное уведомление и не создаёт
  workflow.
- Снятие импланта не удаляет пользовательские Active Effects или предметы.

## Проверка

Каждый новый сценарий сначала фиксируется падающим `node:test`.

Минимальный набор автоматических проверок:

- классификация Синтезатора яда как equipment и построение обеих save-activity;
- границы диалога `1–6`, ограничение остатком, отмена без расхода и половина урона
  при успешном спасброске;
- восстановление за целые и составные часы, верхний предел, заполненный запас,
  обратное время и единственный ответственный GM;
- неизменность обычных слотов пояса, условный слот `4`, назначение одного предмета,
  штатное использование и безопасное освобождение при снятии импланта;
- создание, повторное обновление и удаление единственной управляемой ауры;
- фильтр hostile + хотя бы один язык;
- штраф Провокации, равный значению состояния, отсутствие штрафа против
  провокатора и защита от двойного применения;
- обязательная зависимость Aura Effects в манифесте.

Итоговая проверка:

```powershell
git diff --check
node --test tests/*.test.mjs
```

После автоматических тестов выполняется ручной smoke-test в Foundry:

1. установить каждый из трёх имплантов;
2. использовать обе activity Синтезатора с Midi-QOL;
3. продвинуть SmallTime неполным и полным часом, затем выполнить продолжительный
   отдых с продвижением времени;
4. положить произвольный Foundry Item в четвёртый слот и снять имплант;
5. войти и выйти язычной враждебной целью из радиуса корпуса;
6. атаковать провокатора и постороннюю цель при разных значениях Провокации.
