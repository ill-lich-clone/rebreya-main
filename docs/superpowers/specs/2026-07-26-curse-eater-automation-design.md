# Автоматизация черты «Пожиратель проклятий»

## Цель

Автоматически рассчитывать бонусы черты «Пожиратель проклятий» по проклятым
предметам, размещённым на кукле героя. Автоматизация должна заменять текущие
безусловные эффекты черты и не создавать дублирующиеся Active Effect.

В эту задачу входят ступени 1–7. Восьмая ступень определяется и отображается как
достигнутая, но её механические бонусы и подавление проклятий пока остаются
ручными.

## Источники состояния

Автоматизация включается только для персонажа, у которого есть предмет-черта с
идентификатором `pozhiratel-proklyatiy`.

Активными считаются только предметы, занимающие слот в
`flags.rebreya-main.heroDoll.slots`. Стандартное поле `system.equipped` не
является самостоятельным источником истины, хотя сервис куклы продолжает
синхронизировать его для совместимости с dnd5e.

Предмет считается проклятым, если выполняется хотя бы одно условие:

1. В его описании без учёта регистра присутствует слово «Проклятье» или
   «Проклятие».
2. На предмете установлено хотя бы одно усовершенствование, чей профиль
   `flags.rebreya-main.upgrade.type` равен «Проклятье» или «Проклятие».

Установленные усовершенствования разрешаются через существующие связи
`itemUpgrades.installed` и `installedUpgrade`. Сам предмет-усовершенствование не
считается отдельным проклятым предметом.

## Редкость

Для встроенного проклятья используется базовая редкость родительского предмета.
Отсутствующая или неизвестная редкость считается обычной.

Редкость проклятья-усовершенствования определяется по его рангу:

| Ранг | Редкость |
| --- | --- |
| 1–2 | Обычная |
| 3–4 | Необычная |
| 5–6 | Редкая |
| 7–8 | Очень редкая |
| 9–10 | Легендарная |

Эффективная редкость проклятого предмета равна максимальной из:

- базовой редкости предмета;
- редкостей всех установленных проклятий.

Несколько проклятий на одном родительском предмете всё равно дают только один
проклятый предмет.

## Расчёт достигнутой ступени

Требования ступеней:

| Ступень | Минимальная редкость предмета |
| --- | --- |
| 1 | Необычная |
| 2 | Редкая |
| 3 | Редкая |
| 4 | Редкая |
| 5 | Очень редкая |
| 6 | Очень редкая |
| 7 | Легендарная |
| 8 | Артефакт |

Предметы распределяются по ступеням оптимально. Реализация использует
детерминированный жадный подбор: требования рассматриваются от низкого к
высокому, а для каждого требования выбирается самый слабый ещё не использованный
предмет, который его удовлетворяет. Это не позволяет одному предмету закрыть
несколько ступеней и сохраняет более редкие предметы для поздних порогов.

## Управляемый эффект

На персонаже существует не более одного Active Effect, помеченного флагами
модуля как эффект «Пожирателя проклятий». Его содержимое полностью пересобирается
из текущей достигнутой ступени:

1. `+1` ко всем атакам и броскам урона оружием ближнего и дальнего боя.
2. Максимальные хиты увеличиваются на текущий бонус мастерства.
3. `+1` ко всем спасброскам персонажа.
4. `+1` ко всем исходящим Сл спасбросков, создаваемым персонажем.
5. `+1` к КД.
6. `+1` к двум разным выбранным характеристикам.
7. Сопротивление некротическому и психическому урону.

Постоянные модификаторы хранятся в одном Active Effect. Для четвёртой ступени
эффект хранит признак активной ступени, а узкий хук расчёта Сл добавляет единицу
к исходящей Сл. Это необходимо, потому что dnd5e не предоставляет общего
actor-поля для бонуса ко всем Сл. Фиксированные внешние Сл, не рассчитываемые от
персонажа, не изменяются.

Если черта удалена либо не достигнута первая ступень, управляемый эффект
удаляется. Перед включением новой автоматизации из принадлежащей персонажу копии
черты удаляются старые управляемые безусловные эффекты, чтобы исключить
удвоение бонусов. Другие пользовательские эффекты не изменяются.

## Выбор характеристик шестой ступени

При первом достижении шестой ступени владельцу персонажа показывается окно с
выбором двух разных характеристик. Подтверждение недоступно, пока не выбраны две
разные характеристики.

Выбор сохраняется в модульных флагах персонажа и не может быть изменён через
интерфейс автоматизации. При временной потере шестой ступени он сохраняется и
применяется снова при повторном достижении.

Закрытие окна без выбора не блокирует остальные ступени: эффект продолжает
содержать бонусы 1–5 и, если доступно, 7-й ступени. При следующей подходящей
синхронизации владелец снова получает запрос выбора.

## Синхронизация

Отдельный сервис выполняет идемпотентную синхронизацию персонажа. Он реагирует
на:

- создание, изменение и удаление принадлежащих персонажу предметов;
- добавление или удаление черты;
- изменение описания или редкости предмета;
- изменение `heroDoll`;
- установку, снятие или изменение профиля усовершенствования;
- загрузку мира для первичной сверки.

Повторные события объединяются коротким debounce на персонажа. Изменения,
созданные самим сервисом, помечаются опцией синхронизации, чтобы не запускать
цикл обновлений. Синхронизация сравнивает желаемое состояние с текущим и не
записывает документы без фактических изменений.

## Представление состояния

Флаги управляемого эффекта содержат:

- версию автоматизации;
- достигнутую ступень;
- идентификаторы и эффективную редкость использованных предметов;
- выбранные характеристики шестой ступени;
- признак ручной восьмой ступени.

Это позволяет диагностировать расчёт без повторного анализа бросков. При
изменении достигнутой ступени владелец получает краткое уведомление; чат не
засоряется сообщениями при каждой синхронизации.

## Обработка ошибок

- Неизвестная редкость безопасно считается обычной.
- Некорректный ранг проклятья ограничивается диапазоном 1–10; отсутствующий ранг
  даёт обычную редкость.
- Потерянные ссылки на установленные усовершенствования игнорируются.
- Ошибка одного персонажа журналируется и не останавливает синхронизацию других.
- Только управляемый эффект модуля может быть обновлён или удалён сервисом.
- Если нет пользователя с правами на выбор характеристик, синхронизация
  оставляет шестую ступень без бонуса характеристик и повторяет запрос позже.

## Проверки

Модульные тесты должны покрывать:

- оба способа определения проклятого предмета;
- учёт только слотов куклы;
- преобразование ранга проклятья в редкость;
- выбор максимума между базовой редкостью и редкостью проклятья;
- один предмет с несколькими проклятиями;
- оптимальное распределение предметов по порогам;
- состав одного эффекта на каждой ступени;
- отсутствие механики восьмой ступени;
- сохранение одноразового выбора характеристик;
- удаление и повторное создание эффекта без дублей;
- добавление `+1` только к исходящим Сл персонажа;
- подавление циклических и лишних обновлений.

Дополнительно запускаются существующие тесты компендия черт, куклы героя,
усовершенствований и полная доступная тестовая проверка проекта.
