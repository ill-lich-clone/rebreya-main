# Встроенные сундуки хранилищ Rebreya

## Цель

Модуль поставляет три готовых NPC-хранилища в world-папке актёров «Хранилища». Они отличаются открытой текстурой с медными, серебряными или золотыми монетами, автоматически меняют внешний вид вместе с состоянием лута и восстанавливаются при запуске мира, если мастер их удалил.

Фича не использует Item Piles. Источником состояния остаются actor/token flags Rebreya и существующие `StorageService`, `StorageApp` и active-GM команды.

## Встроенные ассеты

Исходники берутся из:

`D:\ЛИЧный хлам\🎲 ДнД для поляны\Материал для кампаний\Токены\Сундуки`

FFmpeg декодирует и заново кодирует пять изображений в WebP с сохранением прозрачности. Результаты сохраняются в модуле:

| Состояние | Исходник | Путь в модуле |
|---|---|---|
| Закрыт | `Chest_Wood_Ashen_A_1x1.webp` | `assets/storage/chests/wood-dark-closed.webp` |
| Открыт, медь | `Treasure_Chest_Wood_Dark_A1_Coins_Copper_1x1.webp` | `assets/storage/chests/wood-dark-copper-open.webp` |
| Открыт, серебро | `Treasure_Chest_Wood_Dark_A1_Coins_Silver_1x1.webp` | `assets/storage/chests/wood-dark-silver-open.webp` |
| Открыт, золото | `Treasure_Chest_Wood_Dark_A1_Coins_Gold_1x1.webp` | `assets/storage/chests/wood-dark-gold-open.webp` |
| Пуст | `Treasure_Chest_Wood_Dark_A1_Empty_A_1x1.webp` | `assets/storage/chests/wood-dark-empty.webp` |

Пути Foundry начинаются с `modules/rebreya-main/`. Закрытая и пустая текстуры общие для всех трёх пресетов.

## Каталог пресетов

Новый чистый модуль данных экспортирует неизменяемый каталог из трёх записей:

- `wood-dark-copper` — «Сундук — медные монеты»;
- `wood-dark-silver` — «Сундук — серебряные монеты»;
- `wood-dark-gold` — «Сундук — золотые монеты».

Каждая запись содержит стабильный ID, имя, закрытую/открытую/пустую текстуры и данные Prototype Token. Каталог не читает Foundry globals и тестируется отдельно.

## Восстановление world-актёров

`BuiltinStorageActorService` запускается в `ready` через текущий `RebreyaMainModule.initialize()` только на active-GM клиенте.

Алгоритм:

1. Найти корневую Actor-папку с именем «Хранилища»; если её нет — создать.
2. Для каждого пресета найти world Actor по стабильному флагу `flags.rebreya-main.builtinStoragePreset.id`.
3. Существующего актёра не переименовывать и не перезаписывать: пользовательские изменения сохраняются.
4. Если актёр отсутствует — создать NPC в папке «Хранилища».
5. Созданный актёр получает `flags.rebreya-main.storage.enabled = true`, служебный preset-флаг и готовый Prototype Token.

Prototype Token использует закрытую текстуру и несёт начальный token flag хранилища: состояние `unopened`, три текстуры, `displayMode: "unopened"` и базовое имя. Поэтому любой перетащенный экземпляр сразу работает как независимое хранилище.

Удалённая папка восстанавливается. Удалённый встроенный актёр восстанавливается. Дубликаты по имени не создаются, если существует актёр с правильным preset-флагом. Обычные NPC и вручную помеченные хранилища не изменяются.

## Состояние и текстуры токена

Storage token state расширяется полями:

```js
{
  textures: {
    unopened: "modules/rebreya-main/assets/storage/chests/wood-dark-closed.webp",
    opened: "modules/rebreya-main/assets/storage/chests/wood-dark-copper-open.webp",
    empty: "modules/rebreya-main/assets/storage/chests/wood-dark-empty.webp"
  },
  displayMode: "unopened"
}
```

Старые хранилища без `textures` продолжают работать без автоматической смены изображения.

`StorageService` записывает `texture.src` вместе с token flag, когда у состояния есть полный набор текстур:

- первое успешное открытие: `state = opened`, `displayMode = opened`;
- выдача последнего предмета/монет: `state = empty`, `displayMode = empty`;
- сброс содержимого мастером: `state = unopened`, `displayMode = unopened`.

Промежуточная выдача, после которой сундук остаётся `opened`, не сбрасывает ручной визуальный выбор.

## Ручное переключение мастером

В GM-режиме `StorageApp` показывает блок «Внешний вид» только для токенов с полным набором текстур:

- `1 — закрытый`;
- `2 — открытый`;
- `3 — пустой`.

Новый GM-only API `setStorageTextureMode(tokenUuid, mode)` принимает только `unopened`, `opened` или `empty`. Он меняет `displayMode` и `texture.src`, но не меняет логическое `state`, не генерирует лут и не отмечает содержимое забранным.

Ручной выбор хранится в token flag и переживает перерисовку/перезапуск. Следующий реальный переход логического состояния выставляет соответствующую текстуру автоматически.

## Ошибки и безопасность

- Создание папки и актёров выполняет только active GM.
- Ошибка одного пресета логируется и не мешает проверить остальные пресеты.
- API ручной текстуры отклоняет игроков, неизвестный mode и токены без настроенного набора текстур.
- Все пути ассетов являются статическими путями внутри модуля; пользовательский ввод не используется для построения файловых путей.
- Существующие socket-проверки открытия и выдачи лута не меняются.

## Проверка

Автоматические тесты должны доказать:

1. Каталог содержит три пресета и пять ожидаемых module asset paths.
2. Сервис создаёт папку и отсутствующих актёров только на active GM.
3. Повторный запуск не создаёт дубликаты.
4. Удалённый пресет восстанавливается, существующий изменённый актёр сохраняется.
5. `unopened → opened → empty` меняет текстуру автоматически.
6. Сброс возвращает закрытую текстуру.
7. Ручные кнопки меняют только `displayMode`/`texture.src`, не логическое состояние и не содержимое.
8. Игрок не может вызвать ручное переключение.
9. Старые хранилища без texture set сохраняют прежнее поведение.
10. FFmpeg-результаты существуют, являются WebP и объявлены в каталоге.

После unit/integration тестов выполняется живой прогон Foundry: восстановление папки, размещение каждого из трёх актёров, генерация, опустошение и ручные кнопки 1–2–3.
