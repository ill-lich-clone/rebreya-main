# Импорт алхимических продуктов

## Результат

Модуль получает отдельный управляемый compendium `world.rebreya-alchemy` с 230 алхимическими продуктами из листа `Алхимические продукты V1`. Каждый продукт является dnd5e-предметом типа `consumable`, содержит открытые для игроков эффект, рецепт и остальные текстовые правила, фиксированную максимальную цену для Foundry, вес по рангу и две уникальные иллюстрации. Автоматизация реагентов, употребления, бросков, эффектов, зависимости и крафта в эту поставку не входит.

Параллельно существующий импорт обычного снаряжения переходит на вкладку `Взрывчатка V0.1`, удаляет кислоту и алхимический огонь и корректно учитывает сдвинувшиеся строки без массовой смены стабильных ID оставшихся предметов.

## Источники и границы

- Механики и правила: Google Doc `ДНД: Алхимия V1.0` (`13G3y7d5klGEW274kbyixm_8Xk0qD-bslCyjCLuEhMqI`).
- Каталог: spreadsheet `1G-UCW00vsjON05fr0CgyK03YaF82oYJemlqNKdv1JBk`, лист `Алхимические продукты V1`, `sheetId: 179310389`.
- После удаления ранних дублей каталог содержит 230 продуктов. Номера 36, 52, 67 и 76 отсутствуют намеренно; сохранены поздние варианты 221, 226, 227 и 135.
- Номер из столбца `№` является стабильной идентичностью. Физическая строка Google Sheets нужна только для трассировки и может изменяться.
- Все рецепты и компоненты всегда видны игрокам. Секретного GM-блока нет.
- Первая версия переносит механику только в текст описаний. Она не создаёт Activities, Active Effects, Hooks применения, actor flags, счётчики реагентов, UI, sockets или автоматические броски.

## Схема исходного листа

Импортёр читает числовые строки из ограниченного диапазона `A3:V996`, а не предполагает непрерывную нумерацию. После добавления цены колонки имеют следующий контракт:

| Колонка | Поле |
|---|---|
| A | № |
| B | Название |
| C | Тип |
| D | Цена |
| E | Ранг |
| F | Уровень реагентов |
| G | Эффект |
| H | Эффект катализатора |
| I:N | Аспекты: Огонь, Вода, Земля, Воздух, Положительный, Негативный |
| O | Обязательный компонент |
| P | Сл создания |
| Q | Частный катализатор |
| R | Активация |
| S | Длительность |
| T | Требования |
| U | Упрощённое создание |
| V | Радиус или эманация |

Пустое или прочерк-поле нормализуется в `null`; значимый ноль сохраняется. Импорт останавливается до записи файлов, если номер или название дублируется, обязательное поле пусто, тип неизвестен, ранг не является целым числом 1–9 или ценовая формула не соответствует рангу.

## Цена, редкость и вес

Столбец D хранит формулу цены как текст. В описание предмета попадает исходная формула с единицей `ЗМ`. Стандартное числовое поле цены Foundry получает верхнюю границу броска, чтобы магазины и инвентарь не зависели от формульного значения.

| Ранг | Каноническая формула | Максимум, ЗМ | Редкость |
|---:|---|---:|---|
| 1 | `(1d6+1) * 5` | 35 | Обычный |
| 2 | `(1d6+1) * 40` | 280 | Необычный |
| 3 | `(1d6+1) * 50` | 350 | Необычный |
| 4 | `(1d6+1) * 400` | 2 800 | Редкий |
| 5 | `(1d6+1) * 500` | 3 500 | Редкий |
| 6 | `(1d8+1) * 4000` | 36 000 | Очень редкий |
| 7 | `(1d8+1) * 5000` | 45 000 | Очень редкий |
| 8 | `2d6 * 10000` | 120 000 | Очень редкий |
| 9 | `2d6 * 12500` | 150 000 | Легендарный |

Каноническая запись допускает нормализацию пробелов и знаков `*`/`×`, но не другую формулу. В нейтральном JSON редкость хранится как `common`, `uncommon`, `rare`, `veryRare` или `legendary`; dnd5e-проекция использует валидное значение установленной версии системы. `system.price.value` получает максимум, `system.price.denomination` — `gp`, а `system.weight` всегда равен рангу: предмет 1-го ранга весит 1 фнт, предмет 9-го ранга — 9 фнт.

## Канонические данные и импортёр

Новый CLI-импортёр следует существующему equipment-import подходу, но владеет только алхимией:

- читает один live snapshot `Алхимические продукты V1`;
- адаптирует строки в нейтральную модель;
- проверяет полный каталог до записи;
- детерминированно формирует `data/alchemy-products.json`;
- поддерживает dry-run с содержательным diff;
- не обращается к Google Sheets во время запуска Foundry.

Канонический ID имеет вид `alchemy-<№>`. Foundry document ID детерминированно выводится из него существующим проектным способом и не зависит от названия или физической строки. Запись содержит исходные 22 поля, вычисленные `priceMaximumGp`, `rarity`, `weight`, пути обеих иллюстраций и текущий `sourceRef` для диагностики.

## Проекция в Foundry

`AlchemyCompendiumService` создаёт или обновляет отдельный Item compendium `world.rebreya-alchemy` с пользовательской меткой `Алхимия Ребреи`. Он подключается в `scripts/main.js` к существующему startup batch управляемых compendia и выполняется только активным GM в поддерживаемом dnd5e-мире.

Каждая строка проецируется в dnd5e `consumable`. Ближайший валидный native subtype выбирается в одном dnd5e-адаптере; точный тип источника не теряется и определяет папку. Структура папок: продуктовый тип, затем ранг. Яды с уточнённым типом получают отдельную подпапку внутри `Яды`.

Описание строится безопасным HTML-рендерером и содержит только применимые непустые разделы в стабильном порядке:

1. эффект;
2. эффект катализатора;
3. активация, длительность, требования и зона;
4. цена с исходной формулой;
5. открытый рецепт: шесть аспектов, обязательный компонент, Сл создания, частный катализатор и упрощённое создание;
6. относящиеся к типу текстовые правила из документа по алхимии.

Документ получает observer-доступ по умолчанию, квадратную Foundry-иконку в `img` и flags пространства `rebreya-main`:

- `managed: true`;
- `sourceType: "alchemyProduct"`;
- `alchemyProductId` и `sourceNumber`;
- текущий `sourceRef`;
- точные `productType`, `rank` и `reagentLevel`;
- `priceFormula`, `priceMaximumGp`, `rarity` и `weight`;
- `topDownImage`;
- `signature` с версией шаблона.

Синхронизация создаёт, обновляет и удаляет только управляемые алхимические документы. Пользовательские документы и копии вне управляемого набора не удаляются. Весь набор и все пути изображений валидируются до первой world-мутации.

## Синхронизация обычного снаряжения

Registry существующего импортёра меняет название листа `Взрывчатка V0.0` на `Взрывчатка V0.1`. Импорт пересобирает обычное снаряжение из live-таблицы, удаляет `Кислота (флакон)` и `Алхимический огонь (фляга)` и обновляет сдвинувшиеся `sourceRef`.

Физический сдвиг строки не является новой идентичностью. Dry-run обязан доказать, что логически сохранившиеся предметы сохраняют прежние `id`, а ожидаемое удаление ограничено двумя названными позициями. Любая неожиданная массовая смена ID, добавление или удаление блокирует запись до явного reviewed override. Названия и ссылки `Взрывчатка V0.0` не должны остаться в registry, generated data или профильных тестах.

## Генерация изображений сетками

Для каждого из 230 продуктов создаются две уникальные картинки: квадратная Foundry-иконка и top-down предмет на прозрачном фоне. Итог — 460 WebP-файлов размером 512×512.

Генерацию выполняют отдельные агенты модели `gpt-6-luna`. Корневой агент формирует единый manifest, назначает агентам непересекающиеся grid-ID и сохраняет за собой проверку порядка, визуального качества, crop-координат и соответствия предметам. Агент не может менять записи вне назначенной сетки.

Исходники генерируются только сетками 5×5 размером ровно 1254×1254:

- 10 сеток для Foundry-иконок;
- 10 сеток для top-down;
- первые 9 сеток каждого вида содержат по 25 продуктов;
- десятая содержит 5 назначенных продуктов, остальные 20 ячеек отмечены в manifest как пустые и не экспортируются;
- исправления также собираются в ремонтные сетки 5×5, а не генерируются одиночными файлами.

Внутри серии сохраняются общая форма и художественный язык, но каждый ранг получает уникальные силуэт, материалы, цвет, орнамент и интенсивность эффекта. Foundry-иконки повторяют живописную стилистику существующих `templates/icons/Goods`; top-down строго смотрят сверху, не имеют текста, рамки, фона или водяного знака.

Номинальная геометрия 5×5 используется только для поиска ячейки. Для стороны 1254 границы областей равны `0, 251, 502, 752, 1003, 1254`, но экспортный crop определяется по реальным видимым границам предмета или рамки внутри области. Пересечение границы соседней области, отсутствие предмета, неверный порядок или два предмета в одной ячейке являются браком и отправляются в ремонтную сетку.

Нарезка выполняется `ffmpeg` по проверенным координатам из manifest. Пропорции видимого объекта никогда не меняются. Если crop имеет, например, соотношение 1:1.2, короткая сторона холста расширяется до квадрата, объект центрируется, и только после этого квадрат равномерно масштабируется до 512×512. Для top-down добавленное поле прозрачно; для Foundry-иконки используется согласованный с рамкой фон. Нельзя исправлять пропорции независимым масштабированием по X/Y.

Стабильные пути имеют вид:

```text
templates/icons/Alchemy/<№>-<slug>.webp
assets/top-down/items/alchemy/<№>-<slug>.webp
```

Manifest хранит grid-ID, вид изображения, позицию 5×5, canonical product ID, ожидаемые пути, проверенные видимые границы, pad-параметры, статус QA и hash результата. Проверка требует 230 файлов каждого вида, уникальные hash, квадрат 512×512, alpha-канал top-down и существование обоих путей для каждого продукта.

## Ошибки и восстановление

- Некорректный источник, неполный каталог или отсутствующий asset завершают импорт до записи JSON и до world-мутации.
- Ошибка одной генерационной сетки не отменяет принятые сетки. Бракованные product ID переходят в следующий repair manifest.
- Повторный запуск переиспользует принятые grid/crop hashes и не генерирует готовые изображения заново.
- Прерывание compendium sync безопасно для повторного запуска благодаря стабильным ID и существующему managed-sync владельцу.
- В runtime нет зависимости от Google Drive, Google Sheets, генератора изображений или промежуточных сеток.

## Проверка

Focused-тесты покрывают:

- парсинг 22 колонок и 230 строк;
- пропущенные, дублирующиеся и запрещённые номера;
- цену, верхнюю границу, редкость и вес для рангов 1–9;
- видимый игрокам HTML всех продуктовых полей и формулы цены;
- стабильные canonical/document ID и отсутствие зависимости от физической строки;
- dnd5e Item-проекцию, flags, папки и managed sync create/update/delete;
- сохранность неуправляемых документов;
- обновление ordinary gear sheet registry до `Взрывчатка V0.1`;
- удаление только кислоты и алхимического огня без churn ID остальных товаров;
- полноту manifest из 460 изображений, геометрию сеток, crop/pad без искажения и asset paths.

Перед commit выполняются focused-тесты, полная проверка `node --test tests/*.test.mjs`, `git diff --check`, syntax-check всех tracked JS/MJS и JSON parse-check. Меняется версия `module.json`, создаётся соответствующий versioned forwarder, обновляется `docs/function-passport.md`. После этого выполняется live-проверка синхронизации активным GM в Foundry v13/dnd5e: создание нового compendium, повторный sync без дублей, наличие описаний, цен, веса, редкости и обеих картинок. Если live Foundry недоступен, это остаётся явно обозначенным непроверенным пунктом.

## Критерии приёмки

1. `data/alchemy-products.json` содержит ровно 230 валидных записей со стабильными ID.
2. `world.rebreya-alchemy` содержит ровно 230 управляемых продуктов без дублей.
3. Игрок видит эффект, формулу цены и полный рецепт каждого продукта.
4. Цена Foundry равна максимуму формулы, вес равен рангу, редкость соответствует таблице рангов.
5. У каждого продукта есть уникальная квадратная и уникальная top-down WebP-картинка; ни один объект не искажён при нарезке.
6. Обычный компендий больше не содержит кислоту и алхимический огонь, а остальные логические товары сохраняют прежние ID.
7. Импортёр использует `Взрывчатка V0.1`; устаревших runtime/import ссылок на `Взрывчатка V0.0` нет.
8. Повторный импорт и повторный startup sync не создают дубли и не меняют документы при неизменном источнике.
