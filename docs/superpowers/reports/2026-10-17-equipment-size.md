# Размеры снаряжения: отчёт реализации

Версия: **1.4.393**, ветка `lich_branch`.

Спецификация: [2026-10-17-equipment-size-design.md](../specs/2026-10-17-equipment-size-design.md). План: [2026-10-17-equipment-size.md](../plans/2026-10-17-equipment-size.md). Оба одобрены пользователем перед реализацией.

## Реализовано

- Шесть категорий размера предполагаемого владельца, двусторонняя связь размера с основной костью на native вкладке «Подробности», сохранение нестандартных формул и дополнительных членов. Таблица правила проверяется по всем 48 ячейкам, допустимость оружия — по 36 парам размеров.
- Пересчёт веса и цены основы относительно индивидуального исходного профиля. Quantity, содержимое, улучшения, модификации и прежние правила бюджета сохраняются. Composition v4 и ingress v3 добавлены только для размерного состояния; старые wire shapes и Medium defaults сохраняются. Физическое состояние проходит storage/transfer и не объединяется с другим размером.
- Слишком большое оружие применяется как импровизированное: основа 1d4, обычное оружейное владение не применяется; учтён Tavern Brawler. Дополнительные части урона и постоянный Item сохраняются. Small/Medium non-heavy исключение и меньшее оружие поддержаны.
- Managed macro «Изменить размер» в общей папке «Ребрея», один диалог для Actor/Token/отмеченного оружия в руках. Сохраняется центр токена, поддержан synthetic Actor, no-op и отмена. Typed command проверяет намерение, связь документов, права и stale snapshot; используется существующая Actor queue.
- Rune Knight вызывает тот же application owner: согласие владельца, повторная проверка места, сохранение прежних no-space/level/reach/resource/conditional restore правил. Нет общих observers для пересчёта оружия. Ошибка записи компенсирует только свои поля, включая prototypeToken; последующие чужие правки не перезаписываются, невосстановленные документы перечисляются в ошибке.
- Версия manifest, новый forwarder, style version и canonical import graph обновлены. Предыдущие совместимые forwarders сохранены.

Замечания о fingerprint, стирании исходного patch и отсутствии fallback GM отклонены после проверки исходников и тестов: fingerprint структурный, adapter сохраняет входной patch, а прежний ReactionQueueService уже выбирает active GM.

## Живая проверка

Подтверждены **Foundry 13.351**, **dnd5e 5.2.5**, загрузка нового API и открытие native Item sheet в `testovyj3` под тестовым GM CODEX. Server manifest оставался закэширован на 1.4.389; файлы runtime загружались из текущей рабочей копии. Полная проверка поля/боевых бросков/макроса/Rune Knight и маршрута GM↔player не завершена: пользователь прямо попросил остановить живую проверку и выполнить её самостоятельно. Активный GM в другой сессии ещё использовал прежнюю копию модуля. Ни одно утверждение о прохождении этих live сценариев не делается.

Временные QA Actor и Scene удалены; исходная сцена клиента восстановлена. Реальные персонажи и их ресурсы не менялись.

## Решения процесса

1. Использована существующая чистая `lich_branch`: новая ветка/worktree противоречила бы обязательному Git-процессу проекта. Перед staging повторно проверены remote и состав изменений.
2. Focused tests выполнялись для владельцев поведения; полный runtime check выполнен перед commit, затем повторены проверки затронутых исправлениями файлов.
3. Меню вариантов завершения Superpowers не запрашивалось: инструкции проекта уже предписывают commit и push в `lich_branch`.
4. Живая QA остановлена по прямому указанию пользователя; это явное ограничение принятой проверки.
