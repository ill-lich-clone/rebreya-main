# Глобальные реакции: отчёт реализации

Версия: 1.4.400. Ветка: lich_branch.

## Согласованные документы

- Спецификация: `docs/superpowers/specs/2026-10-23-global-reaction-chat-design.md`.
- План: `docs/superpowers/plans/2026-10-23-global-reaction-chat.md`.

## Изменения

Existing providers и стандартный MIDI chooseReactions проходят через ReactionQueueService. Общий чат показывает «Имя выбирает реакцию»; подтверждённый успех удаляет сообщение, отказ/закрытие/таймаут/сбой применения оставляет «Имя не применил реакцию». Имена NPC видны всем по согласованной спецификации.

Native callbacks выполняются на исходном владельце Actor. GM проверяет sender, ownership (повторно перед commit), доступность и activity cost; выдаёт разрешение до callback. Нулевая стоимость реакций сохраняется при исчерпанной платной реакции. Формулы, native quantity/count/payment и несколько последовательных AC-бонусов не переписаны. Module ledger синхронизируется после фактического native расхода через стабильную квитанцию; изменение общего ledger другой реакцией не теряет списание текущей.

Session ID нельзя перезаписать запросом другого Actor; двойной клик не применяет activity дважды. Native session metadata сохраняется в GM-authored сообщении, чтобы новый GM мог завершить операцию. Отключившийся владелец освобождает applying-резерв. Дедупликация и transient maps ограничены; новых мировых scan/polling нет.

Резервы учитывают количество оставшихся реакций: два доступных использования допускают два платных применения, но не третье. Бесплатная вложенная реакция не блокируется платным применением того же Actor. Existing providers повторно проверяют доступный бюджет с учётом native резервов перед оплатой.

`CombatAttackService.consumeReaction` сериализует записи одного Actor. Дополнительный `idempotencyKey` хранится в ограниченном списке из 64 квитанций существующего reactionState flag и предотвращает повторное списание после reconnect. Это понадобилось для сохранения количества использований при параллельных native завершениях; проверено RED→GREEN отдельным тестом с задержанной записью Actor и новым экземпляром сервиса.

Независимое ревью выявило пять проблем (реальная структура AC window, двойной клик, reconnect, overwrite session ID, бесплатные реакции). Каждая закреплена RED→GREEN тестом и исправлена. Отдельно проверен отзыв ownership до commit. Gemini помог выявить headless forced AC; его финальное CLI-ревью не вернулось за 5 минут, поэтому финальное ревью выполнил независимый Codex agent.

## Проверка в Foundry

Foundry 13.351, dnd5e 5.2.5, Midi-QOL 13.0.61, тестовый GM CODEX, мир testovyj3. Использованы отдельные Actor/Scene fixtures, удалённые вместе с тестовыми сообщениями; существующие персонажи не изменялись.

- Реальный DialogV2 без ответа: через 10 секунд accepted=0, сообщение «QA Страж не применил реакцию», окно закрыто.
- Native forced optional AC: исходный AC 10, результат native handler AC 15, одноразовый effect удалён, сообщение выбора удалено.
- Native optional AC с настоящим окном: перед выбором в чате «RM QA native AC choice выбирает реакцию»; native формула `@abilities.dex.mod + 5`, commit подтверждён до callback, native результат AC 15, effect удалён, reaction messages=0.
- После reload тестового клиента адаптер зарегистрирован. В консоли нет ошибок адаптера. При fixture operations наблюдались отдельные ошибки самого Foundry Notifications `Cannot set properties of null (setting 'hidden')`, `[No packages detected]`; не выдаются за чистую консоль.
- Настоящая сессия другого active GM оставалась на старой загрузке модуля. Полный player→active-GM→owner workflow в живой сессии не проверен; native activity payment, авторизация, replay/timeout и failover проверены Node harness. Для запуска нового протокола необходим reload всех клиентов, включая active GM.

## Решения и границы

- Использована существующая lich_branch без нового worktree согласно правилам проекта. Вся runtime-реализация входит в один commit с согласованной новой версией; промежуточные коммиты со старой версией не создавались.
- Вместо пересылки callbacks выбран begin/commit/finish RPC к активному GM. Native callbacks остаются на их owner client; риск — изменения внутренних API MIDI/socketlib. Граница изолирована, неподдерживаемый API выдаёт явную ошибку.
- Сохранён внешний MIDI `reactionTimeout * 2`: настройки пользователей и закрытые native функции не переписываются. Наш выбор прекращается по 10-секундному deadline, подтверждённое применение не прерывается нашим таймером. Если native применение превысит собственный внешний timeout MIDI, родительский workflow может продолжиться раньше; это сохраняемый предел MIDI.
- Другие клиенты не перезагружались принудительно. Это исключает вмешательство в их текущие действия; до reload новый межклиентский протокол недоступен на старом GM.
- Учёт native списаний расширяет канонический CombatAttackService сериализацией и bounded idempotency receipts вместо сравнения общего остатка с первоначальным snapshot. Цена ошибки — потеря или дублирование расхода при конкурентных завершениях; покрыто отдельными регрессиями, обычные вызовы без ключа сохранены.
- Старые versioned forwarders сохранены по существующему compatibility contract; runtime manifest указывает только main-1.4.400.js.
