# Уменьшение затихающего урона: план реализации

> **Для исполнителя:** использовать superpowers:executing-plans. Сначала регрессионный тест, затем минимальная реализация.

**Цель:** макрос и кнопка в чате открывают одну операцию уменьшения конкретного затихающего урона.

**Архитектура:** `CombatStatusService` остаётся владельцем значения и managed OverTime; новый узкий координатор запускает проверку и применяет результат через типизированную команду active GM. Чат и world-макрос вызывают один публичный API; существующая синхронизация управляемых макросов создаёт документ.

**Стек:** Foundry VTT 13, dnd5e, MIDI-QOL, Node test runner.

**Спецификация:** `docs/superpowers/specs/2026-10-27-decaying-damage-recovery-design.md`.

## Общие ограничения

- Только `lich_branch`; не менять существующие правила тика, stored flags, источники, внешний API и иные changes внешних эффектов.
- Сл 10 + БМ источника; если источник недоступен — явный ввод Сл. Успех: 1 шаг бонусным действием или 2 действием; провал ничего не меняет.
- Работать с идентификатором эффекта, а не произвольно выбранным статусом Actor. Player-команда проверяет владельца, active GM авторитетно рассчитывает значение и сериализует изменения Actor.
- Изменить module version, versioned entrypoint, README и паспорт; выполнить полный набор проверок проекта.

## Фокус проверки

- Два эффекта одного существа: изменяется лишь указанный ID.
- Эффект удалён или заменён до завершения: никакой другой эффект не изменяется.
- Повторное нажатие и повторная доставка команды: один результат применяется не более одного раза, при отказе до подтверждения не скрывать неоднозначность.
- Отсутствует source Actor или БМ: запросить явную Сл, не подставлять значение молча.
- Несовпадение прав игрока, невалидные поля или недоступный GM: отклонить без записи и без чужого броска.

### Задача 1: каноническая операция и права

**Файлы:** `scripts/combat/status-service.js`, новый узкий сервис операции в `scripts/combat/`, `scripts/main.js`, `tests/decaying-damage.test.mjs`, отдельный focused-тест операции.

**Интерфейс:** публичный `recoverDecayingDamage(options = {})`; запрос содержит Actor UUID, effect ID, выбранный режим, допустимую Сл при отсутствии источника и уникальный operation ID. GM-команда проверяет отправителя и существующий эффект, производит штатный бросок Медицины и применяет его к текущему значению выбранного эффекта. Ручной режим не бросает кости и задаёт явное уменьшение; оба режима используют один effect-specific метод владельца и сохраняют его meta и прочие changes.

**Интерфейс:** управляемый макрос «Уменьшить затихающий урон» вызывает `game.rebreyaMain.recoverDecayingDamage()`. ### Уточнение: союзник

Проверка разрешена владельцу выбранного лекаря или GM для пациента, выбранного через T либо заданного чатовой кнопкой. GM повторно проверяет владение лекарем; ручное уменьшение требует владения пациентом или прав GM. Тесты дополнительно покрывают владельца лекаря без прав на пациента и запрет помощи чужим лекарем. Дистанция не проверяется.
