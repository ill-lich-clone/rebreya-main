# Исправление перевязки ран: план реализации

> **Для исполнителя:** выполнить задачи последовательно с superpowers:executing-plans; перед каждым изменением поведения получить RED, затем GREEN.

**Цель:** разрешить перевязку конструктов и целей с 0 HP, а также явный обход отсутствующего комплекта.

**Архитектура:** `TreatWoundsDnd5eAdapter` определяет допустимого пациента; `TreatWoundsDocuments`, typed contract и `TreatWoundsService` остаются авторитетными владельцами проверки комплекта и транзакции. DialogV2 передаёт подтверждённый intent; прежний journal и inventory debit сохраняются.

**Стек:** Foundry 13, dnd5e 5.2.5, JavaScript ES modules, Node test runner.

**Спецификация:** `docs/superpowers/specs/2026-10-27-treat-wounds-construct-zero-no-kit-design.md`.

## Общие ограничения

- Не воскрешать персонажа с тремя проваленными спасбросками от смерти; нежить по-прежнему исключена.
- `dead` при 0 HP не блокирует перевязку; `dead` при положительных HP блокирует. Конструкт допускается.
- Галочка выключена по умолчанию; когда доступный комплект есть, выбранный комплект расходуется даже при включённой галочке.
- При включённой галочке и отсутствии доступных подходящих комплектов не создавать расходный debit и сохранить решение в журнале; старый intent без нового поля означает обычный расход.
- Сохранить проверки Medicine/прав/tiers, HP, иммунитета, все исходы и продолжение; версия и forwarder синхронизируются в том же commit.

## Фокус проверки

- `dead` при HP 0: лечение проходит, провалы сбрасываются, успехи сохраняются; HP 0 + три провала: отказ до затрат.
- Конструкт с 0 и положительными HP допускается; нежить, недопустимый Actor и `dead` при положительных HP отклоняются.
- Нет комплектов + галочка выключена: диалог позволяет выбрать её, но подтверждение отклоняется; с галочкой операция идёт без дебита.
- Есть комплект + галочка включена: валидный выбранный комплект расходуется один раз; исчезнувший выбранный комплект не заменяется обходом.
- Повторный запуск, продолжение и recovery используют сохранённый режим; старые журналы и payload без нового ключа сохраняют прежние правила, подложные комбинации не обходят проверку.

**Интерфейсы:** новый необязательный boolean `ignoreMissingKit` в start intent; отсутствие ключа в старых intent означает `false`.
