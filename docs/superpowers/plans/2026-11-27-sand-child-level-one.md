# Дитя песков (1-й уровень) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Автоматизировать превращение, размещение одного тайла после перемещения, полуукрытие и поглощение песка ради временных хитов.

**Architecture:** Компендиум проецирует две карточки по стабильным ID. Один боевой сервис владеет превращением, возможностями размещения и мутациями песка. Foundry-хуки передают ему события, кнопка HUD и макрос работают через сервис и существующую границу active GM.

**Tech Stack:** Foundry VTT 14.369, dnd5e, JavaScript ESM, ActiveEffect, TileDocument, Node test runner, Foundry QA.

**Spec:** [Дитя песков: автоматизация умений 1-го уровня](../specs/2026-11-27-sand-child-level-one-design.md)

## Общие ограничения

- «Проявление духов»: бонусное действие, одна минута, `1d10 + модификатор Харизмы` временных хитов, максимум использований `@prof`, полное восстановление за продолжительный отдых. «Искусство предков»: без действия, раз за текущий ход, временные хиты в размере бонуса мастерства. Применять `Math.max(0, текущие, полученные)`.
- Поверхность поддерживаемой сцены — квадратная 2D-сетка по 5 футов на клетку. Один завершённый маршрут с расходом хотя бы 5 футов даёт один тайл. Кандидаты — клетки под основанием и внешний пояс в одну клетку вместе с углами. Лимит равен бонусу мастерства и сбрасывается в начале собственного хода. Каждый тайл живёт свою минуту. Вне инициативы сроки и шестисекундные интервалы следуют игровым часам Foundry.
- Редакция из чата заменяет прежние правила в двух карточках. Сохраняются ID и принадлежность уровню. Песчаное оружие, провоцированные атаки, природный песок, 3D, ручные альтернативы «Искусства предков» и умения следующих уровней остаются за границей автоматизации.
- Сохранить один канонический URL на изменённый ESM-владелец, обновить паспорт функций в коммите реализации и повысить `module.json.version` вместе с форвардером. Ветки, проверки и push — по `AGENTS.md`. Живой HUD проверять через компьютерное управление после отдельного разрешения на текущую задачу.

## Что проверить в первую очередь

- Уже выданные карточки и совпадающие названия. Старый управляемый экземпляр обновляется на месте с сохранением ID и `spent`, посторонняя карточка исключена. Задача 1.
- Отмена атаки и два уведомления об одном броске. Отмена сохраняет эффект, реальная атака одним оружием двумя руками завершает превращение один раз. Задача 2.
- Пауза или отмена маршрута, позднее завершение первого маршрута, открытое окно после хода или нового движения. Старая возможность перестаёт приниматься. Задачи 3 и 4.
- Два подтверждения одновременно и повтор после незавершённой записи. Тайл, лимит и временные хиты применяются один раз, состояние восстанавливается при повторе или старте active GM. Задача 3.
- Два источника полуукрытия и истечение одного из нескольких тайлов под большим токеном. Состояние пересчитывается только для затронутых токенов, независимый источник сохраняется. Задача 3.
