# Magic item top-down implementation plan

Use `superpowers:executing-plans` for the integration. The user delegated decisions and asked for autonomous execution; use GPT‑6 Luna (max) agents only for the image batches.

**Goal:** Ship a clean transparent top-down PNG for each of the 672 stable magic catalog IDs, wired into the existing scene texture resolver.

**Architecture:** Add a static magic index next to the existing generated gear/material index. Keep the scene resolver and existing container snapshot as owners of presentation. Raw atlas images stay outside Git. No runtime image processing or world migration.

1. **Artwork.** Assign disjoint ranges [0,225), [225,450), [450,672) of `magicItem.js` to the three agents. Generate one atlas per batch of up to 25 with explicit row-major positions; visually verify each chosen cell against the intended item, retry mismatches and output one image per ID. Crop without stretching, center in a 512×512 PNG, check real alpha, isolated silhouette and a fully clear margin of at least 32 px. Record atlas/cell provenance in staging so IDs can be reconciled before copying. Agents write isolated output folders and do not alter product files.
2. **Regression first.** Extend `tests/top-down-item-texture-resolver.test.mjs` and the owner tests for single ground item and native magic container. Assert exact magic ID, correct explicit subtype path, one sprite after native template configuration in `tests/magic-weapon-template.test.mjs`, rejection of name-only and conflicting metadata, correct armor sizing, unchanged fallback and restored container art for native and legacy snapshots. Run the focused tests before changing resolver behavior. Assert release coverage against every raw ID, one unique PNG per ID, with PNG alpha/margins checked separately on the final files.
3. **Integrate.** Add `scripts/data/magic-item-top-down-catalog.js` and `assets/top-down/items/magic/*.png`. Extend `scripts/data/top-down-item-texture-resolver.js` in both public resolution paths, retaining gear/material/alchemy behavior. Preserve canonical magic identity in `scripts/data/storage-container-item-service.js`; refresh cache keys for both consumers. Bump `module.json`, README and release test expectations, add the versioned forwarder, and document the owner in `docs/function-passport.md`.
4. **Verify and publish.** Check complete ID coverage, PNG format, distinct image content, alpha margins and visuals; run focused verification and the prescribed full Node, syntax, JSON and Git diff checks. Review the scoped diff, commit, and push `lich_branch`. No computer-use tools; verify offline and report the live Foundry check as unrun.
