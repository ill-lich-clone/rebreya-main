# План реализации крафта зелий Ребреи

> **Для исполнителя.** Используй `superpowers:executing-plans` или `superpowers:subagent-driven-development`. Шаги отмечаются по мере выполнения. Пиши focused regression test и наблюдай его падение до изменения соответствующего runtime-кода.

**Цель.** Из меню Ребреи игрок выбирает одно зелье и готовит его через утверждённый простой или следующий короткий отдых.

**Архитектура.** Один расчёт рецепта обслуживает окно и активного GM. Лаборатория входит в существующий цикл заявок простоя, поле входит в существующий dnd5e rest hook. Обе ветки используют общий учёт расхода, документ выдачи и восстановление по журналу.

**Среда.** ESM, Foundry 14.369 и dnd5e 6.0.6 в мире «Ребрея мейн», существующий Node test runner и ApplicationV2. Совместимость манифеста 13–14, зависимость `statuscounter >= 3.0.4`.

**Спецификация.** [2026-11-09-potion-crafting-design.md](../specs/2026-11-09-potion-crafting-design.md), подтверждена пользователем.

## Общие ограничения

- Правила и рецепты определяет «ДНД: Алхимия V1.0». Сохраняются ID и данные карточек из мира. Новые рецепты связаны с каждым из 109 стабильных ID зелий. Импортируемый из таблицы `data/alchemy-products.json` продолжает принадлежать своему импортёру.
- Одна кнопка «Алхимия» в меню Ребреи и одна компактная форма с режимами «Простой / Путешествие». Простою остаются его баланс недель, подтверждения Мастера и прежний маршрут существующих заявок.
- Ручные срок и сумма доступны только для упрощённой лаборатории. Исходная цена берётся из рецепта, недели вводятся вручную. Поле использует авторскую цену упрощённого рецепта.
- Серверная сторона операции повторно вычисляет данные из точных ID Actor, группы, предметов и рецепта. World mutations проходят через зарегистрированную команду, существующие репозитории и active GM. Повторные вызовы используют тот же идентификатор операции.
- Работа только в `lich_branch`. Сначала `git status --short --branch`, `git branch --show-current`, `git fetch origin`, сравнение HEAD с `origin/main` и `origin/lich_branch`. В финальном коммите обновить runtime-версию с `1.5.70` на `1.5.71`, если remote всё ещё на этой версии, и выполнить проверки из `AGENTS.md` перед push. Интерактивный Foundry QA только с явным разрешением для текущей задачи.

## Что проверить особенно внимательно

1. В legacy-наборе третьего ранга `flags.rank` равен нулю, а сломанный набор с тем же названием по-прежнему недоступен. Задача 1.
2. Одна и та же порция материала выбрана одновременно как основа и как замена либо катализатор. Задача 1.
3. Сбой после списания или создания Item и повтор из другого клиента. Задача 2.
4. Повторное утверждение со старой ценой, заявка прежнего формата и завершение нескольких календарных дней одним переходом. Задача 3.
5. Устаревшая карточка короткого отдыха, второй игрок и передача зелья перед истечением срока. Задача 4.
