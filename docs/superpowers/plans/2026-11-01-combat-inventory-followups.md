# Бой и инвентарь: план исправлений

> Для исполнителя: после согласования спецификации использовать `superpowers:executing-plans`; независимые этапы выпускать отдельно. Checkbox означает работу, которую ещё предстоит сделать.

**Цель:** исправить сбой боя и телепортации, выполнить пункты 19, 24, 27, 29–35 и завершить верховым боем и наскоком (28).

**Архитектура:** менять существующих владельцев и интеграции, а не вводить параллельные источники истины. Сначала исследовать неустановленные сценарии, затем тест владельца, минимальное исправление и отдельная проверка. Приведённые пути — подтверждённые точки входа или явно обозначенные кандидаты, не разрешение заменять чужие модули вслепую.

**Стек:** Foundry VTT 13.351, dnd5e 5.2.5, JavaScript ESM, Node test runner, MIDI-QOL / Chris Premades при их наличии.

**Спецификация:** `docs/superpowers/specs/2026-11-01-combat-inventory-followups-design.md`.

## Общие ограничения и проверка

- Работать в `lich_branch` с обязательными fetch/status и проверкой конфликтующих изменений; перед commit полный набор runtime-проверок по AGENTS.md, затем push без force.
- Перед изменением клиентских файлов поднять версию, обновить forwarder и cache keys; новые или изменённые методы внести в паспорт функций.
- Для каждого этапа: воспроизвести актуальный дефект на конкретном пути, написать падающий тест с нужными данными, запустить его, внести минимальный фикс, повторить focused-тесты и проверить соседние сценарии; после новых runtime-изменений повторить затронутые проверки.
- Не использовать Computer Use без отдельного явного разрешения. Живой мир и игровые документы не изменять ради проверки; source-тесты не выдавать за live-подтверждение.
