# Восстановление расхода бюджета Lootgen — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Восстановить расход заданного бюджета, включая 1 000 000 без монет, с авторскими формулами количества и мягким тематическим подбором.

**Architecture:** Изменить существующие генераторы и тематический контекст, сохранив владельцев бюджета и форму шаблонов. Обычный результат добирает стопки после выбора разных строк; составной результат сохраняет общий ledger и ограничения, а валютный остаток учитывается один раз. Новых сервисов, настроек тематик и схем хранения не вводить.

**Tech Stack:** Foundry VTT 13, dnd5e, JavaScript ESM, Node.js `node:test`, Handlebars; обязательный `statuscounter >= 3.0.4`, без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-10-02-loot-budget-restoration-design.md` — одобрена пользователем 2026-10-02 сообщением «Ок пробуй».

## Global Constraints

- Заданный бюджет должен расходоваться; тематика не отменяет расход бюджета, количество предметов или авторские формулы.
- Каждый добор использует существующий разбор и бросок `multipleAppearance`; последний пакет ограничивается доступным бюджетом.
- Не менять формат шаблонов, публичные параметры генератора, цены, фильтры ранга и типов, включение магических предметов, обработку сломанного снаряжения, установку улучшений, физическую вместимость и глубину контейнеров, уникальные идентификаторы и существующий лимит документов составного результата.
- Нулевые цены не должны создавать бесконечный добор. Существующие технические ограничения могут оставлять остаток при выключенных монетах; тематические предпочтения — не могут.
- Первое открытие хранилища без шаблона создаёт только монеты на 500–1500 value один раз; повторное открытие не генерирует новую добычу.
- Работать в `lich_branch`; проверять статус и remote перед изменениями, останавливать работу при чужих изменениях или опережении remote. Runtime-изменения выпускаются с новой версией и синхронным обновлением клиентского кэша.

## Review Focus

1. Формула кубов: добор заново бросает каждый куб, включая пакет, обрезанный остатком бюджета — тест Task 2.
2. Большой бюджет и дешёвый предмет: обычный режим расходует миллион, не наследуя искусственный лимит 2000 попыток составного режима — тест Task 2.
3. Ручной предмет и несовпадающая совместимость: распознавание сохраняется, предпочтения остаются положительными и не запрещают тратить бюджет — тест Task 1.
4. Заполненные контейнеры и внутренние монеты: внешний остаток не дублирует вложенную валюту; переполнение вместимости откатывает только принятую резервацию — тест Task 3.
5. Уникальные магические, нарративные и улучшенные экземпляры: добор обычных стопок не объединяет их и не меняет идентичность — тесты Tasks 2–3.

## Task 1: Мягкие тематические предпочтения

**Files:** `scripts/data/lootgen-thematic-selection.js`; `tests/lootgen-thematic-selection.test.mjs`; тематические сценарии в `tests/lootgen-generator.test.mjs`.

**Interfaces:** Сохранить `getLootgenThemeProfile(item={}) -> profile` и `createLootgenThemeContext(seedRows=[], {initialTheme=""}={}) -> {weight(row), accept(row), forContainer(row)}`. Метаданные структурных ролей, семейств боеприпасов и двуручности не менять.

- [ ] Добавить тесты: вес связанного предмета больше веса постороннего, оба положительны; после принятия одного и нескольких предметов той же роли следующий остаётся доступным; после трёх реагентов четвёртый доступен. Для ручного двуручного оружия щит менее предпочтителен, но не исключён.
- [ ] Сохранить тесты распознавания реального каталога и переименованных native предметов. Тесты совместимости изменить с `weight === 0` на `0 < incompatibleWeight < compatibleWeight`; сравнивать пары с одинаковой ролью. Генераторные сценарии проверяют предпочтения и расход, а не гарантированное отсутствие любого постороннего предмета при случайном выборе.
- [ ] Запустить `node --test tests/lootgen-thematic-selection.test.mjs` и подтвердить падения именно новых требований к весам.
- [ ] Изменить только `weight`: основа 4 для совпадающей тематики, 1 для нейтрального контекста/открытой тематики, 0.25 для иной известной тематики, 0.15 для отсутствующих сведений. Повторную роль ослаблять делением на `1 + число принятых предметов этой роли`; несовпадающую специальность, семейство боеприпасов и сочетание щита с двуручным оружием ослаблять множителем 0.1 вместо запрета. Для корректных кандидатов итог всегда положителен.
- [ ] Повторить профильный тест: все проверки распознавания и мягких предпочтений проходят. Существующий обработчик `accept` вызывается для нового выбранного экземпляра, а не для каждой копии добираемой стопки.

- [ ] Исправить ошибочные ожидания `d68870f2`, закрепившие отсутствие добора. Каждый пакет бросать через существующий `rollLootgenMultipleAppearance`, обрезать по бюджету и обновлять соответствующую объединённую строку, а не создавать миллион временных объектов пакетов.
